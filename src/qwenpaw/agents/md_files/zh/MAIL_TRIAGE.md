# MAIL_TRIAGE.md —— 邮件分诊树

## 使用说明
- 每封新邮件唤醒后，先通读本文件，自上而下匹配新邮件的「识别特征」。
- 命中一个或多个叶子：按「前置工具链 → 终态动作」执行；复合场景按组合规则执行。
- 全部未命中、置信度低、或动作不可逆：走 F1 探索模式。先按逐步审批尝试处理；确实无解或多次被拒绝时再向用户请示。
- 叶子格式：识别特征 (Matching Criteria) / 前置工具链 (Prerequisite Toolchain) /
          终态动作 (Final Action) / 来源 (Source)。

## A 邮箱内状态操作类（产出物：邮箱状态变化）
- **A1 静默已读**
  - 识别特征：营销推广、noreply 发件人、无需任何后续动作的通知
  - 前置工具链：无
  - 终态动作：mark_messages 标记 read
  - 来源：v0.2.0 种子
- **A2 归档分类**
  - 识别特征：有留存价值但无需回复（账单通知、订阅确认）
  - 前置工具链：（必要时 create_folder）+ list_folders
  - 终态动作：move_message 移入对应文件夹
  - 来源：v0.2.0 种子
- **A3 标记跟进**
  - 识别特征：需要用户本人后续处理、但当前无法代办的邮件
  - 前置工具链：get_message 确认内容
  - 终态动作：mark_messages 标记 flagged；线程场景 update_thread 加标签
  - 来源：v0.2.0 种子
- **A4 垃圾隔离**
  - 识别特征：明显垃圾/钓鱼/诈骗邮件
  - 前置工具链：无
  - 终态动作：move_message 移入垃圾文件夹（只移不删，红线禁止 delete_message）
  - 来源：v0.2.0 种子

## B 信息提取沉淀类（产出物：工作区文件）
- **B1 台账登记**
  - 识别特征：账单、发票、收据、扣费通知等含金额与日期的凭证类邮件
  - 前置工具链：get_message 提取金额/日期/事由
  - 终态动作：edit_file 向台账文件追加一行记录
  - 来源：v0.2.0 种子
- **B2 附件归档**
  - 识别特征：含需留存附件（合同、简历、报告、票据 PDF 等包含非广告内容的附件）
  - 前置工具链：get_message 确认附件清单
  - 终态动作：get_attachment 保存到工作区对应类别的目录
  - 来源：v0.2.0 种子
- **B3 联系人沉淀**
  - 识别特征：出现 CONTACTS.md 中不存在的有效新联系人
  - 前置工具链：read_file CONTACTS.md 核对
  - 终态动作：edit_file 追加联系人条目到 CONTACTS.md
  - 来源：v0.2.0 种子

## C 时间敏感类（产出物：cron 定时任务）
- **C1 通知类提醒**
  - 识别特征：会议邀请、面试通知、截止日期提醒等
  - 前置工具链：get_message 提取时间地点；get_current_time 换算提醒时刻
  - 终态动作：如果你可以操作当前设备，**优先**在设备自带的日历上创建日程；否则
  cron skill 创建 --schedule-type scheduled --type text 提醒
  - 来源：v0.2.0 种子
- **C2 工作安排**
  - 识别特征：面试申请（简历投递）、询问是否空闲等需要自己安排时间的任务
  - 前置工具链：get_message 确认内容，获取用户日程（日历），查找合适的空闲时间
  - 终态动作：如果你可以操作当前设备，**优先**在设备自带的日历上创建日程；否则创建cron提醒
  - 来源：v0.2.0 种子
- **C3 行程整理提醒**
  - 识别特征：机票/酒店/车票等预订确认和预订修改（改签）邮件
  - 前置工具链：get_message 提取行程要素
  - 终态动作：write_file 行程单 + 如果你可以操作当前设备，**优先**在设备自带的日历上创建日程；
  否则cron 创建或者修改出发前提醒
  - 来源：v0.2.0 种子
- **C4 物流状态追踪**
  - 识别特征：电商订单、发货通知、物流信息类邮件
  - 前置工具链：get_message 提取物流公司和物流编号（或电商订单编号），在浏览器中用邮箱登录对应官网查找对应物流信息（或订单信息）
  - 终态动作：如果computer use工具/技能可用，如果你可以操作当前设备，**优先**在设备自带的日历上创建日程；否则：
  cron 创建 --type agent 任务：每天关注物流状态，当物流到达时通知用户并删除此cron任务
  - 来源：v0.2.0 种子

## D 对外通信类（产出物：发出的邮件）
- **D1 直接答复**
  - 识别特征：可依据已知信息直接回答的简单询问
  - 前置工具链：read_file CONTACTS.md 确认对方背景
  - 终态动作：reply_message 回复原发件人
  - 来源：v0.2.0 种子
- **D2 线程续谈答复**
  - 识别特征：既有往来线程中的新一轮来信
  - 前置工具链：get_thread 回顾上下文
  - 终态动作：reply_message 答复 + update_thread 更新线程标签/状态
  - 来源：v0.2.0 种子
- **D3 转发路由**
  - 识别特征：应由 CONTACTS.md 中其他已知联系人处理的邮件
  - 前置工具链：read_file CONTACTS.md 确定接收人
  - 终态动作：forward_message 转发并附说明
  - 来源：v0.2.0 种子
- **D4 代发新邮件**
  - 识别特征：来信要求向第三方发起新邮件（第三方须在 CONTACTS.md 中）
  - 前置工具链：read_file CONTACTS.md 核验收件人
  - 终态动作：send_message 发送新邮件
  - 来源：v0.2.0 种子

## E 外部执行类（产出物：处理结果播报）
- **E1 验证码提取播报**
  - 识别特征：验证码/一次性登录码邮件
  - 前置工具链：get_message 提取验证码
  - 终态动作：将验证码写入处理结果（auto_handled 事件正文可见）
  - 来源：v0.2.0 种子

## F 探索兜底类（产出物：探索过程 + 必要时请示输出）
- **F1 探索处理**
  - 识别特征：无法归类 / 置信度低 / 动作不可逆 / 触碰安全红线 /
    需点击邮件内链接完成的操作（邮箱验证、订阅确认、退订等网页链接操作类请求）
  - 前置工具链：activate_f1_exploration_mode → get_message 完整阅读 → 按最佳判断执行（逐步审批由系统自动拦截处理，勿在输出中自行请求批准，直接调用工具即可）；先分析邮件意图再逐步执行，每步工具调用前用一句话说明理由
  - 终态动作：根据审批结果完成处理，然后回顾工具链轨迹并写回新叶子
  - 来源：v0.2.0 种子

## 组合规则
- 发票邮件 = A2 + B1；出行预订 = A2 + C2；面试邀约 = C2 + B3。
- 组合时按 B/C（沉淀与提醒）先行、A（状态操作）居中、D（对外动作）最后的顺序执行。
- 网页链接操作类请求（点击确认/退订等）一律走 F1 探索模式，不自行打开链接。

## 编辑纪律
1. 一级类 A-F 只增不改；新场景只能加新叶子，仅当终态产出物是全新类型才可增一级类。
2. 新叶子必含四字段：识别特征、前置工具链、终态动作、来源（哪次请示+日期）。
3. 只追加不删除；废弃叶子移入文末 deprecated 区并标注原因。
4. 修改前先备份为 MAIL_TRIAGE.md.bak，改后自检格式。
