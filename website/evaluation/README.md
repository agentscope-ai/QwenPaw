# 评测发布摘要与榜单规则

网站仅接收 `schema_version: 1` 的精简发布摘要，不接收逐题结果或轨迹。
执行库保留完整观察记录用于审计，完成单项题目身份、评分及费用核验后，导出网页摘要。
网站维护 benchmark 均分、方向分和总分的计算规则；不兼容旧的逐题输入格式。

## 提交摘要

每个模型、harness/模式、SDK、profile、评测批次使用一份文件，可包含多个 benchmark。
正式摘要放 `results/official/<id>.json`；文件名与 `id` 一致，`kind` 为 `official`。
对外索引只构建正式成绩，不显示测试或模拟记录。参考 `example.json` 与 `schema.json`，
提交前运行 `pnpm --dir website build` 校验并构建。

配套执行库 `qwenpaw-index`在评测完成后
自动生成摘要；历史完整结果可用 `qwenpaw-index export-web <单项文件...> --output <目录>`
重新导出，无需重跑模型。仅提交审核后的摘要，不把内部完整结果复制到网站。

摘要保留候选身份、profile、源码与分发包指纹、运行参数、汇率，以及每项评测的
修订、Judge 配置、来源观察 ID 和日期。每项只提交：

- 全题数、异常记零后的原始得分合计、各类异常计数。
- 模型与 Judge 的已确认原币种费用合计，以及各自覆盖的题数。
- 已记录端到端用时合计与题数，包含环境准备和评分。

导出端负责验证预定题目完整、唯一且已结束；网页校验摘要 schema、计数范围、
元数据一致性和身份唯一性。摘要不包含题目清单、逐题明细、凭据、AP 内部标识、
轨迹或 OSS 地址；它不能代替内部审计证据。

## 榜单版本与计算

`indexes.json` 定义版本 ID、方向、权重及数据/Judge 修订。同一版本的不同模型、
SDK、模式与 profile 在同一榜单比较；运行 ID 包含 profile，详情地址不会跨配置共用。
选择器和详情同时显示 benchmark 名称与版本 ID，权重变化使用新版本 ID。

第一期 GAIA、SpreadsheetBench Verified、SWE-bench Verified、PawBench 各占 25%。
每个 benchmark 恰好属于一个方向，方向权重之和及每个方向的内部权重之和均为 1。

1. 正常题采用原始 0–1 得分，终态异常按 0 计，异常率单列。
2. 单项分 = 得分合计 / 全题数 × 100。
3. 方向分按方向内部权重求和；总分再按方向权重求和。

从未评测的 benchmark 保持缺项，不当作失败零分；缺项导致对应方向和总分为 `null`。
新增 benchmark、数据/Judge 修订或权重时增加榜单版本，不覆写旧规则。
同一 candidate/profile 可按时间组合已完成单项；选择当时最新且符合规则的观察，
不选择最高分。不同身份不拼接历史成绩。源码或模型别名漂移须另行核验。

## 费用、用时与公开范围

费用按已确认调用的原币种金额合计除以全题数，人民币再除以固定 `cny_per_usd`
换算美元；不对缺失请求估价，也不把缺失费用变成零。原始记录确认未调用 Judge 或
请求遭供应商拒绝时可以记零。覆盖数仍需展示，已确认金额不代表完整账单。
模型、Judge 费用及用时独立展示，不参与能力得分。用时按已记录题数取均值。
方向和总榜中的费用、用时沿用对应分数的两层权重。

缺少费用记录的数据点可显示，但不参加费用 Pareto 前沿。只发布已审核的摘要，
来源仓库使用无凭据、无查询参数的 HTTPS 地址。构建生成的
`public/evaluation/data/index.json` 不手工编辑，也不重复提交。

`harness: qwenpaw` 表示 QwenPaw 默认模式；coding、loop、goal 等模式使用独立
harness 身份和运行配置。SDK 统一发布展示时，`source_sha` 标记发布源码，
实际评测分发包的 `artifact_sha256` 保持原值。
