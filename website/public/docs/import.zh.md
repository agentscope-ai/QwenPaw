# 从其他智能体导入

QwenPaw 可以从 Codex、Qoder 中个性化导入受支持的聊天记录、记忆、Skill、MCP、插件和定时任务，让你在 QwenPaw 中最大程度恢复已有工作进度。导入前可以自主选择需要导入的内容，导入时会尝试对工具和设置做针对 QwenPaw 生态的适配，不必担心环境不兼容的问题，实现真正的“无痛迁移”。

例如，你可以迁入 Codex 中的项目讨论记录和代码审查插件，或迁入 Qoder 中的项目记忆和每日简报定时任务，再使用 QwenPaw 当前配置的模型在这些会话上利用导入的工具继续工作。

## 使用前准备

1. 选择接收导入内容的 QwenPaw 智能体，确认它使用原生后端，并已配置可用的
   [模型](./models)。自动兼容性修复会调用该智能体的模型，产生相应的模型用量。
2. 确认运行 QwenPaw 的系统用户有权限读取来源数据及所需的项目目录。
3. 准备好工具需要的本地运行环境、环境变量和服务授权，便于导入后验证。

源文件的发现与读取在本机进行。兼容性修复会将相关内容交给你配置的模型；使用远程模型时，这部分处理也会使用远程模型服务。

### 支持的来源与数据位置

| 来源               | 默认数据目录 | 可配置的环境变量       | 读取方式                                                                                         |
| ------------------ | ------------ | ---------------------- | ------------------------------------------------------------------------------------------------ |
| Codex              | `~/.codex`   | `CODEX_HOME`           | 优先通过可用的 Codex app-server 读取会话与配置；会话读取不可用或不完整时，尝试本地 rollout JSONL |
| Qoder              | `~/.qoder`   | `QODER_HOME`           | 读取本地 IDE / Agent SDK 会话、记忆、Skill、插件和 MCP 配置                                      |
| Qoder IDE 用户数据 | 见下表       | `QODER_USER_DATA_HOME` | 补充会话索引、Quest 信息和定时任务定义                                                           |

Qoder IDE 用户数据目录默认位于：

| 系统    | 目录                                                                         |
| ------- | ---------------------------------------------------------------------------- |
| macOS   | `~/Library/Application Support/Qoder/User`                                   |
| Windows | `%APPDATA%\Qoder\User`；没有 `APPDATA` 时使用 `~/AppData/Roaming/Qoder/User` |
| Linux   | `$XDG_CONFIG_HOME/Qoder/User`；未设置时使用 `~/.config/Qoder/User`           |

使用自定义目录时，在**启动 QwenPaw 的环境中**设置上述变量，值应为绝对路径。
`QODER_USER_DATA_HOME` 应指向 `User` 目录本身。页面不提供上传备份包或选择任意目录的入口。

如果 QwenPaw 运行在容器、远程服务器或另一个系统用户下，检测到的是该运行环境能访问的数据，不是浏览器所在设备的数据，也不能从其他设备远程拉取来源内容。

## 可以导入什么

| 内容     | 导入后的结果                                                            | 使用前需要确认                                              |
| -------- | ----------------------------------------------------------------------- | ----------------------------------------------------------- |
| 聊天记录 | 转换为目标智能体的 QwenPaw 会话，保留可读取的消息、标题、时间及归档状态 | 历史工具调用是记录；后续对话使用当前智能体的模型和能力      |
| Memory   | 按来源和作用域保存 Markdown 资料                                        | 核对来源及项目，避免把其他项目的资料当成当前要求            |
| Skill    | 经检查和适配后写入目标工作区，默认禁用                                  | 阅读内容、检查依赖，再手动启用                              |
| MCP      | 转换为目标工作区的 MCP 驱动卡，默认禁用                                 | 检查启动方式、目录、凭据及访问策略，再连接和启用            |
| 插件     | 经适配后通过 QwenPaw 原生插件流程安装                                   | 安装可能执行插件代码；生成的适配插件所提供的 Skill 默认禁用 |
| 定时任务 | 转换为默认禁用、待审核的 QwenPaw Agent 任务                             | 核对调度、内容和目录，先审核通过，再单独启用                |

目前 QwenPaw 只能转换能够识别的内容。源应用的登录状态、模型提供商配置、内置工具、沙箱与审批策略、正在运行的任务状态不会整体搬到 QwenPaw。独立的 `AGENTS.md` 等人设文件也不会自动覆盖目标智能体的人设；需要调整时请参考 [人设与行为](./persona)。

项目的本地目录关联会尽可能保留，但**不会复制项目代码、创建 Git 工作树或恢复原应用的运行进程**。整套 QwenPaw 环境的迁移请使用 [备份与恢复](./backup)。

## 导入步骤

### 1. 选择应用

打开控制台的 **导入** 页面。

- 勾选显示 **已检测到** 的 Codex、Qoder，可以同时选择两者。
- **未检测到** 的来源不可选择。先检查数据目录及启动环境，再重新打开页面检测。
- 点击 **继续**，等待系统清点可导入的内容。

这个阶段只读取来源并保存导入计划，还没有把聊天记录或工具写入目标智能体。

### 2. 选择内容

扫描完成后，每个来源分别展示 **聊天记录** 和 **工具&设置**：

- **聊天记录** 按来源整体勾选，当前页面不提供逐条会话选择。一次最多可迁移 **500 个会话**。
- **工具&设置** 分为 Memory、定时任务、Skill、MCP、插件。可以逐项选择，也可以按组勾选。
- 可选择的聊天记录和非插件项目默认勾选，**插件默认不勾选**。
- 无法安全读取或生成指纹的项目会显示原因，并禁止选择。
- 部分 Codex heartbeat 依赖原聊天记录。请一并导入对应来源的聊天记录，或先完成聊天迁移后再重试该定时任务。

检查页面显示的 **导入目标智能体**，然后点击 **开始导入**。每个目标智能体同一时间只能有一个活动导入任务；切换智能体不会改变已经创建的任务的归属。

如果选中了插件，会出现 **插件代码执行提醒**。确认来源可信并勾选确认项后，点击
**确认并导入**。插件可能安装 Python 依赖，在 QwenPaw 进程中运行代码，注册全局工具、
Hook、路由或命令。插件安装作用于 QwenPaw 实例，不能视为只影响当前智能体。

依赖插件安装目录的绑定 MCP 随插件一起导入，不单独显示为可选项目；其配置和凭据按 MCP
迁移规则处理，驱动卡保持禁用。

### 3. 查看进度与结果

系统先写入选中的聊天记录，再开启 [Mission 模式](./loop-engineering) 检查和修复 Skill、MCP、插件及定时任务。Skill 和插件在临时副本中修改，MCP 和定时任务在待导入的定义上适配，不会直接改写来源文件。Memory 按作用域复制为参考资料。

| 状态           | 含义                                                   |
| -------------- | ------------------------------------------------------ |
| 等待中         | 尚未处理                                               |
| 兼容性修复中   | 正在修复工具使其适配 QwenPaw 的格式和能力              |
| 修复成功待迁移 | 已通过 QwenPaw 兼容性检查，等待写入                    |
| 导入成功       | 该项已写入；是否可立即使用还取决于启用、凭据和审核状态 |
| 已存在，未覆盖 | 保留了 QwenPaw 中已有的项目                            |
| 导入失败       | 该项未完成导入，可检查详情并修复后重试                 |

将鼠标移到状态标签上可以查看提示，展开 **迁移详情** 可以查看过程信息。聊天记录的
“已导入”计数表示本次新写入的会话数；已存在、空白或读取失败的会话可能被跳过。

兼容性检查包括格式、文件安全、插件接口、MCP 启动程序和调度定义等。它不会实际运行来源定时任务，也不代表外部服务连接、授权或完整业务流程已经验证成功。部分尚需人工处理的内容可能以禁用状态保存，应继续完成下方的检查。

## 导入后继续工作

### 聊天记录与项目

在目标智能体的聊天历史或 **会话** 页面中查看迁入的对话。来源中已归档的会话仍保持归档，需要在归档会话中查找。可以继续发送消息，例如：

```text
根据这个会话的历史，概括项目当前进展和未完成事项。先确认当前项目目录，再说明下一步需要查看哪些文件。
```

后续回答由当前 QwenPaw 智能体处理。但是原工具也不会因出现在历史中就自动可用。

如果来源会话的绝对工作目录仍在本机存在，会将其设为该会话的项目目录。目录已经移动或无法访问时，需要重新选择项目目录。PawPort 不会通过聊天记录恢复缺失的项目文件。

每个来源单次最多处理 **500 个会话**，并有读取时间、单会话及总历史大小限制。
Codex 内部子任务、自动化运行会话，以及 Qoder 内部 Agent / Experts 执行轨迹会被过滤；父会话中已有的调用和结果仍可作为历史阅读。

### Memory

导入的记忆默认位于目标工作区的：

```text
memory/imports/<source>/<scope>/
  _scope.json
  ...Markdown 资料
```

`<source>` 为 `codex` 或 `qoder`，`<scope>` 为生成的作用域目录。如果配置了其他记忆
`daily_dir`，则使用该目录下的 `imports/`。`_scope.json` 记录来源、项目标识及原工作目录。

- Codex 读取已整理的 `MEMORY.md`、`memory_summary.md` 和扩展中的项目资源；没有整理版记忆时，可读取 ad-hoc notes。内部原始记忆和整理流水线的中间文件不会作为长期记忆导入。
- Qoder 支持按账户保存的全局/项目记忆，以及较早的 `projects/*/memory/` 布局。

这些文件不会直接合并到 QwenPaw 的 `MEMORY.md`。智能体使用检索结果前应核对 `_scope.json`，把内容作为有来源的参考资料。更多用法见 [长期记忆](./memory)。

### Skill 与 MCP

在目标工作区的 **技能** 页面查看导入的 Skill（导入的 Skill 默认禁用）。先阅读 `SKILL.md` 和配套脚本，检查路径、命令与依赖，再手动启用。独立 Skill 导入到当前工作区，不会自动广播给其他智能体或写入共享技能池；需要复用时可使用 [Skills](./skills) 中的上传到技能池与广播流程。

在 **MCP** 页面查看迁入的驱动卡。所有导入的 MCP 默认禁用，需要先核对配置：

- Codex app-server 提供的可迁移环境变量与请求头绑定会转换为 QwenPaw 凭据引用，字面值加密保存。环境变量引用仍需要目标环境提供对应值。
- Qoder MCP，以及从 Codex/Qoder 插件清单读取的 MCP，其 `env` / `headers` 值会转为占位引用；请重新配置所需值，不能假设原值已经可用。
- OAuth 登录状态不迁移，需要重新授权。包含无法安全转换的命令行或 URL 明文凭据的配置会被拒绝写入。
- 仍引用原应用或插件运行目录的 MCP 可能依赖这些目录继续存在。启用前检查启动程序、工作目录、服务地址和工具访问策略，再验证连接。

详细配置见 [MCP 与内置工具](./mcp)。

### 插件

QwenPaw 在导入时会清点来源中启用的插件及其 Marketplace 信息。支持直接适配的类型包括
Codex 中包含 Skill / MCP 的内容插件，以及符合条件的 Qoder Skill-only 插件；其他本地插件需要适配为 QwenPaw 插件清单和入口，并通过检查后才能安装。

生成的适配插件会保留其 Skill 与所需资源，并默认禁用这些 Skill。源应用专属的 Hook、命令、Agent 或运行时接口并不保证都能迁移。远程插件只有地址、没有可检查的本地内容时，也不能视为已通过兼容性检查。

插件安装可能已经注册实例级能力；若插件的绑定 MCP 导入失败，整体结果可能仍显示失败。请同时检查已安装插件和 MCP 配置。管理方式见 [插件系统](./plugins)。

### 定时任务：先审核，再启用

在 **定时任务** 页面查找标记为 **待迁移审核** 的任务：

1. 打开 **编辑**，检查提示词、执行时间、时区、投递设置和工作目录。
2. 如需更换工作目录，填写 **本地项目目录映射**。保留了远程或无法验证的来源目录标记的任务，必须先映射到真实存在的本地目录，才能通过审核。
3. 保存后点击 **审核通过**，在弹窗中点击 **确认审核通过**。
4. 审核通过后任务仍是禁用状态。准备好后再点击 **启用**；也可以在审核后手动执行一次以验证结果。

审核前无法启用或立即执行，通过普通编辑或 CLI 恢复任务也不能跳过审核。

Codex 支持可转换的每日、每周、每小时、每分钟 RRULE 和未过期的一次性任务；带复杂日期限制、起始时间锚点或无法确定等价节奏的规则需要人工调整。绑定会话的 Codex heartbeat
会转换为共用已导入会话的定时任务，不会改写 QwenPaw 的全局心跳配置。

Qoder 优先读取 `tasks.v2.json`；只有 v2 不存在时才读取 v1。支持一次性、每小时、每日、每周，以及可以保留原节奏的间隔规则。已删除或已结束的任务会过滤，不会恢复运行队列或执行历史。损坏的 v2 文件不会通过回退到 v1 来恢复旧任务。

迁入的任务默认投递到 Console、保存结果到收件箱，并开启工具安全策略。普通任务使用独立任务会话；原应用的模型、通知方式和执行环境信息不代表这些行为会被原样启用。完整说明见
[定时任务](./cron)。

## 重试、中断与重复导入

- **重试失败项**：在结果页勾选失败的工具或设置，点击 **重试已选项** 并确认。系统重新读取来源、生成计划并执行所选项；插件重试仍需确认代码执行。聊天记录不在此重试范围内，需要重新发起包含聊天记录的导入。
- **重复导入**：已导入的来源会话、记忆作用域、定时任务，以及同名 Skill、MCP 和同 ID
  插件会保留已有内容，不会通过重试强制覆盖。需要修改已有内容时，在对应功能页面操作。
- **页面刷新或暂时断线**：重新打开导入页并选择原目标智能体，可以恢复任务视图、重新连接进度。导入期间应保持 QwenPaw 服务运行。
- **取消或服务重启**：取消会等待当前操作安全停止；服务重启会将未完成的扫描或导入标记为中断，不会自动接着运行。已经写入的内容保留，可检查后重试失败项或重新扫描。
- **部分失败**：各项分别写入，一项失败不会撤销其他成功项。取消也不是整批撤销功能。

## 常见问题

### 导入过程耗时较长

先看 **迁移详情**，确认是否出现报错。如迁移过程未出现报错，导入时间较长是正常现象。因为 QwenPaw 导入功能会自动开启 Mission 模式对不兼容 QwenPaw 生态的工具进行持续内容修改和兼容化，直到所有工具都可用为止，而当内容较多时会需要更多时间。但是不必担心，导入是永久性的，也就意味着你只需要做一次导入就能一直使用已导入的会话和工具。导入也受尝试次数和运行时间限制，所以不存在无限期运行导入的情况。

### 未检测到应用，或提示仅限本机访问

检查来源目录是否存在、路径变量是否传给了 QwenPaw 进程，以及运行用户是否有读取权限。通过远程地址访问控制台，不会因此获得导入权限。Codex CLI 不可用时仍可尝试读取本地会话和资产，但可发现的内容可能少于 app-server 可用时。

### 提示“来源数据在预演后发生了变化”

扫描后的工具文件或配置已变化，当前计划不能继续使用。结束本次任务，重新扫描并确认内容后再导入。避免在扫描与开始导入之间同时修改选中的来源内容。

### 需要进一步排查

目标工作区的 `.qwenpaw/imports/` 保存任务快照、计划和兼容性修复摘要。摘要位于
`migration-*/adaptation/summary.md`，可用于检查尚需修复的项目；临时 `staging/` 和兼容性
`manifest.json` 在导入结束时清理，因此不要把它们当作来源备份。详细错误也可结合 QwenPaw
服务日志查看。
