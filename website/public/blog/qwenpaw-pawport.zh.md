你已经在 Codex 或 Qoder 上处理了好几轮需求，确定了多个方案，也留下了一串待办。但是发现这些 AI 工具要么功能不满足自己的需求，要么计费超出自己的预期，抑或是各方面部署和使用都感觉受限。

现在想试试使用 QwenPaw，却发现最先要做的事情，是把项目背景再讲一遍，把工具和技能再部署和注册一遍，有些工具甚至还绑定了 Codex 或 Qoder 环境无法在 QwenPaw 中直接部署。那些慢慢积累起来的东西：顺手的写作或代码审查 Skill、连接外部服务的工具、每天定时生成的简报。重新整理它们，也要花时间，想想就觉得棘手。

**QwenPaw 早已为你考虑到了这些！目前 QwenPaw 已经支持把 Codex、Qoder 中的近期聊天记录、记忆、技能、插件、MCP和定时任务导入 QwenPaw，并对它们做兼容性优化，让已有的工作更容易接着做，实现真正的“无痛迁移”** 你可以先查看能带来哪些内容，再决定导入什么。你也不用担心 QwenPaw 不能使用来自 Codex 和 Qoder 中的工具，QwenPaw 会自己尝试对它们做兼容性优化，使其在 QwenPaw 中也能正常使用。

![pawport](https://img.alicdn.com/imgextra/i1/O1CN01dYqOyowBl3G3OTaP_!!6000000001080-2-tps-1672-941.png)

## 什么时候会用到？

- **项目做到一半，想换个助手继续。** 把需求讨论和已有结论带过来，在 QwenPaw 中接着梳理下一步，少一些复制粘贴和重复解释。
- **已经有一套顺手的工作方式。** 写周报、审代码、整理资料时常用的 Skill，以及连接外部服务的 MCP 配置，可以选择受支持的部分导入，再检查和启用。
- **想把日常任务交给 QwenPaw。** 把已有的每日简报、每周回顾等受支持的定时任务带过来，确认时间和内容后，让它们在 QwenPaw 中继续运行。

## 能带来哪些内容？

目前支持的来源是 **Codex 和 Qoder**。扫描后，页面会列出实际发现的内容：

| 内容           | 可以怎样继续使用                                 |
| -------------- | ------------------------------------------------ |
| 聊天记录       | 在 QwenPaw 中查看已有会话，并继续发送消息        |
| 记忆（Memory） | 将已整理的经验和项目资料保存为带来源的参考内容   |
| 技能（Skill）  | 带来处理特定工作的说明和配套资源，检查后启用     |
| MCP            | 迁入受支持的MCP，补齐授权后再使用                |
| 插件           | 导入能够适配的扩展插件；需要你主动选择并确认安装 |
| 定时任务       | 保留能够转换的任务安排，审核并启用后继续执行     |

实际可导入的范围取决于来源数据和兼容性检查结果。项目目录仍在本机时，聊天可以保留与它的关联；**项目代码和文件本身不会随聊天一起复制**。原应用的登录状态、模型设置和运行环境也需要在 QwenPaw 中另行配置。

## 如何使用导入功能？

假设你正在 Codex 或 Qoder 中规划一个产品介绍网站，已经讨论过页面结构、文案风格和待办事项。现在，想把这些讨论带到 QwenPaw，继续完成首屏文案。

### 开始前，准备这几件事

在保存来源数据的电脑上运行 QwenPaw，并通过本机地址打开控制台。选择接收内容的智能体，确认它使用 **QwenPaw 原生后端**，并配置了可用的模型。还没完成基础配置，可以先看[快速开始](/docs/quickstart?lang=zh)。

打开控制台的 **导入** 页面。PawPort 读取的是运行 QwenPaw 的环境中的数据。如果 QwenPaw 装在容器或远程服务器里，它不会自动读到你浏览器所在电脑上的聊天记录。第一次体验，直接使用保存来源数据的本机环境会更方便。

### 1. 选择来源应用

勾选显示 **已检测到** 的 Codex 或 Qoder，也可以同时选择两者，然后点击 **继续**。

PawPort 会先清点可导入的内容。这一步还没有把聊天记录或工具写入目标智能体，你可以查看清单后再作决定。

![first](https://img.alicdn.com/imgextra/i2/O1CN01M0YeCv93CeC4FLWa_!!6000000004659-0-tps-2092-916.jpg)

### 2. 选好要导入的内容

在 **选择内容** 页面，每个来源都有 **聊天记录** 和 **工具&设置** 两部分。

为了先体验接续讨论，可以保留聊天记录，取消暂时用不到的工具和设置。工具可以逐项选择；聊天记录目前按来源整体选择，不能在这里只勾选某一条对话。

可选择的聊天记录和非插件内容默认勾选，**插件默认不勾选**。检查清单和页面上的 **导入目标智能体**，确认后点击 **开始导入**。

![second](https://img.alicdn.com/imgextra/i4/O1CN01BT3YSNUCAcJ5xqR6_!!6000000005986-0-tps-2938-1662.jpg)

### 3. 看看哪些已经准备好了

导入过程中，每一项都有自己的状态。如果选了工具或定时任务，可能会看到 **兼容性修复中**：正在尝试把它们调整为 QwenPaw 能使用的形式。

结束后，逐项看看结果：**导入成功** 表示内容已写入；**已存在，未覆盖** 表示保留已有内容；失败项可以展开 **迁移详情** 查看原因，再调整配置并重试。

导入成功的工具仍可能需要补充授权、检查依赖或手动启用。导入期间请保持 QwenPaw 运行。

![third](https://img.alicdn.com/imgextra/i3/O1CN01k8kCmi9G9rC3ltKQ_!!6000000006224-0-tps-1858-1252.jpg)

### 4. 打开原来的讨论，继续下一步

回到目标智能体的聊天历史或 **会话** 页面，找到刚才的网站项目讨论。如果原会话已经归档，请在归档会话中查找。

先发一条消息，把接下来的工作说清楚：

```text
请根据这段聊天记录，整理我们已经确定的页面结构、文案风格和未完成事项。
先给我一份简短的进度回顾，再列出完成首屏文案还需要确认的问题。
```

确认它理解了上下文后，再继续：

```text
沿用已经确定的风格，起草首屏标题、副标题和按钮文案，给我两个版本比较。
```

如果下一步要编辑项目文件，先确认会话关联的项目目录正确、文件仍然可访问。后续工作由 QwenPaw 当前配置的模型和工具完成，历史中的工具调用只作为记录保留。

## 让常用工具和日常任务也接上

接续聊天之后，可以逐步启用导入的能力：

- **Skill**：到 **技能** 页面阅读内容，检查需要的程序或资源，再手动启用。
- **MCP**：到 **MCP** 页面检查连接配置，补齐凭据或重新授权，验证连接后启用。
- **记忆**：作为带来源的参考资料保存。使用前核对它属于哪个项目，避免把另一个项目的约定混进来。

以“每天早上整理项目进展”的定时任务为例，导入后可以这样接续：

1. 在 **定时任务** 页面找到标有 **待迁移审核** 的任务，打开 **编辑**。
2. 检查任务内容、时间、时区、结果投递位置和工作目录；页面要求映射目录时，填写实际存在的本地项目目录。
3. 保存后点击 **审核通过**，再点击 **确认审核通过**。此时任务仍然是禁用状态。
4. 可以先手动执行一次，检查结果，再点击 **启用**，让它按计划运行。

迁入的任务默认将结果保存到 QwenPaw 收件箱，便于回来查看。原应用的任务不会因为导入而自动停止；启用前确认由哪一边继续执行，避免收到两份相同的提醒。

## 数据与执行权限，由你掌握

### 原来的内容会被改动吗？

QwenPaw 读取来源数据，适配时处理副本或待导入的配置，不会直接改写 Codex、Qoder 的原文件。重复导入时，已导入的聊天和已有的同名工具等会保留，不会被强制覆盖。

### 数据会在哪里处理？

来源数据的发现和读取在本机完成，导入接口也仅允许本机访问。**兼容性修复会调用你为目标智能体配置的模型，并将相关内容交给它处理。** 使用远程模型时，这部分内容会发送到对应的模型服务，也会产生模型用量。选择工具和设置前，可以先确认自己使用的模型以及要处理的内容。

工具凭据也不会全部原样复制。支持安全迁移的密钥会加密保存，其他配置可能需要你重新填写；OAuth 登录需要重新授权。

### 导入后会立刻开始执行吗？

导入的 **Skill 和 MCP 默认禁用**。**定时任务必须先审核，再单独启用**；未经审核不能运行。你可以先看清楚内容、权限和执行安排，再决定何时使用。

**插件需要额外留意安装这一步。** 它们默认不选中；选中后，页面会要求确认代码执行。安装可能下载依赖、在 QwenPaw 进程中运行代码，并为整个实例添加能力。请确认来源可信后再安装。

## 从一段还没做完的讨论开始

打开 **导入** 页面，选择 Codex 或 Qoder，先把聊天记录带过来。找到那段还没完成的讨论，让 QwenPaw 回顾已有结论，再一起推进下一步。

需要了解具体支持范围、自定义数据目录或失败重试方式等更细化的操作，可以查看 [导入使用文档](/docs/import?lang=zh)。
