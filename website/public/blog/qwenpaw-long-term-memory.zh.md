# QwenPaw 长期记忆：让每次对话，都成为以后用得上的知识

你有没有遇到过这种情况？

上周，你花了一个小时向 AI 解释项目背景。今天打开新对话，它又问：“你们的目标用户是谁？”

三个月前，团队认真比较过两个方案，也说清了为什么选择其中一个。现在再问，AI 只给出一套通用建议，完全不知道当时已经做过什么决定。

问题不在于 AI 不够聪明，而在于过去真正重要的事情，没有被整理成可以长期使用的记忆。

QwenPaw 的长期记忆就是为了解决这个问题。它由 [ReMe](https://github.com/agentscope-ai/ReMe) 驱动，把对话和当前已支持的资料逐步整理成一套属于你的个人知识库。

![QwenPaw 与 ReMe 将对话和资料变成长期记忆](https://img.alicdn.com/imgextra/i3/O1CN01IvOZgheUdXK3OTaP_!!6000000004070-2-tps-1672-941.png)

接下来，我们用一次产品发布，把这套记忆系统从记录、整理到找回完整地走一遍。

## 从一次产品发布说起

假设你是一名产品经理，正在和团队准备新版本发布。过去一个月，你经常和 QwenPaw 讨论这些事情：

- 发布说明应该怎么写；
- 为什么这次不迁移数据库；
- 客户最关心哪些功能；
- 上次发布出了什么问题；
- 接下来还有哪些事情没完成。

如果这些内容只留在几十段聊天记录里，过一阵子就很难再用。真正的长期记忆需要完成四步：

1. **Capture**：从对话和已接入的资料中捕获值得保留的信息；
2. **Index**：让记忆可以通过关键词、语义和知识关系被找到；
3. **Consolidate**：把不同日期的零散记录整合成可复用的长期知识；
4. **Recall**：在新问题出现时，只取回真正相关的内容和依据。

![QwenPaw 长期记忆从记录、整理到找回的完整循环](https://img.alicdn.com/imgextra/i3/O1CN01mG5Uot1GQdX33v4h4_!!6000000000617-55-tps-1200-640.svg)

它很像我们自己做笔记：先保留现场，再整理成经验，真正遇到问题时回到正确的那一页。

## 记忆首先是你拥有的文件

在讨论 QwenPaw 怎样提取和搜索记忆之前，先回答一个更重要的问题：这些记忆到底放在哪里？

QwenPaw 与 ReMe 遵循 **Memory as File, File as Memory** 的设计。核心工作记忆和长期记忆不是藏在不可见的产品数据库里，而是保存在 workspace 中的普通 Markdown 文件；原始对话使用 JSONL，论文 PDF 等来源资料则保留原始格式。

![Markdown 记忆文件连接长期经验和原始证据](https://img.alicdn.com/imgextra/i4/O1CN01wj1PUE1a2d5QtEyUv_!!6000000003272-55-tps-1200-640.svg)

这带来四个直接好处：

- **你看得见**：可以直接打开 daily note 和 digest，检查 QwenPaw 记住了什么；
- **你改得动**：内容不准确或已经过时，可以像修改普通文档一样修正；
- **你查得到来源**：长期结论会通过来源链接回到原始对话或已接入资料；
- **你带得走**：整个 workspace 可以备份、同步、用 Git 管理或迁移到其他环境。

例如，QwenPaw 记成了“所有文章都要先写结论”，但你真正表达的是“技术方案要先写结论”。你可以直接修正这条记忆。下一次写品牌故事时，Agent 就不会机械套用错误偏好。

文件是事实来源，索引、图谱和缓存只是可以重新构建的派生状态。Agent 可以帮你整理记忆，但最终控制权始终属于你。

## Auto Memory：不记住每句话，只保留以后有用的事

一天，你对 QwenPaw 说：

> “发布说明先写用户能得到什么，再介绍技术改动。不要一上来就列版本号和模块名。”

这不是一句随口闲聊，而是以后会反复用到的写作偏好。

同一天下午，团队又讨论了数据库迁移。最后决定本次发布暂不迁移，因为交付时间紧，现有方案仍能满足需求；发布完成后，再单独安排评估。

Auto Memory 不会机械复制整段聊天。它会按配置的用户轮次数周期性运行，并在启用上下文压缩时先处理尚未写入的对话，把真正值得长期保留的内容整理成 daily note：

> **写作偏好**：发布说明先讲用户价值，再讲技术变化。
>
> **项目决定**：本次发布不迁移数据库。
>
> **原因**：交付时间紧，现有方案仍然够用。
>
> **下一步**：发布后重新评估迁移计划。
>
> **来源**：当天的原始对话。

![Auto Memory 把长对话提炼成可复用、可追溯的每日记忆](https://img.alicdn.com/imgextra/i3/O1CN01Qg6uAk1VoeXMqbE54_!!6000000002700-55-tps-1200-640.svg)

几周后再次起草发布说明时，QwenPaw 可以自然地先写用户价值。有人重新提出数据库迁移时，它也能提醒团队：这个方案不是被永久否决，而是推迟到发布之后评估。

长期记忆真正有用的地方，不是记住一句孤立的话，而是保留事情的背景、原因、后续动作和来源。

## 资料也能进入同一条链路

有价值的信息不只来自聊天。

ReMe 提供了 Beta 阶段的 Auto Resource 能力：它可以理解来源资料、保留原始文件，并生成带有来源链接的 daily memory card。QwenPaw 正在逐步接入这条资料链路，目前已经提供的内置入口是 Daily Paper。

启用 Daily Paper 后，它会从 Hugging Face Papers 的周榜和月榜收集候选论文，筛选内容、保存原始 PDF，并生成论文精读和每日简报。这些 Markdown 阅读记录随后会和对话记忆一样进入索引，也可以继续参与 Auto Dream 的长期整理。

例如，如果一篇论文讨论了用户为什么容易忽略新发布的能力，以后你询问如何改进功能触达时，这份阅读记录就可能成为回答的依据。

![ReMe Auto Resource 将来源资料变成可追溯记忆；QwenPaw 目前通过 Daily Paper 接入这条链路](https://img.alicdn.com/imgextra/i2/O1CN015ankve1aJ7LTl8Cxa_!!6000000003308-55-tps-1200-640.svg)

客户访谈报告、会议纪要、项目文档和网页内容等其他资料类型仍在接入中。当前仅把任意文件放入 `resource/`，并不会让 QwenPaw 自动处理它。接入完成后，这些资料也可以沿着同一条可追溯链路，从原始来源进入 daily note，再沉淀为长期知识。

## Auto Dream：让零散日记长成长期经验

只写 daily note 还不够。使用半年后，可能会有几百条记录。如果每次都从头阅读，记忆只是从聊天记录换成了文件堆积。

假设你经历了三次发布：

- 第一次，发布说明写得太技术化，客户看不懂；
- 第二次，先讲用户价值，客户反馈明显更好；
- 第三次，团队又补充了一条经验：重要变化最好配一个使用场景。

Auto Dream 会读取近期发生变化的 daily note，提取值得复用的内容，并把它们整合进长期 digest。面对已有知识，它不会简单追加一份副本，而会根据新证据选择创建、强化、补充或修正原有结论。

最终，分散在不同日期里的记录可以变成一条更完整的经验：

> 发布说明先讲用户能得到什么，再说明技术变化；重要变化尽量配一个实际使用场景。

![Auto Dream 合并新旧经验，Auto Link 同时建立知识连接](https://img.alicdn.com/imgextra/i3/O1CN01DSVTuF1rEr7yobCav_!!6000000005600-55-tps-1200-640.svg)

整合知识时，Auto Link 会把来源和相关概念写成可读的 Wikilink。这样，长期结论既能回到产生它的 daily note，也能连接相邻的偏好、方法和知识节点。

在 QwenPaw 的 Knowledge Base 中，这些关系可以显示为知识图。不同节点代表日期、记忆或知识，连线表示它们之间的来源与关联。你既能看到最终结论，也能追踪它是怎样从多次经历中逐渐形成的。

![QwenPaw Knowledge Base 中由记忆与资料组成的知识关系图](https://img.alicdn.com/imgextra/i1/O1CN01JBjN5c3diWC49o9I_!!6000000000514-0-tps-2048-1024.jpg)

如果团队后来发现，企业客户更希望先看到兼容性提醒，Auto Dream 可以为原来的经验补上适用范围，或修正已经过时的结论，而不是让互相矛盾的说法永远并排存在。

## Memory Search：需要时找回正确的记忆

一个月后，有人问：“当初为什么没有迁移数据库？”

只按字面搜索，可能会翻出所有提到“数据库”的内容。QwenPaw 的 `memory_search` 会组合 BM25 关键词检索与可选的向量检索，通过 RRF 融合结果，再按需沿 Wikilink 展开相关节点。

这让它可以先找到最相关的决定，再查看原因、后续计划和来源，最终回答：

> 当时不是认为迁移没有价值，而是因为发布时间临近，现有数据库仍能满足需求，所以团队决定发布后再评估。这个决定来自 7 月的发布规划讨论。

![混合搜索先找到相关片段，再按需沿知识关系展开](https://img.alicdn.com/imgextra/i2/O1CN01Zln7TK1TJOGqP84hk_!!6000000002361-55-tps-1200-640.svg)

这很像在书架上找东西：先定位最可能相关的书和章节，再根据目录与引用继续查找。Agent 不必把所有旧对话和相邻节点一次性塞进上下文，只需要带回当前问题真正用得上的内容。

即使没有配置 Embedding，BM25 和 Wikilink 展开仍然可以工作；配置向量模型后，语义相近但用词不同的内容也更容易被找到。

## 把完整的记忆循环串起来

现在回到这次产品发布：

1. 你和 QwenPaw 讨论发布计划，Auto Memory 把重要偏好、决定、原因和下一步写入 daily note，同时保留对话来源；
2. 如果启用了 Daily Paper，论文精读会作为当前已接入的资料输入，进入同一个 daily 与索引体系；
3. 后台索引持续让 daily 和 digest 中的 Markdown 保持可搜索；
4. 你主动运行 `/dream`，或启用定时任务后，Auto Dream 把近期记录整合进长期 digest，并用 Wikilink 保留来源与关系；
5. 当新问题出现时，`memory_search` 找到最相关的片段，再沿关系读取必要的上下文；
6. 你可以随时打开、检查和修正这些文件，修正后的内容会继续成为后续协作的依据。

这条链路没有要求模型重新阅读全部历史，也没有把记忆锁在一个不可见的黑盒里：

> 今天聊过的事，成为明天能用的经验；今天已经接入的资料，成为以后回答问题的依据。

## Proactive Mode：一项独立的主动跟进能力

QwenPaw 当前的 `/proactive` mode 与上面的长期记忆循环是两条不同的运行时链路。Auto Dream 会生成 `interests.yaml`，ReMe 也提供读取兴趣主题的底层 job，但 QwenPaw 当前的 `/proactive` 不读取这个文件。

你明确启用 proactive mode 后，QwenPaw 会等待设定的空闲时间。达到阈值后，它会分析近期 chat session；如果当前模型支持图像，还可以使用桌面截图补充上下文，再从这些信息中识别一到三个可能需要继续处理的任务。

例如，近期对话里既有尚未完成的发布说明，也多次出现功能触达问题。会话空闲后，临时创建的 proactive assistant 可以使用当前可用工具，最多调研三个任务 query，然后把主动请求发送回 QwenPaw 对话：

> 你最近的会话里还有一个关于“怎样帮助客户发现新功能”的未完成问题。要不要把发布说明反馈整理成一份具体的后续清单？

这不是一个只负责弹出提醒的功能：它可以读取近期 session 历史、在支持时查看屏幕，并使用工具完成辅助调研。因此必须由你明确启用。可以用 `/proactive <分钟数>` 调整空闲阈值，用 `/proactive off` 停止后台循环。

## 它真的能应对很长的历史吗？

ReMe 使用公开测试验证多会话与超长对话中的记忆能力。

在包含 500 道问题的 LongMemEval cleaned-S 测试中，ReMe 取得了 **89.4%** 的整体 Agentic 得分。在 BEAM 中，100K 设置包含 20 cases / 400 题，得分为 **66.1%**；1M 设置包含 35 cases / 700 题，得分为 **65.0%**。

![ReMe 在 LongMemEval 与 BEAM 上的公开基准结果](https://img.alicdn.com/imgextra/i4/O1CN01ohO0e31MntKw6mQZL_!!6000000001480-55-tps-1200-640.svg)

这些数字不能代表所有真实场景，也会受到模型、数据集与评测设置影响。它们说明的是：随着历史规模增长，文件化整理、混合检索和按需读取仍然能帮助 Agent 从大量旧信息中找到回答依据。

完整设置与分项结果可以查看 [LongMemEval benchmark](https://github.com/agentscope-ai/ReMe/tree/main/benchmark/longmemeval) 和 [BEAM benchmark](https://github.com/agentscope-ai/ReMe/tree/main/benchmark/beam)。

## 最后：长期记忆不是记得越多越好

真正好用的长期记忆，不是把所有聊天原封不动地堆起来，而是做到四件事：

- 捕获真正重要的内容，同时保留来源；
- 把零散经历整理成可以继续演化的知识；
- 需要时准确找回，并按需展开相关依据；
- 让你随时查看、修改、备份和带走。

随着你不断使用 QwenPaw，最初的几条 daily note 会慢慢长成一套真正属于你的个人知识库。

它不只是“记得更多”，而是逐渐理解你的习惯、项目和过去做过的决定。更重要的是，你始终可以看到它记住了什么、为什么形成这个结论，以及应该怎样修正它。
