# QwenPaw 长期记忆：让每次对话，都成为以后用得上的知识

你有没有遇到过这种情况？

上周，你花了一个小时向 AI 解释项目背景。今天打开新对话，它又问：“你们的目标用户是谁？”

三个月前，你们认真比较过两个方案，也说清了为什么选择其中一个。现在再问，AI 只给出一套通用建议，完全不知道你们当时做过什么决定。

问题不在于 AI 不够聪明，而在于它没有把过去真正重要的事情变成可以长期使用的记忆。

QwenPaw 的长期记忆就是为了解决这个问题。它由 [ReMe](https://github.com/agentscope-ai/ReMe) 驱动，会把对话和当前已支持的资料整理成一套属于你的个人知识库。

![QwenPaw 与 ReMe 将对话和资料变成长期记忆](https://img.alicdn.com/imgextra/i4/O1CN016mGvikM8DGD3OTaP_!!6000000003113-2-tps-1672-941.png)

接下来，我们不讲复杂原理，先认识一位用户——小林。

## 小林正在准备一次产品发布

小林是一名产品经理，正在和团队准备新版本发布。过去一个月，她经常和 QwenPaw 讨论这些事情：

- 发布说明应该怎么写；
- 为什么这次不更换数据库；
- 客户最关心哪些功能；
- 上次发布出了什么问题；
- 接下来还有哪些事情没完成。

如果这些内容只留在几十段聊天记录里，过一阵子就很难再用。QwenPaw 会把它们慢慢整理成一条简单的记忆循环：

> **聊过的事情被记下来，零散的记录被整理好，需要时再把最相关的部分找回来。**

![QwenPaw 长期记忆从记录、整理到找回的完整循环](https://img.alicdn.com/imgextra/i3/O1CN01deWyUt1jTUrXQRTJz_!!6000000004549-55-tps-1200-640.svg)

这有点像我们自己做笔记：先写下当天发生的事，之后再复盘成经验，真正遇到问题时再翻到相关的那一页。

## 它不会记住每一句话，只记住以后可能有用的事

一天，小林对 QwenPaw 说：

> “发布说明先写用户能得到什么，再介绍技术改动。不要一上来就列版本号和模块名。”

这不是一句随口闲聊，而是一个以后会反复用到的写作偏好。

同一天下午，团队又讨论了数据库迁移。大家最后决定：这次发布先不迁移，因为交付时间紧，而且现有方案仍能满足需求；等发布完成后，再单独安排评估。

一段长对话里可能有很多尝试、补充和跑题。QwenPaw 不需要逐字背下来，而会留下类似这样的简明记录：

> **写作偏好**：发布说明先讲用户价值，再讲技术变化。
>
> **项目决定**：本次发布不迁移数据库。
>
> **原因**：交付时间紧，现有方案仍然够用。
>
> **下一步**：发布后重新评估迁移计划。
>
> **来源**：当天的原始对话。

![Auto Memory 把长对话提炼成可复用、可追溯的每日记忆](https://img.alicdn.com/imgextra/i2/O1CN01a8Gj7V1UUDFBk6GAU_!!6000000002520-55-tps-1200-640.svg)

几周后，小林让 QwenPaw 起草发布说明，它会自然地先写用户价值。有人再次提出数据库迁移时，它也能提醒团队：“这个方案不是被永久否决，而是推迟到发布之后评估。”

这才是长期记忆真正有用的地方：不是单纯记住一句话，而是记住事情的背景、原因和下一步。

## 零散的日记，会慢慢长成经验

只写日记还不够。使用半年后，可能会有几百条记录。真正省心的是，QwenPaw 还能把多次经历整理成更稳定的经验。

比如，小林经历了三次发布：

- 第一次，发布说明写得太技术化，客户看不懂；
- 第二次，先讲用户价值，客户反馈明显更好；
- 第三次，团队又补充了一条经验：重要变化最好配一个使用场景。

这些记录不需要永远散落在三个日期里。经过整理后，它们会变成一条更完整的写作经验：

> 发布说明先讲用户能得到什么，再说明技术变化；重要变化尽量配一个实际使用场景。

![Auto Dream 合并新旧经验，Auto Link 同时建立知识连接](https://img.alicdn.com/imgextra/i2/O1CN011mEx1x1XmTtCPsruU_!!6000000002966-55-tps-1200-640.svg)

在 QwenPaw 的 Knowledge Base 中，这些连接也可以用知识关系图查看。不同节点代表记忆、资料或日期，节点之间的连线表示它们存在关联。这样，小林既能从一条经验找到相关的原始记录，也能看见原本分散的信息是怎样逐渐连成一张知识网络的。

![QwenPaw Knowledge Base 中由记忆与资料组成的知识关系图](https://img.alicdn.com/imgextra/i1/O1CN01JBjN5c3diWC49o9I_!!6000000000514-0-tps-2048-1024.jpg)

新信息出现时，旧记忆也不是一成不变的。

假设团队后来发现，企业客户更希望先看到兼容性提醒。QwenPaw 会更新原来的经验，补上适用范围，而不是一边坚持旧结论，一边再存一条互相矛盾的新结论。

你可以把这个过程理解成定期复盘：重复出现的结论会更可信，不完整的经验会被补充，过时的说法会被修正。

## 资料也能进入同一条记忆链路

有价值的信息不只来自聊天。

ReMe 提供了 Beta 阶段的 Auto Resource 能力：它可以理解来源资料、保留原始文件，并生成一份带有来源链接的 daily memory card。QwenPaw 正在逐步接入这条链路。目前已经接入的是 Daily Paper：启用后，它会选择研究论文、保留原始 PDF，并把论文精读和每日简报写入记忆。

这些精读内容随后可以和对话记忆一样，参与搜索与整合。例如，如果一篇论文讨论了用户为什么容易忽略新发布的能力，小林以后询问如何改进功能触达时，它就能成为回答的依据。

客户访谈报告、会议纪要、项目文档和网页内容等其他资料类型，目前仍在接入中。接入完成后，像小林的客户访谈总结这样的报告，也可以沿着同一条可追溯链路，从原始资料进入 daily note，再沉淀为长期知识。

![ReMe Auto Resource 将来源资料变成可追溯记忆；QwenPaw 目前通过 Daily Paper 接入这条链路](https://img.alicdn.com/imgextra/i1/O1CN01bfUxpA1gdANS9XGQ1_!!6000000004164-55-tps-1200-640.svg)

## 需要时，它怎样找回正确的记忆？

一个月后，有人问小林：“当初为什么没有迁移数据库？”

如果只按字面搜索，可能会翻出所有提到“数据库”的内容。但 QwenPaw 会先找到最相关的决定，再根据需要查看它的原因和后续计划。

于是，它可以回答：

> 当时不是认为迁移没有价值，而是因为发布时间临近，现有数据库仍能满足需求，所以团队决定发布后再评估。这个决定来自 7 月的发布规划讨论。

![混合搜索先找到相关片段，再按需沿知识关系展开](https://img.alicdn.com/imgextra/i4/O1CN01rHmJoR22rI8gZpRsU_!!6000000007173-55-tps-1200-640.svg)

这很像在书架上找东西：先找到最可能相关的那本书，再翻到对应章节；只有确实需要时，才继续查看它引用的其他资料。

因此，即使历史越来越长，QwenPaw 也不必把所有旧对话重新读一遍。它只需要带回当前问题真正用得上的几段记忆。

## Proactive Mode 会根据近期上下文主动跟进

QwenPaw 当前的 `/proactive` mode 是一项独立的运行时能力，与 Auto Dream 生成的兴趣主题并不是同一条链路。目前，它不会读取 Auto Dream 的 `interests.yaml` 文件。

小林主动启用 proactive mode 后，QwenPaw 会等待设定的空闲时间。达到阈值后，它会分析近期 chat session；如果当前模型支持图像，还可以选择把桌面截图作为补充上下文，再从这些信息中识别一到三个可能需要继续处理的任务。

假设小林最近的对话里，既有尚未完成的发布说明，也多次提到新功能触达问题。会话空闲后，QwenPaw 可能判断这里值得继续跟进。临时创建的 proactive assistant 可以使用当前可用工具，最多调研三个任务 query，然后把面向用户的主动请求发送回 QwenPaw 对话。

最终收到的消息可能是：

> 你最近的会话里还有一个关于“怎样帮助客户发现新功能”的未完成问题。要不要把发布说明反馈整理成一份具体的后续清单？

由于这个模式可以读取近期 session 历史、选择性查看屏幕，并使用工具完成辅助调研，QwenPaw 要求用户明确启用它。你可以用 `/proactive <分钟数>` 调整空闲时间，也可以用 `/proactive off` 停止后台循环。

## 记忆不是黑盒，而是你自己的文件

很多人会担心：AI 记住的内容放在哪里？记错了怎么办？以后能不能带走？

QwenPaw 与 ReMe 选择了一个很朴素的答案：记忆保存为普通的 Markdown 文件。

![Markdown 记忆文件连接长期经验和原始证据](https://img.alicdn.com/imgextra/i1/O1CN01fF7xEt29K2hGFkXFC_!!6000000008048-55-tps-1200-640.svg)

这意味着：

- **你看得见**：可以直接打开文件，看看 QwenPaw 记住了什么；
- **你改得动**：如果内容错误或已经过时，可以自己修改；
- **你查得到来源**：重要结论可以回到当时的对话或资料；
- **你带得走**：可以备份、同步和迁移，不被某个产品锁住。

比如，QwenPaw 记成了“所有文章都要先写结论”，但小林真正想表达的是“技术方案要先写结论”。她可以直接修正这条记忆。下一次写品牌故事时，QwenPaw 就不会再机械套用错误偏好。

Agent 可以帮你整理记忆，但最终控制权仍然属于你。

## 它真的能应对很长的历史吗？

ReMe 也使用公开测试检查长期记忆效果。

在包含 500 道多轮记忆问题的 LongMemEval cleaned-S 测试中，ReMe 取得了 **89.4%** 的整体成绩。在另一项长对话测试 BEAM 中，当对话规模从 100K 扩大到 1M 时，成绩从 **66.1%** 变为 **65.0%**，整体保持稳定。

![ReMe 在 LongMemEval 与 BEAM 上的公开基准结果](https://img.alicdn.com/imgextra/i4/O1CN016I1rKF1tym4HogJ0A_!!6000000005971-55-tps-1200-640.svg)

这些数字不能代表所有真实场景，也会受到模型和测试设置影响。它们主要说明了一件事：历史变长以后，通过整理和按需找回，AI 仍有机会从大量旧信息中找到正确依据。

完整结果可以查看 [LongMemEval benchmark](https://github.com/agentscope-ai/ReMe/tree/main/benchmark/longmemeval) 和 [BEAM benchmark](https://github.com/agentscope-ai/ReMe/tree/main/benchmark/beam)。

## 把小林的一天串起来看

早上，Daily Paper 把选中的研究论文及其精读带入记忆，同时保留原始 PDF。客户访谈报告等其他资料类型仍在接入中。

上午，她和 QwenPaw 讨论发布计划。重要决定、原因和下一步被整理成当天的记忆。

下午，她问起上一次发布失败的原因。QwenPaw 找到旧记录，并带回当时的解决办法。

晚上，零散的新记录被补充到已有经验中。旧结论如果已经不准确，也会得到修正。

之后，小林启用 `/proactive`，会话进入空闲状态后，QwenPaw 会分析近期 session 上下文，在有必要时调研可能的后续任务，并把主动请求发送回对话。

没有哪一步像魔法。真正有价值的是，被捕获的对话与已经接入的来源资料不会白白消失：

> 今天聊过的事，成为明天能用的经验；今天由 Daily Paper 读过的论文，成为以后回答问题的依据。

## 最后：长期记忆不是记得越多越好

真正好用的长期记忆，不是把所有聊天原封不动地堆起来，而是做到四件事：

- 记住真正重要的内容；
- 把零散经历整理成经验；
- 需要时准确找回，并说明依据；
- 让你随时查看、修改和带走。

随着你不断使用 QwenPaw，最初的几条日记会慢慢长成一套真正属于你的个人知识库。

它不只是“记得更多”，而是越来越理解你的习惯、项目和过去做过的决定——并且，你始终知道它为什么这样理解。
