# QwenPaw 长期记忆：让每次对话，都成为以后用得上的知识

你有没有遇到过这种情况？

上周，你花了一个小时向 AI 解释自己的研究框架。今天打开新对话，它又问：“你重点跟踪哪些公司？”

三个月前，你认真分析过锂价下跌对动力电池企业的影响，也记下了判断成立的条件。现在再问，AI 只给出一套通用结论，完全不知道当时已经验证过什么、还有哪些风险待确认。

问题不在于 AI 不够聪明，而在于过去真正重要的事情，没有被整理成可以长期使用的记忆。

QwenPaw 的长期记忆就是为了解决这个问题。它由 QwenPaw 管理的核心长期记忆文件 `MEMORY.md` 和 [ReMe](https://github.com/agentscope-ai/ReMe) 个人知识库共同组成：前者可以由你和 Agent 共同维护并选择直接加载到上下文，后者把对话和当前已支持的资料逐步整理成可按需检索的 Markdown 知识。

![QwenPaw 与 ReMe 将对话和资料变成长期记忆](https://img.alicdn.com/imgextra/i3/O1CN01IvOZgheUdXK3OTaP_!!6000000004070-2-tps-1672-941.png)

接下来，我们跟随一名研究新能源汽车产业链的金融分析师，把这套记忆系统从记录、整理到找回完整地走一遍。

## 从一次产业链研究说起

假设你是一名金融分析师，正在持续研究新能源汽车产业链。过去一个月，你经常和 QwenPaw 讨论这些事情：

- 宁德时代的动力电池与储能业务怎样变化；
- 动力电池价格下行会怎样影响毛利率；
- 碳酸锂供需处于什么阶段；
- 锂价下跌究竟利好电池厂，还是会带来库存减值；
- 当前判断还有哪些假设尚未验证。

如果这些内容只留在几十段聊天记录里，过一阵子就很难再用。真正的长期记忆需要完成六件事：

1. **记录**：从对话中留下研究偏好、事实、判断、理由和待验证假设；
2. **引入**：从已经接入的外部数据源补充论文等资料；
3. **整理**：把不同日期的零散记录沉淀为长期知识；
4. **连接**：用来源链接和 Wikilink 串起公司、产业链、结论与证据；
5. **找回**：通过关键词、语义和知识关系找到真正相关的内容；
6. **展开**：先返回最相关的片段，证据不足时再沿文件和链接继续阅读。

![QwenPaw 长期记忆从记录、整理到找回的完整循环](https://img.alicdn.com/imgextra/i3/O1CN01mG5Uot1GQdX33v4h4_!!6000000000617-55-tps-1200-640.svg)

它很像我们自己做笔记：先保留现场，再整理成经验，真正遇到问题时回到正确的那一页。

## 记忆首先是你拥有的文件

在讨论 QwenPaw 怎样提取和搜索记忆之前，先回答一个更重要的问题：这些记忆到底放在哪里？

QwenPaw 与 ReMe 遵循 **Memory as File, File as Memory** 的设计。核心记忆、每日记忆和整合后的长期知识不是藏在不可见的产品数据库里，而是以普通 Markdown 文件保存在 Agent Configuration Directory，也就是 Agent 自己的工作区中；原始对话使用 JSONL，论文 PDF 等来源资料则保留原始格式。

![Markdown 记忆文件连接长期经验和原始证据](https://img.alicdn.com/imgextra/i3/O1CN01vwIbuJ1zAkVDvcYjh_!!6000000006674-55-tps-1200-640.svg)

沿着这名分析师的研究过程，工作区会逐渐长成下面这样：

```text
workspace/
├── MEMORY.md                         # 少量、稳定的核心长期记忆
├── memory/
│   ├── 2026-08-14.md                 # 当天记忆笔记的自动索引页
│   └── 2026-08-14/
│       ├── 宁德时代盈利讨论.md        # 一个 session 对应的一条记忆笔记
│       └── 锂价敏感性分析.md
├── digest/
│   ├── personal/                     # 个人偏好、关注范围与长期约定
│   ├── procedure/                    # 可复用的研究流程
│   └── wiki/                         # 公司、行业、指标等知识
├── mem_session/                      # 可追溯的来源对话
├── resource/                         # PDF 等原始资料
└── mem_metadata/                     # 可重建的索引、图谱与缓存
```

| 对象或机制                           | 它负责什么                                                                                         | 怎样进入上下文或被找回                                                    |
| ------------------------------------ | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `MEMORY.md`                          | QwenPaw 的核心长期记忆；你和主会话中的 Agent 都可以自由读取、编辑和更新                            | 通过文件工具按需读取；不属于 ReMe 的 `memory_search` 索引                 |
| `memory/YYYY-MM-DD.md`               | 当天所有记忆笔记的索引页；ReMe 自动维护 `notes:auto` 区块，用户和主 Agent 可在自动区块之外补充内容 | 属于个人知识库，可搜索、直接读取，并可沿索引渐进式展开                    |
| `memory/YYYY-MM-DD/{name}.md`        | Auto Memory 为一个 session 创建或更新的一条主题记忆笔记                                            | 属于个人知识库；主 Agent 通常不需要主动管理                               |
| `digest/` 中的所有 `.md`             | ReMe 整理出的长期知识，分为 `personal`、`procedure` 和 `wiki` 三类，并用 Wikilink 相互连接         | 属于 `memory_search` 的检索范围                                           |
| `memory/` + `digest/` 中的所有 `.md` | ReMe 个人知识库的完整文件范围：前者保留每日研究现场，后者保存跨时间整理后的知识                    | `memory_search` 的完整检索范围                                            |
| `memory_search` 返回的片段           | 与当前问题最相关的局部内容及其文件路径                                                             | 片段不足时，Agent 使用 `read_file` 按路径渐进展开，只读取当前任务所需内容 |

这带来四个直接好处：

- **你看得见**：可以直接打开每日记忆和长期知识节点，检查 QwenPaw 记住了什么；
- **你改得动**：内容不准确或已经过时，可以像修改普通文档一样修正；
- **你查得到来源**：长期结论会通过来源链接回到原始对话或已接入资料；
- **你带得走**：整个 Agent 工作区可以备份、同步、用 Git 管理或迁移到其他环境。

一条已经沉淀下来的产业链长期记忆，可能是这样的：

```markdown
---
name: 新能源汽车产业链
description: 跟踪整车需求、动力电池盈利与上游锂资源的传导关系。
---

# 新能源汽车产业链

需求从整车销量传导到动力电池排产，再影响正极材料和锂资源需求。

- 代表性电池企业：[[digest/wiki/宁德时代.md]]
- 关键成本项：[[digest/wiki/碳酸锂.md]]
- 分析方法：[[digest/procedure/动力电池盈利敏感性分析.md]]

## Sources

- [[memory/2026-08-14/锂价敏感性分析.md]]
```

正文保存知识，frontmatter 提供概要，Wikilink 则把公司、成本项、分析方法和来源串起来。从“新能源汽车产业链”指向“宁德时代”的链接是一条出边；系统同时建立反向索引，所以从“宁德时代”也能回到引用它的产业链和研究记录。作者只需写一次链接，Agent 就能在检索时双向展开。

例如，QwenPaw 记成了“分析公司时统一先看市盈率”，但你真正表达的是“分析盈利稳定的消费公司时先看市盈率”。你可以直接修正这条记忆。下一次研究周期股时，Agent 就不会机械套用错误的估值框架。

文件是事实来源，索引、图谱和缓存只是可以重新构建的派生状态。Auto Memory 和 Auto Dream 不会覆盖 `MEMORY.md`。Agent 可以帮你整理记忆，但最终控制权始终属于你。

为了让这些文件可检索，ReMe 会先解析 frontmatter，再按 Markdown 的标题层级、段落、列表、表格和代码块构建 AST 并分块，而不是每隔固定字符生硬切断。每个片段保留必要的祖先标题、文件路径和行号；Wikilink 则独立形成文件图谱。于是，同一份 Markdown 既能提供保持语义完整的搜索片段，也能提供从公司走向行业、方法和原始证据的关系路径。

## Auto Memory：不记住每句话，只保留以后有用的事

一天，你对 QwenPaw 说：

> “先把宁德时代加入重点跟踪。当前假设是碳酸锂价格下跌有利于电芯单位成本，但还要检查库存减值和售价联动。”

这不是一句孤立的市场观点，而是一项研究范围、一条当前判断和两个待验证条件。

同一天下午，你又补充了动力电池价格和公司库存周期的数据，并说明只有当原料成本下降快于售价、且高价库存风险可控时，利润改善的判断才成立。

Auto Memory 不会机械复制整段聊天。它默认每累计 5 个用户回合运行一次，并在发生上下文淘汰或折叠时先处理尚未写入的对话，把真正值得长期保留的内容整理成每日记忆；如果没有值得新增或更新的内容，也不会制造空记忆：

> **研究对象**：将宁德时代加入新能源汽车产业链的重点跟踪名单。
>
> **当前判断**：锂价下跌通常有利于降低电芯单位成本。
>
> **成立条件**：原料成本下降快于电芯售价下调，高价库存减值风险可控。
>
> **待验证项**：售价联动速度、库存成本和动力与储能产品结构。
>
> **来源**：当天的原始对话。

![Auto Memory 把长对话提炼成可复用、可追溯的每日记忆](https://img.alicdn.com/imgextra/i3/O1CN01Qg6uAk1VoeXMqbE54_!!6000000002700-55-tps-1200-640.svg)

后台会把来源会话保存为可追溯的 JSONL，并在当天的日期子目录中为这个 session 创建或更新一条主题记忆，例如 `memory/2026-08-14/锂价敏感性分析.md`。`memory/2026-08-14.md` 是当天笔记的自动索引页；同一天再次处理同一 session 时，系统会合并更新原笔记，而不是按对话中的多个话题拆出多份文件。主 Agent 通常只需在检索后按路径展开，不必主动维护这些笔记。

这个日期索引页的实际结构类似下面这样：

```text
---
name: 2026-08-14
description: 2 note(s) today.
---

<!-- notes:auto -->
- [[memory/2026-08-14/宁德时代盈利讨论.md]] name: 宁德时代盈利讨论 description: 跟踪动力与储能业务的量、价、成本驱动。
- [[memory/2026-08-14/锂价敏感性分析.md]] name: 锂价敏感性分析 description: 分析锂价下跌对电芯成本、售价与库存减值的影响。
<!-- /notes:auto -->
```

索引行来自每条笔记的 frontmatter。`notes:auto` 区块会在刷新时整体重建，不应手工编辑；自动区块之外的正文则会保留。真正的 session 记忆位于日期子目录中，并通过 `session_id` 与 `source_conversation` 指回原始 JSONL：

```markdown
---
name: 锂价敏感性分析
description: 分析锂价下跌对电芯成本、售价与库存减值的影响。
session_id: qpsid_sha256_<64-hex>
source_conversation: "[[mem_session/dialog/qpsid_sha256_<64-hex>.jsonl]]"
---

## 当前判断

锂价下跌通常降低电芯材料成本，但仍需检查售价联动速度和高价库存减值。
```

如果模型后来优化了笔记的 `name`，文件也会安全重命名并同步更新链接。自动召回的旧记忆在抽取前会被移除，避免系统把刚刚找回的内容误当成用户新提供的事实。

![Auto Memory 完成后推送到 Inbox 的任务结果](https://img.alicdn.com/imgextra/i3/O1CN01q1761gvctQB49nzS_!!6000000007099-0-tps-2048-414.jpg)

Inbox 只负责展示后台运行结果。真正可编辑、可复用的记忆，仍然是工作区里的 Markdown 文件。

几周后再次写宁德时代研报时，QwenPaw 可以找回这条判断。有人直接把锂价下跌解释为利润利好时，它也能提醒你：还需要核对售价联动、库存成本和产品结构，不能只根据锂价方向下结论。

长期记忆真正有用的地方，不是记住一句孤立的话，而是保留事情的背景、原因、后续动作和来源。

## 资料也能进入同一条链路

有价值的信息不只来自聊天。

Auto Resource 是 Beta 阶段的外部资料管线总称。QwenPaw 目前已经提供 Daily Paper 和 Auto Fin 两个内置入口，其他类型仍在持续扩展。

启用 Daily Paper 后，它会从 Hugging Face Papers 的周榜和月榜收集候选论文，筛选内容、保存原始 PDF，并生成三篇论文精读和一份每日简报。这些 Markdown 阅读记录随后会和对话记忆一样进入索引，也可以继续参与 Auto Dream 的长期整理。

如果把关注主题设置为 `battery, lithium, energy storage`，这条资料链路会持续补充电池材料、寿命预测和储能技术研究：原始 PDF 写入 `resource/papers/`，论文精读与每日简报写入 `memory/YYYY-MM-DD/`。进入日期目录的是 Markdown 阅读记录，因此它们既能参与普通检索，也能在之后被整理成长期知识。

例如，如果一篇论文讨论了电池寿命预测或储能技术，以后你评估动力电池企业的技术竞争力时，这份阅读记录就可能成为回答的依据。

Auto Fin 则面向财经研究。它默认回看最近 24 小时的财联社电报，按关注主题筛选相关新闻，再搜索已有 ReMe 记忆补充历史背景，最终把一份带有效 Wikilink 的中文报告写入当天的记忆目录。当前新闻与中间筛选结果不会持久化；没有相关新闻时任务会正常跳过。同日再次运行会参考已有报告并原子覆盖为修订结果。

Auto Fin 不具备可靠行情数据，不计算收益、目标价或买卖点，也不提供投资建议。

![Daily Paper 的调度与主题配置](https://img.alicdn.com/imgextra/i4/O1CN01P4HuDOo3HjE3MD24_!!6000000007223-0-tps-1654-670.jpg)

当前仅把任意文件放入 `resource/`，仍不会让 QwenPaw 自动处理它。因此，现阶段不应把 Auto Resource 理解成通用文件导入器。

## Auto Dream：让零散日记长成长期经验

只写每日记忆还不够。使用半年后，可能会有几百条记录。如果每次都从头阅读，记忆只是从聊天记录换成了文件堆积。

假设你在不同日期留下了三条研究记录：

- 第一条，锂价下跌降低正极材料成本；
- 第二条，电芯价格也可能随原料价格下调；
- 第三条，高价库存会在短期带来减值压力。

Auto Dream 会读取近期发生变化的每日记忆，提取值得复用的内容，并把它们整合进长期知识节点。它先判断内容应该写成哪一类长期记忆：

| 记忆类型    | 保存内容与写法                                           | 金融分析师示例                           |
| ----------- | -------------------------------------------------------- | ---------------------------------------- |
| `personal`  | 用户身份、偏好、关注范围和长期约定                       | 重点跟踪中国新能源汽车产业链和锂资源公司 |
| `procedure` | 可复用的操作流程，写成包含步骤、输入和注意事项的 runbook | 动力电池公司盈利敏感性分析流程           |
| `wiki`      | 定义、事实、观察、原则和心智模型                         | 宁德时代、碳酸锂、库存减值及锂价传导机制 |

分类后，Auto Dream 会搜索已有节点，判断新材料与旧知识的关系，并且只选择一个整理动作：

| 动作          | 它在这次研究中意味着什么                         |
| ------------- | ------------------------------------------------ |
| `CREATE`      | 还没有同类知识，创建一个新节点                   |
| `CORROBORATE` | 新数据再次支持原判断，补充来源或强化表述         |
| `REFINE`      | 新材料增加条件、边界、步骤或细节                 |
| `CORRECT`     | 新证据修正原节点中的错误、遗漏或与现实不符的判断 |

最终，分散在不同日期里的记录可以变成一条更完整的经验：

> 锂价下跌通常缓解动力电池材料成本，但对宁德时代利润的净影响还取决于售价联动速度、库存成本、客户议价与产品结构，不能只依据锂价方向判断。

![Auto Dream 合并新旧经验，Auto Link 同时建立知识连接](https://img.alicdn.com/imgextra/i3/O1CN01DSVTuF1rEr7yobCav_!!6000000005600-55-tps-1200-640.svg)

整合知识时，Auto Link 会把来源和相关概念写成可读的 Wikilink。这样，长期结论既能回到产生它的每日记忆，也能连接相邻的偏好、方法和知识节点。Auto Dream 不会改写每日记忆：`memory/` 保留当时的研究现场，`digest/` 保存跨时间后仍值得复用的结论。

例如，它不会只在文末堆出几个裸链接，而会把关系写进句子：“锂价变化通过 [[digest/wiki/碳酸锂.md]] 影响 [[digest/wiki/宁德时代.md]] 的材料成本，具体评估可使用 [[digest/procedure/动力电池盈利敏感性分析.md]]。”每个长期节点还会在 `## Sources` 中指回 daily note，让最终结论始终有证据链可循。

![Auto Dream 完成后推送到 Inbox 的任务摘要](https://img.alicdn.com/imgextra/i1/O1CN01ddkg0rN9DXK49o5c_!!6000000001181-0-tps-2048-796.jpg)

在 QwenPaw 的 Knowledge Base 中，这些关系可以显示为知识图。不同节点代表日期、记忆或知识，连线表示它们之间的来源与关联。你既能看到最终结论，也能追踪它是怎样从多次经历中逐渐形成的。

## Memory Search：需要时找回正确的记忆

一个月后，你准备更新研报，问：“锂价下跌对宁德时代是利好吗？”

只按字面搜索，可能会翻出所有提到“锂价”或“宁德时代”的内容。QwenPaw 的 `memory_search` 会组合 BM25 关键词检索与可选的向量检索，通过 RRF 融合结果，再按需沿 Wikilink 展开相关节点。

这让它可以先找到最相关的判断，再查看成立条件、待验证项和来源，最终回答：

> 锂价下跌通常降低材料成本，但对宁德时代利润的净影响取决于售价联动、库存成本、客户议价和产品结构。此前的敏感性分析支持成本改善方向，但仍需结合最新季度数据核对这些条件。

![混合搜索先找到相关片段，再按需沿知识关系展开](https://img.alicdn.com/imgextra/i2/O1CN01Zln7TK1TJOGqP84hk_!!6000000002361-55-tps-1200-640.svg)

这很像在书架上找东西：先定位最可能相关的书和章节，再根据目录与引用继续查找。Agent 不必把所有旧对话和相邻节点一次性塞进上下文，只需要带回当前问题真正用得上的内容。

即使没有配置 Embedding 模型，BM25 和 Wikilink 展开仍然可以工作；配置向量模型后，语义相近但用词不同的内容也更容易被找到。

BM25 擅长“宁德时代”“CATL”“碳酸锂”这类明确名称；向量检索则可以让“上游原料降价对电芯龙头利润的影响”命中措辞不同的“锂价敏感性分析”。RRF 根据两路结果的名次进行融合，避免某一路的分数尺度支配最终排序。

`memory_search` 的范围是 `daily_dir`（默认 `memory/`）和 `digest_dir`（默认 `digest/`）下的全部 Markdown 文件。索引后台只监听这两个目录，每个文件最大 10 MiB；根目录的 `MEMORY.md`、`resource/` 与 `mem_session/` 不进入 ReMe 搜索。例如，搜索“锂价下跌如何影响宁德时代盈利”可能返回：

```text
========== digest/wiki/宁德时代.md:18-24 [score=0.0325 vector=0.8120 keyword=8.4700] ==========
## 锂价与盈利敏感性
锂价下跌通常降低材料成本，但净影响取决于售价联动、库存成本与产品结构。
参见 [[digest/wiki/碳酸锂.md]] 和 [[digest/procedure/动力电池盈利敏感性分析.md]]。
  outlinks (2):
    → digest/wiki/碳酸锂.md  name="碳酸锂"
    → digest/procedure/动力电池盈利敏感性分析.md  name="动力电池盈利敏感性分析"
  inlinks (2):
    ← digest/wiki/新能源汽车产业链.md  name="新能源汽车产业链"
    ← memory/2026-08-14/宁德时代盈利讨论.md  name="宁德时代盈利讨论"
```

返回结果先给出命中片段的路径和行号，以及关键词、向量与融合排序信息；正文可以包含原始 Wikilink。`outlinks` 是命中文档引用的下游，`inlinks` 是引用命中文档的上游。

这是一种渐进式混合搜索：第一步只取回最相关的局部片段；如果还不能回答“为什么”，Agent 再打开“碳酸锂”或盈利敏感性分析流程；如果要核对判断何时形成，则沿入边打开 8 月 14 日的讨论。它不必一开始把整座知识库塞进上下文，却始终保留了从结论走向概念、方法和原始记录的路径。`MEMORY.md` 则通过文件工具按需读取，不依赖 ReMe 搜索。

## 把完整的记忆循环串起来

现在回到这名金融分析师的研究过程：

1. 你在 `MEMORY.md` 中写下“重点跟踪新能源汽车、锂电池和锂资源”的稳定研究范围；
2. Auto Memory 把当天关于宁德时代与锂价的 session 总结成一条日期子目录笔记，并刷新当天索引页；
3. 如果启用了 Daily Paper，相关论文精读会进入同一个每日记忆与索引体系；
4. 后台索引持续更新 Markdown 片段、BM25、可选向量索引与 Wikilink 文件图谱；
5. 你主动运行 `/dream`，或启用定时任务后，Auto Dream 把多天记录整理为 `personal`、`procedure` 和 `wiki` 长期节点；
6. 下一次写研报时，`memory_search` 先返回最相关的片段，再沿出边、入边和文件路径读取必要的上下文；
7. 你可以随时打开、检查和修正这些 Markdown，修正后的内容会继续成为后续协作的依据。

![QwenPaw 长期记忆控制台总览](https://img.alicdn.com/imgextra/i2/O1CN019aX2sCLIZvB6wGdo_!!6000000005818-0-tps-3418-1594.jpg)

这条链路没有要求模型重新阅读全部历史，也没有把记忆锁在一个不可见的黑盒里：

> 今天聊过的事，成为明天能用的经验；今天已经接入的资料，成为以后回答问题的依据。

## 它真的能应对很长的历史吗？

ReMe 使用公开测试验证多会话与超长对话中的记忆能力。

在包含 500 道问题的 LongMemEval cleaned-S 测试中，ReMe 取得了 **89.4%** 的整体 Agentic 得分。在 BEAM 中，100K 设置包含 20 个案例、400 道题，得分为 **66.1%**；1M 设置包含 35 个案例、700 道题，得分为 **65.0%**。

![ReMe 在 LongMemEval 与 BEAM 上的公开基准结果](https://img.alicdn.com/imgextra/i4/O1CN01ohO0e31MntKw6mQZL_!!6000000001480-55-tps-1200-640.svg)

这些数字不能代表所有真实场景，也会受到模型、数据集与评测设置影响。它们说明的是：随着历史规模增长，文件化整理、混合检索和按需读取仍然能帮助 Agent 从大量旧信息中找到回答依据。

完整设置与分项结果可以查看 [LongMemEval benchmark](https://github.com/agentscope-ai/ReMe/tree/main/benchmark/longmemeval) 和 [BEAM benchmark](https://github.com/agentscope-ai/ReMe/tree/main/benchmark/beam)。

## 最后：长期记忆不是记得越多越好

真正好用的长期记忆，不是把所有聊天原封不动地堆起来，而是做到四件事：

- 捕获真正重要的内容，同时保留来源；
- 把零散经历整理成可以继续演化的知识；
- 需要时准确找回，并按需展开相关依据；
- 让你随时查看、修改、备份和带走。

随着你不断使用 QwenPaw，最初的几条每日记忆会慢慢长成一套真正属于你的个人知识库。

它不只是“记得更多”，而是逐渐理解你的研究偏好、跟踪对象和判断形成过程。更重要的是，你始终可以看到它记住了什么、为什么形成这个结论，以及应该怎样修正它。
