## 1. 核心原则

**总原则**：上游已有现成 E2E 测试（tests/e2e 197 条 + CI e2e job）——不新建，先摸清怎么运作，再在既有基础上优化扩展。

**事实 + 推理 + 证据链**：
- 一切判断基于证据
- 截图/视频是 E2E 的第一证据——判定必附现场证据，不凭日志空口断言
- 不瞎猜瞎编：不确定的状态不编造结论，拿不准的结论必须标注「未确认」或「推测」

- **位置**：上游仓库 `tests/e2e/`

  ```bash
  pytest tests/ -m "integration and p1"  # nightly 回归

  ```

## 3. 选择器规范与 UI 改版适配

### 3.1 稳定选择器优先级

1. **专用测试锚点**（data-testid 类）优先
2. **语义化 role/label** 次之
3. **结构类选择器**（层级/位置）最后——UI 改版最先碎的就是它

### 3.2 UI 大改版批量适配方法

**历史先例**：
- **#6185**：v2.0.0 UI 改版适配——改版前先盘点受影响选择器面，改版后批量适配一次过审，不散修
- **#5542**：agentscope 2.0 适配——跨版本大改的适配节奏与验证方法

**适配流程**：
1. 改版前：盘点受影响的选择器面（grep 搜索旧选择器）
2. 改版后：批量适配，本地跑绿
3. 推 fork 跑 CI 验证
4. 开上游 PR

## 4. 超时治理

### 4.1 分类

- **真超时**：功能卡死 = 真缺陷 → 提 Aone 单
- **误报超时**：阈值不合理/环境慢 → 调阈值 + 留痕

### 4.2 方法论

1. 先分真超时 vs 误报超时
2. 误报类：调阈值 + 留痕（为什么这个值）
3. 真超时类：提缺陷
4. 与 flaky 的边界：时好时坏走观察窗法，稳定超时走阈值/缺陷分流

### 4.3 首个处理项

v2.1.0-beta 测试中 E2E 600 秒超时误报——超时设置偏紧导致慢用例被误判失败。祖冲之评审建议调约 1800 秒。

## 5. 证据纪律

### 5.1 截图/视频证据留存规范

- E2E 判定必附现场证据：关键步骤截图、失败时刻截图/视频
- 证据文件实际落盘 + 结果块中正确引用（引用路径必须真实存在，禁"分析结论伪装成文件"）
- 版本感知留存：证据按版本/轮次归档，可追溯

### 5.2 证据文件命名

```
screenshots/{test_name}_{step_number}_{timestamp}.png
videos/{test_name}_{timestamp}.webm
```

## 8. Aone 提单与六步标准工作流

### 8.1 Aone 提单

**前置**：E2E 失败先经根因定性（qpqat_root_cause），确认产品缺陷才提单；上游契约变更/环境/flaky/用例质量问题不提单

**固定口径**：
- 发现渠道：**3-CI E2E 测试**
- 署名：**李时珍·E2E@QPQAT** 钉正文最顶部
- 指派：模块负责人，实时查询为准（绝不指派泰哥）；每单抄送崔越 387564
- 严重度：P0→87 / P1→88 / P2→89，优先级联动 urgent/high/medium
- 截图/证据必须嵌入正文（`![](url)`），只挂附件 = 违规
- 提交后必回读核验 + 留痕，谁提单谁跟到闭环

### 8.2 六步标准工作流

1. 克隆源头 = 泰哥 fork 仓库 `yutai78786/QwenPaw`（我的克隆 origin=泰哥 fork，upstream=上游主仓只读同步、**绝不 push upstream**）
2. 开**本地分支**开发（不在主干直接改）
3. 开发完成先做**本地验证**（本地跑通验证通过才算完成）
4. 推到 fork 仓库的分支上**跑 CI**（fork 的 PR 触发 CI）
5. CI 通过后用**中文**出正式 PR 描述，与泰哥对焦（经姜子牙转呈拍板）
6. 泰哥确认 OK 后**转英文开上游 PR**
