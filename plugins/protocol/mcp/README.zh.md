# QwenPaw MCP

## MCP 可选运行时

官方插件 ID 为 `qwenpaw-mcp`，协议名为 `mcp`。本次交付 MCP 可选插件与公开 SDK 1.1
Driver 支持，不包含 Agent Mail 或 ACP 插件化。

- **新用户或未使用 MCP 的用户：**不创建插件安装目录、加载记录、MCP 连接、DriverManager
  或 MCP 扫描任务。`/mcp` 导航和初始页面仍在；仅访问页面不会安装或启动运行时。
  在原页面点击**安装**即可使用随发行包提供的离线资源，随后继续配置服务器。
  已安装但未启用时，页面提供**启用**操作。
- **已有自定义 MCP 配置：**启动检查各工作区并在符合条件时离线安装，保留来源设置、凭据、
  OAuth、策略与白名单。全部来源停用时仍可管理配置，但不连接服务。旧 `mcp.clients`
  只转换一次；已有 DriverCard 和迁移水位避免重复转换或恢复已删除来源。
  未修改的默认禁用 AnySearch 配置本身不会触发安装。
- **显式禁用或卸载：**后续启动尊重该选择，保留配置和凭据。通过 MCP 页面重新启用；
  卸载后可显式安装并复用原设置。停用单个来源只关闭该来源；禁用插件停止插件运行时。
  更新通过常规插件管理进行，启动不会覆盖用户已安装的插件代码，也不会后台联网安装依赖。

升级保留 `command`、`args`、`cwd`、`env`、`url`、`headers`、`timeout`、显示名、
各来源启用状态以及凭据引用、OAuth、策略和工具白名单。`tools: []` 仍表示全部禁止。
不同工作区中的同名来源保持独立身份。

启用插件且工作区仍需监测时，保留原有的**两秒**文件扫描，包括全部自定义来源暂时停用
的情况。手工将来源改为启用后，下一轮扫描生效；连接和发现可能需要额外时间。
插件未安装或未启用时没有 MCP 扫描。配置监测与服务连接条件相互独立。

### 故障恢复

安装或启用失败后原 MCP 页面仍然可见，可重试。先检查页面错误与日志；本地依赖缺失时
使用正常应用安装程序修复，启动过程不执行 pip/uv。重试时无需删除 DriverCard、凭据或
升级记录。更新失败会保留或回滚旧插件代次；资源忙时可能需要重启后再试。
中断升级通过事务记录恢复；无效元数据或无法明确判断的旧配置进入待检查状态，不猜测或
丢弃配置。手工修复损坏文件前先备份相关工作区与配置。

wheel、sdist 与桌面包使用同一份 `plugins/protocol/mcp` 资源，包括预构建前端。
资源仅供离线安装，不加入插件发现目录。共享消费者仍可能使用上游 `mcp` 包；本次保证
针对项目可选运行时，不承诺环境中完全没有 `mcp.*` 导入。
