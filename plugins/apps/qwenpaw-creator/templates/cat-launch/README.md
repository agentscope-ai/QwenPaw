# 非正式发布会

Creator 官方内置模板，ID 为 `informal_launch`。选择“非正式发布会”、上传猫、狗等主体的参考图，发送“给它做个非正式发布会”。固定的是官方视觉包装和制作契约，主体的动作、小情节与文案按本次图片重新创作。支持单图或多图，也可同时上传音频；有上传音频时优先用作 BGM，没有时由单次 r2v 同步生成画面与轻快发布会配乐。模板引导现有 Creator 流程完成读图、分镜、视频、双语包装与 MP4 合成，默认约30秒。生成视频始终铺满项目画布，文字与动效直接叠加在视频内部。

创作规则、字幕样式及封面位于本目录；字幕设计知识定义在 Creator 内置技能 [`informal-launch-captions/SKILL.md`](../../backend/skills/informal-launch-captions/SKILL.md)。`video_templates.py` 将 `template.json` 注册为官方内置模板，风格选择器接入 `presentation.ts`，用 `cover.jpg` 展示并置于“默认风格”之后、其他模板之前。模板字幕入口为 `backend/services/media_files/informal_launch_template.py`，现有动效设计和渲染流程仅在选中本模板时调用它；不修改 Agent 基础 prompt 或现有通用 skill，不新增 Agent/specialist，也不改变通用字幕的默认渲染行为。

## 使用

模板随 Creator 插件源码一起提供，不再依赖 `user-templates/` 安装。开始创作时，“默认风格”保持第一位，“非正式发布会”作为第一张官方风格卡紧随其后，使用带文本的猫咪发布会封面，不显示用户模板删除按钮。封面只是风格示例，支持一张或多张参考图。

历史 `user:cat_launch_v1` 选择值仍解析到该官方模板；列表不会重复展示旧用户模板副本，也不会删除用户数据。已有项目保留自身的模板快照，需在修订时明确应用新版规则。

在「通用」场景中新建项目，选择「非正式发布会」。推荐16:9；用户已选9:16等画幅时按该画幅重新构图，不由原照片比例强制决定。上传清晰参考图及可选音频，发送一句需求，不必提供宠物名字、长提示词、分镜或字幕坐标。继续遵循项目已有执行授权设置。

## 内容如何随参考图变化

整体语气是用认真的发布会包装主体不太认真的一面。先结合图片与用户描述识别主体、可见体态、配件、道具和环境，再构思若干适合它的小情节，只选能在片长内讲清的内容。通常考虑一到两个俏皮桥段，也可按用户意图采用更安静的反应。照片事实与本片的创意表演分开记录，既不靠照片断言真实长期性格，也不因为照片是静态的就禁止创作新动作。

- 根据用户上传的参考图、主体特点和用户需求，自由设计自然、轻松、有趣的俏皮镜头。具体动作、情节、道具和反应由本次内容决定，保持主体身份与身体结构一致，让每次创作都有自己的趣味。
- 镜头数、动作轮廓数与字幕组数按情节和阅读时长安排，不硬凑10–11镜或五种指定姿势。多种装扮展示是必拍经典镜头，通常为同一主体创作3–5款不同搭配；照片没有衣服也必须设计，款式、配色、数量和文字样式不固定。为阵列揭示留5–7秒，全部亮相后稳定至少3秒供双语标签阅读。
- 字幕可以对俏皮镜头中的表现作幽默点评或拟作功能介绍；它表达观众能理解的结果与反差，不复述具体动作的生成步骤。动作包袱可先留白，结果稳定后再出中文及对应英文，避免字幕遮住互动或提前讲破笑点。

## 模板内容

参考[猫咪发布会分镜帖](https://www.xiaohongshu.com/explore/6aabd1d1000000001200375f)的完整信息结构，以及[iCat发布会成片](https://xhslink.cn/o/3WvYnjqYEqc)的特征标题、渐变强调、多款搭配与结尾回扣。前者是七页图文帖，后者是约15秒横幅视频。

- **多图 r2v 参考**：逐张读图，明确主身份、补充角度/细节、姿态、造型或场景等用途。按当前模型上限选用所需图片，它们的 exact AssetVersion 同时进入分镜和视频参考链，不能默认忽略第二张图；不同主体的外观不能混合。分镜只提供构图/动作参考，不设置 first frame，不先播放原照背景，不以无身份图参考的文生图替换主体身份。音频不进入图片参考数组。
- **用户音频优先**：有上传音频时以用户音频作 BGM，用其 exact `source_asset_version_id` 创建 `creation.type=audio`、`role=bgm` 的元素，`script` 留空、`gain_db=0`，沿用现有混音器的音乐床增益。调用 `r2v_generation` 时传 `generateAudio=false`（这是工具参数，不是 `creation` 字段），不再生成另一首配乐。多条音频以用户指定为先，未指定时按素材理解和时长选择合适的一条；音乐过长按成片时长截取，过短复用同一版本接续并用短交叠淡化处理接点，不添加运行时不支持的音频字段。保留用户音乐本身的风格和人声，不用器乐要求替换它。
- **无音频时模型配乐**：默认一个30秒多镜头 R2V 单元，显式设置 视频生成工具参数 `generateAudio=true`，在同一个 `creation.video_prompt` 写入声音设计。模型直接生成贯穿全片的原创器乐配乐：轻快、明亮、干净，清透合成器或拨弦音色、温暖低音与克制鼓点；开场简洁、主体稳定推进、小情节或关键揭示适度抬升、片尾自然收束，切镜不重新起乐。少量同步轻音效融入配乐，无歌词、人声或旁白。此分支只使用模型原生音轨，不另建 BGM、TTS 或音效 Element，不要求用户额外上传音乐。模型须支持所需时长、图片参考和本分支的原生音频；能力不足时明确报告，不静默拆段或降级声音方案。
- **单次完整生成的声音说明**：片内按本次情节设计的多个镜头由同一个 R2V Element、同一次模型调用生成，共用一条连续原生音轨。镜头切换不等于多个独立视频的音轨拼接，因此不会遇到逐段生成配乐在衔接处跳变的问题。模板在开场规则、转场规则和声音设计中明确这一前提，要求从 `creation.narrative` 到首次 `creation.video_prompt` 保留音乐说明。用户没有上传音频时，不能将配乐改成只有摄影棚底噪、爪垫或布料声；“无对白、无歌词”也不等于无音乐。这一说明仅用于本模板，不改写 Agent 基础 prompt 或 skill。
- **首次提示词核对**：请求视频生成前回读实际保存的 `creation.video_prompt`，检查完整配乐、曲风/乐器、随镜头推进和片尾收束、切镜不断乐均已写入；只有 `generateAudio=true` 或计划中提到配乐不算完成。有上传音频时则检查真实 BGM 引用、`generateAudio=false`，以及视频提示词没有要求另一首音乐。
- **专属叙事**：优先读出至少三项真实可见特征，证据不足时按实际记录；结合本次体态、配件、道具和用户描述创作主题与小情节，安排亮相、趣味演示和片尾回扣。镜头数和顺序随情节调整，不推断品种、年龄或看不清的身体特征，也不把创意表演说成照片证实的日常习惯。
- **真正的动作变化**：每镜写清主体与道具的初态、触发、动作、结果和反应。位移、姿态转换和互动自然形成变化，不以凑齐固定轮廓数为目标；关键接触与结果应清楚可见，不把换机位、换衣服或静止推近算成新表演。分镜必须体现本次互动状态和道具关系，不能仍是一排坐姿。
- **拍摄指令与观众文案分开**：每镜计划在 `Timeline.description` 内分列 `production_notes`、`audience_brief` 与 `screen_copy`，不新增运行时字段。动作过程、姿态、机位、角度、秒数和留白只进入分镜/视频生成提示词；先把本镜的可见特征、事件结果或反差提炼成 `audience_brief`，再独立写字幕；`Overlay.creation.text` 与 HTML 只使用独立创作并审稿的 `screen_copy`。不能把“前腿伸长，胸口降低”翻译后当字幕，但可从已发生的小事件提炼幽默功能梗。中文通过后再译英文，副句没有新信息就省略，不为凑版式塞入导演说明。真实的造型数量、颜色和款式标签照常保留。
- **完整双语**：中文主文案与准确英文逐组对应，包括说明、颜色和造型标签。英文不使用固定口号。每个 Overlay 的 `creation.text` 和 HTML 可见文字按相同 DOM 顺序保存。
- **词组与译文校对**：主副句均限4–10个汉字，长句在完整词组之间主动换行；英文采用均衡换行。先整理本片照片确认的中英术语，防止把“加白”等毛色信息拆开或漏译，不将示例里的特征套给其他主体。
- **模板内排版**：片头侧边标题、细节强调、特征与观感卖点、造型总标题与逐款标签、片尾双层文案可以组合。文档流和等宽 Grid 是易于保持间距的起点，也允许按实片独立设计花字、关键词分层、逐字错峰与弹性缩放；通过完整动画过程检查中英文和相邻标签的间距，稳定期保持完整可读。
- **全屏叠字与主体避让**：原视频始终铺满画布，透明字幕直接覆盖片内留白。逐镜核对主体、关键互动道具、接触点及动作范围，调整整组位置、文案长度与出现时段；空间不足时分时呈现或修正生成构图，不能缩小视频、添加外栏或大面积底板来避让。缺少实片证据时标记待验收，不宣称完成主体检测。
- **造型标签**：生成阶段要求全部造型揭示后固定机位，真实展示的每款造型都有对应中英标签，标签在稳定阅读期出现；具体数量随本片设计，不固定五套。实际横移或逐款揭示时，按真实时段延迟标签；没有时段与位置证据时使用画内留白中的紧凑造型列表，不把静态标签错误对应到移动主体。

## 字幕文件与渲染契约

本模板开放自定义字幕与花字，也保留五种可选预设。模型按本次主体、实片与文案选择字体层级、位置和动画；预设只是起点，不是样式白名单，不要求每片凑齐或轮换。默认让中文主标题和重点词采用清楚可见的彩色渐变、珠光或金属材质，结合字重与字号层级形成现代感；英文和辅助标签可用干净纯色。按语义选择逐字错峰、关键词弹性、字形流光、细描边转实心、轻微倾斜回正等动效，也可自由创造新的表达，不把全片做成黑字淡入或每句同一种扫光。配色从主体、服装和背景重新提炼；浅背景用有深度的饱和彩字，流光经过时字形仍清晰。用户指定的风格优先。

- 自定义：`creation.text` 保存完整双语，`creation.prompt` 描述本镜的花字意图，由工具结合实片自动设计。也可提供已有透明 `html_css` 或可确定性 seek 的 `html_js` 文档；无须版本标记或 `recipe`，没有字幕槽位或内部类名白名单。缺少设计时先调用设计工具，再合成。
- 预设：仅在主动选择预设时用 `creation.prompt` 的 `template=informal_launch` 加 `recipe` 或 `mode=preset` 选择 `recipe`、`layout`、颜色与可选的文字区百分比。造型列表可用 `header_delay`、`label_delay`、`label_stagger`；这些槽位只属于预设实现，不限制自定义设计。

调用 `design_motion_overlays` 时，已写好的文档会经过完整文案和实际渲染检查；保留原设计，只修复可确定的 CSS 换行转义。自动和手动合成也保留这份文档，失败报错而不替换成预设或基础字幕。预览与成片均不对本模板注入通用字幕的强制字号、缩放、描边等覆盖，`title/text/caption` 类名可正常使用。通用字幕默认行为保持原样。

字幕需要退场时使用已有的 `data-motion-exit="soft_fade"` 或 `"shrink"` 协议；CSS/GSAP 动画自身保持完整可见的末态，由预览和导出统一完成片段末尾的退场。不能再写一套末尾透明度归零的动画，否则会被空帧校验拒绝，或与渲染器退场叠加。

`caption-styles.json` 是 `template.json` 的 `design_floor_body` 中「字幕设计约束」后的 JSON 可读副本，两份须保持一致。`document_template`、`region_template` 和 `group_template` 是预设实现及创作参考，可以复用、改造，也可以不用。HTML 只作一次 JSON 编码，读回后 CSS 使用真实换行；`html_css` 不包含脚本，`html_js` 使用现有的本地 GSAP 与确定性 seek 协议，不请求外部资源，不伪造 `html_file_id`。

横版通常用透明全画布 Overlay，文字在文档内布局，原片始终全屏。竖版按实际尺寸重新设计透明文字带；不把横版直接缩进狭窄字幕框。`overlay_layouts` 是构图参考，不是强制位置或主体检测结果；文字位置、时段、字号与对比度必须核对实际画面。

后期采用整批启用顺序：先把全部字幕和必要的全屏 Edit 作为未启用草稿写齐，再一次启用完整后期，之后请求最终合成。使用 Edit 时停用原 r2v；只叠字时保留原 r2v，保持一条全屏视频底层。现有成片记录或“复用成功”不能替代逐镜文字核对；较早的中间成片可能尚未包含后来增加的字幕。

有上传音频时，直接调用 `r2v_generation` 可传 `generateAudio=false`。自动链路或复用原片带有声音时，本模板在预览与最终合成中用已启用的真实 BGM 替代视频原声；这由模板集成处理，无须 Agent 填写未支持的原声字段或为了静音另建 Edit。没有上传音频时，R2V 保持 `generateAudio=true`，使用 Edit 明确设置 `original_sound=preserve`，字幕叠加和最终合成保留模型原声。内置模板更新只影响随后应用模板的项目；已创建项目保存自己的模板与生成提示词。要改变既有成片的模型原生配乐，需把声音要求应用到该项目的 R2V 提示词并按现有制作授权重新生成，单纯更新模板文件或重新叠字合成不会产生新配乐。

## 验证与边界

验收必须看实际 MP4，而不是只看提示词、分镜图、任务成功或缩略图：逐镜检查身份与动作、中文及对应英文、所有造型标签、主体遮挡、碰撞、字号、裁字及音轨。合成出现“回退”“安全动效模板”“文案不一致”等警告时，先修正该字幕设计再导出。模板自身不新增主体检测或视频观察工具，也不能让现有工具接受其不支持的 ArtifactVersion 引用；缺少真实审阅证据时必须明确记录待验收，不宣称自动验证通过。

排版检查覆盖入场中间帧、稳定期、末帧及较小预览视口，并核对 Creator 预览与最终合成的一致性。除了画布边界与主体关键部位避让，还要检查中英文、主副组、相邻标签的字形边界两两相交，以及每个区域实际内容高度；不能把“字都在画布里”当成没有重叠。超预算先改短文案或重新安排信息，不用裁字、省略号或微小字号掩盖。

文字审稿需逐组判断是在向观众传达特征、事件结果或幽默反差，还是在指导模型执行动作；制作指令即使中英文齐全、字号与边界正常，也不能通过验收。对本次画面结果的幽默点评可以保留，不能重新收紧成只准写严肃的外观形容词。检查不能仅靠禁词或禁止数字，合法的颜色、款式与造型数量应保留。

声音验收按分支进行：上传音频分支核对所选真实音频引用，最终 MP4 确实播放用户音乐且没有第二条原配乐；模型配乐分支试听原始 R2V 和最终 MP4，确认连续轻快配乐与同步轻音效。两者均试听开头、中段、关键揭示和结尾的音量、衔接与自然收束；有音轨不等于合格。声音制作说明不进入字幕。模型配乐未生成时记录失败并修订原生提示词，不用后贴音频冒充模型原声。

验收还要确认视频四边由原片覆盖，没有小框、外栏或底衬；文字直接叠在画面中。生成模型可能偏离构图和时序，因此实际成片的可用留白与信息对应关系需要验收。手工校准既有素材的排版样片，只能证明模板渲染效果；一键流程必须以新项目、原照和短提示词独立验证。

`cover.jpg` 取自已生成的猫咪发布会视频，作为可分发的风格封面；此目录不包含用户原始照片、上传音频、其他测试媒体、项目运行数据或模型凭据。

### 自动花字设计

默认在 `Overlay.creation.prompt` 描述本镜的字体、情绪与入场意图即可。`design_motion_overlays` 读取内置 `informal-launch-captions/SKILL.md` 的正文，结合所选 R2V/剪辑视频在对应时段的真实帧、准确文案与全片上下文生成独立透明字幕，支持任意合适的花字排版。不是先手写 HTML 才能离开预设。已有文档保留；只有显式指定 `recipe` 或 `mode=preset` 才使用可选预设。缺实片、设计或渲染失败会明确报错，不自动用基础字幕代替。

技能通过 Creator 已有的目录自动发现机制对主 Agent 可见，可用 `view_skill` 阅读；字幕设计工具自动加载同一文件，无须再调用一个 specialist。技能描述限定于“非正式发布会”，不改变其他模板的基础字幕风格。
