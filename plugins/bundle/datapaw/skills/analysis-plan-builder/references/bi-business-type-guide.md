# 业务类型与子类型判定指引

本文档供 analysis-plan-builder 在 Step 2.1 使用，用于判定用户分析任务涉及的业务类型。

## 判定步骤

### 1. 判定业务类型（ToB / ToC / ToD / Mixed）

根据产品名、上下文、关键词综合判断。若查询涉及不熟悉的产品或平台，通过网络搜索查询其官网或行业介绍，获取产品定位、目标用户、商业模式等信息辅助判断。

**ToB**：

- 客户类型：企业/付费企业，决策链长，重 ROI
- 价值主张：降本增效、业务赋能、合规安全
- 典型场景：SaaS 服务、企业工具、云基础设施、模型推理服务

**ToC**：

- 客户类型：个人用户付费或免费使用，决策链短，重体验
- 价值主张：解决需求、情感满足、社交归属
- 典型场景：内容平台、社交应用、工具类 App、电商平台

**ToD**：

- 客户类型：开发者、创作者、模型提供者、开源贡献者等内容/能力生产者
- 价值主张：影响力构建、技术成长、作品传播、生态协作、潜在变现、社区互动活跃度/开发者间协作能力
- 典型场景：GitHub、魔搭（ModelScope）、Hugging Face、开源中国、知识创作者平台
- 核心特征：
  - 供给方具有双重身份：内容生产者 + 社区参与者
  - 核心驱动力：成就感/影响力 > 直接经济回报
  - 网络效应强：优质供给吸引消费者，消费者反馈激励供给方持续贡献
  - 长周期培养：供给成长需要时间投入、技能积累、作品沉淀

**Mixed 判定**：当业务同时具备多种类型特征时输出 Mixed。常见模式：

| 模式      | 典型案例                   | 分析重点                                    |
| --------- | -------------------------- | ------------------------------------------- |
| ToB + ToD | 云服务 + 开发者生态        | ToB 看收入成本，ToD 看开发者活跃与供给质量  |
| ToC + ToD | 电商 + 商家、内容 + 创作者 | 双边网络效应、供需平衡、飞轮验证            |
| ToB + ToC | 企业微信、钉钉             | ToC 体验驱动 adoption，ToB 变现驱动 revenue |
| 三边      | 美团、滴滴                 | 三边协同、资源分配、优先级动态调整          |

处理规则：
1. 识别主要业务类型，以权重最高的两个为主干
2. 追加跨模块联动分析（如 ToD 供给质量 → ToC 体验 → ToB 收入）

分析优先级原则：
1. **阶段优先**：早期优先规模（ToC/ToD），中期优先变现（ToB），后期优先均衡
2. **瓶颈优先**：识别当前业务最大瓶颈（供给不足？需求不够？变现困难？）
3. **联动优先**：优先分析跨模块联动指标

### 2. 判定业务子类型

ToB 默认「产品类」，ToD 默认「开发者社区」。ToC 根据以下特征区分 4 个子类型。若产品特征不确定或跨界，通过 WebSearch 查询其核心功能和变现模式辅助判断。

**工具类**：

- 核心价值是“用完即走”的功能效率，用户为工具能力付费或免费使用
- 无显著内容消费、社交互动、交易链路或游戏玩法
- 关注指标：DAU/MAU、功能渗透率、使用时长、留存
- 典型产品：通义千问、天气 App、扫描工具、记账 App

**内容社区类**：

- 核心价值是内容消费或社交互动，用户时间花在“看/读/聊/互动”上
- 存在内容供给侧（创作者、UGC）和消费侧的双边结构
- 关注指标：内容供给量、消费深度、互动率、创作者分层
- 典型产品：抹音、小红书、B站、微博、豆瓣

**电商交易类**：

- 核心价值是商品交易，存在明确的“浏览→加购→下单→支付”转化链路
- 核心驱动是 GMV，关注交易规模和转化效率
- 关注指标：GMV、转化率、客单价、复购率、售后率
- 典型产品：淘宝、京东、拼多多、美团外卖

**游戏类**：

- 核心价值是游戏体验，存在关卡/副本/赛季等游戏内玩法结构
- 付费模式为内购/抽卡/战令等，付费率和 ARPPU 是核心变现指标
- 关注指标：新增、留存、付费率、ARPPU、LTV、关卡进度
- 典型产品：原神、王者荣耀、和平精英

---

## 判定优先级

1. 用户显式指定业务类型 → 直接采用
2. 产品名明确且已知 → 按已知信息判定
3. 产品名不确定 → 通过搜索获取信息后判定
4. 无产品信息（如纯数据集分析）→ 跳过业务类型判定
