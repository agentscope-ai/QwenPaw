# 钉钉 Channel 插件化：第一版体验与测试

## 这一版做了什么

钉钉的收发实现已从宿主 `app/channels/dingtalk` 移到独立插件。宿主通过现有 PluginLoader/PluginApi 加载它，ChannelManager 按工作区创建连接。配置标识仍是 `dingtalk`，不是 `dingding`。

第一次启动新版，程序会将随发行包附带的钉钉插件复制到当前 `QWENPAW_WORKING_DIR/plugins/dingtalk`。这个迁移只发生一次，不联网、不修改 agent.json、凭据、ACL、媒体、聊天记录或钉钉会话映射。已有同 ID 插件，包括 `.disabled` 副本，不会被覆盖。主动卸载后，下次启动不会把它偷偷装回来。

钉钉配置模型、扫码入口和原表单暂留宿主，防止用户升级后重新填写设置。未启用时，插件只注册加载入口，不导入钉钉 SDK。SDK 缺失时显示未安装/加载失败提示并保留配置，启动不自动安装依赖。

**这是兼容优先的插件化试点，不是完整依赖减重版本。** 钉钉 SDK 仍在默认依赖和 Desktop 打包中，让原来启用钉钉的用户升级后继续工作。后续再把 SDK 移入可选安装，同时补完整发行与老用户依赖迁移。

## 先体验已有设置的兼容性

1. 在 `la/dev/channel` 分支，用原来启动 dev 项目的方式重启应用。保持原 `QWENPAW_WORKING_DIR`，不要换成一个空目录，也不要重跑初始化。
2. 在插件管理中，应能看到 **DingTalk，ID=dingtalk，1.0.0**。
3. 在原工作区打开渠道页面，钉钉表单出现“钉钉渠道插件”提示；之前的启用状态、Client ID/Secret、卡片配置等应保留。卡片属于插件渠道，筛选“内置”时不会显示它。
4. 从钉钉给原机器人发一条消息，检查回复。再检查已有会话、群聊、流式卡片和媒体发送。
5. 切到另一个工作区，确认它不会自动继承第一个工作区的凭据或启用状态。

源码运行可参考（端口沿用你的原设置）：

```bash
# 仓库根目录；必须沿用你原来的 QWENPAW_WORKING_DIR
.venv/bin/qwenpaw app --host 127.0.0.1 --port 8088
```

前端已在本地构建；其他机器拉取分支后需要先在 `console/` 执行 `npm run build:prod`。

## 体验停用、卸载与恢复

1. 在所有启用了钉钉的工作区关闭钉钉，然后重启 QwenPaw。不要让机器人正在回答时做这个测试。
2. 在插件管理中卸载 DingTalk。若本次进程创建过钉钉实例，会拒绝卸载/覆盖并提示先停用、重启。这是第一版明确保留的限制，用来避免旧连接或在途回复仍引用已删除代码。
3. 返回渠道页面：钉钉仍然可见，旧凭据保留，显示插件不可用。此时不能重新开启，但可以读取设置或保持停用。
4. 再次启动应用，确认不会自动重新安装已卸载的插件。
5. 在插件管理里“从本地路径安装”，选择仓库中的 `src/qwenpaw/bundled_plugins/channel/dingtalk`；或者用 CLI：

```bash
.venv/bin/qwenpaw plugin install src/qwenpaw/bundled_plugins/channel/dingtalk
```

6. 重新打开渠道页面，启用钉钉，再做一次收发测试。原配置和会话标识应继续可用。

日常启用/关闭仍沿用现有工作区 reload 机制；这版不承诺零中断热切换，也未实现按渠道排空所有在途任务。更新/卸载使用上述重启保护。插件代码和版本在宿主共享，凭据和连接按工作区管理。

## 打包成独立插件 ZIP

```bash
.venv/bin/python scripts/pack/generate_plugin_metadata.py \
  --plugins-root plugins --dist /tmp/qwenpaw-channel-package --only dingtalk
```

产物为 `/tmp/qwenpaw-channel-package/channel/dingtalk/dingtalk-1.0.0.zip`，可在插件管理里上传安装。

插件源码随 wheel 和 Desktop 发布，供首次兼容迁移；正常运行加载的是用户插件目录中的副本。后续升级独立插件，使用插件安装流程；不会每次启动都拿宿主附带版本覆盖用户安装版本。

## 回归与限制

- 自动化覆盖：一次性迁移、旧设置保留、两个工作区启用不同、缺包配置可读、禁用后可恢复、卸载后不自动复活、禁止覆盖已使用插件、未启用不导入 SDK。
- 钉钉原有单元与契约测试继续跑；真实 SDK 对接本地模拟钉钉/模型的 7 项端到端收发测试通过。
- 前端测试覆盖插件来源下原扫码/凭据/卡片表单和缺包提示；独立 ZIP 与干净 wheel 均检查包内文件。
- 尚需真人机器人测试：真实钉钉账号、卡片权限、扫码授权与真实网络断线恢复。未使用个人凭据替用户发送任何消息。
- Desktop 修改了清单，但未构建或运行 macOS/Windows 安装包；默认依赖减重、完整单渠道热切换属于后续工作。
- CLI 的旧配置向导仍可使用；通用 CLI 完整 class registry 仍可能加载其它渠道 SDK，本次惰性加载验收覆盖应用启动和渠道列表。
