# 聊天页面恢复焦点刷新优化验收报告

日期：2026-09-02

## 1. 问题

用户从其他应用切回浏览器时，聊天页面会出现一次类似整页刷新的闪动。

聊天页监听 `visibilitychange`、`focus` 和 `pageshow` 后执行会话同步。第一次修复只关闭了“后端处于 `idle` 就递增 `refreshKey`”的错误重建条件，但仍然会在每次恢复焦点时无条件请求完整会话列表和聊天历史。因此即使用户没有创建消息，恢复浏览器时仍会启动一次不必要的完整会话同步，验收标准不完整。

## 2. 修复

第二次修复增加了恢复同步入口门控：只有页面隐藏前或恢复时确实存在运行中的任务，才允许读取会话列表和历史；普通空闲会话恢复焦点时直接返回，不发起 `/api/chats` 请求。

进入恢复同步后，仅在以下情况重建聊天组件：

- 后端消息数大于当前前端消息数；
- 前端仍显示运行中，但后端已经变为 `idle`。

前后端都处于空闲且消息数量一致时不执行重建。长命令在后台完成后的恢复能力保留。

## 3. 自动化验证

- 恢复同步入口和刷新判定测试：7 项通过；
- 聊天缓存相关回归合计：10 项通过；
- TypeScript 编译：通过；
- Vite 生产构建：通过；
- Monaco CSS 完整性检查：通过。

构建仍输出项目原有的动态/静态导入与大分包警告，本次没有新增构建错误。

## 4. 真实浏览器验证

使用管理员账号登录 `http://127.0.0.1:18089`，打开已有历史消息的空闲聊天会话，记录网络请求并触发窗口 `focus` 与页面 `visibilitychange`。

结果：

- 焦点恢复前后 URL 相同；
- `/api/chats` 请求数为 `0`；
- 原主内容区和输入框节点保持不变，输入框仍为 `isConnected=true`；
- 空闲会话没有执行恢复同步或卸载重建。

## 5. 未包含范围

多用户访问令牌到期后的静默刷新属于独立问题，本次不修改认证刷新策略。
