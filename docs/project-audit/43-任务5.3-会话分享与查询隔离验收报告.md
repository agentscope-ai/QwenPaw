# Task 5.3 会话分享与查询隔离验收报告

## 1. 验收结论

Task 5.3-A 至 Task 5.3-E 已形成完整闭环：会话列表和详情以 PostgreSQL 权限事实为准，分享用户只能查看完整历史，所有写入口由前后端共同限制；所有者撤销分享后，查看者已打开的页面会在轮询周期内立即失效，不保留可继续操作的缓存副本。

本报告覆盖 Task 5.3-E 的撤销即时失效、综合回归和双用户可视化验收。Task 5.4 的实时 SSE 权限推送和 Task 5.5 的全量 PostgreSQL 历史回放不在本任务范围内。

## 2. 实现内容

### 2.1 已打开共享会话的权限复核

- 仅当当前会话角色为 `viewer` 时，每 3 秒直接读取一次会话详情。
- 所有者会话不会产生额外权限轮询。
- `Chat not found`、`conversation not found` 或 `not_found` 被识别为授权已经失效。
- 普通网络故障不会误判为撤销，避免短暂断网导致页面被错误清空。

### 2.2 撤销后的客户端清理

- 清除转换后的会话缓存、短期结果缓存和当前会话请求引用。
- 从会话列表和共享 Zustand 状态中移除失效会话。
- 清空已渲染消息和 Token/上下文快照。
- 清理会话队列、工作区和文件页关联状态。
- 重置窗口会话身份并跳转到 `/chat`。
- 向用户显示“该共享会话的访问权限已撤销，页面已清除失效内容”。

### 2.3 PostgreSQL 权限回归

- 集成测试新增断言：所有者移除查看者后，查看者无法继续按 ID 读取会话，并且 `shared` 列表不再返回该会话。
- 更新旧隔离测试桩，使其验证 `list_accessible_chats` 和 `conversation_repository`，不再依赖多用户模式下已退出的文件型事实源。

## 4. 双用户可视化验收

验收实例：`http://127.0.0.1:18089`

验收步骤与结果：

1. 管理员打开已有的“友好问候”会话。
2. 管理员通过“分享会话（仅查看）”授权给普通用户 `task42-user`。
3. 普通用户登录后自动打开该会话，页面显示完整历史。
4. 普通用户输入框显示“只读分享：无法发送消息或修改会话”，发送、语音和新建按钮均不可用。
5. 管理员点击“移除”撤销查看权限。
6. 普通用户页面在一个轮询周期内从 `/chat/94b78717-4434-4abb-abbc-85055d00ec7e` 自动跳转至 `/chat`。
7. 页面旧消息被清空，并显示撤销提示；未留下可编辑缓存副本。
8. 临时分享授权已撤销，原会话及所有者历史未删除。

## 5. 原功能无侵入核对

- 所有者仍可正常查看原会话和富消息历史。
- 本次只对 `viewer` 已打开页面增加访问复核，不改变所有者发送、停止、审批、模型、项目目录或工具执行路径。
- 权限结果仍由后端 PostgreSQL 仓储决定，前端只负责只读呈现和失效清理。
- 未修改数据库结构，未删除会话，未改变模型或 Agent 配置。
