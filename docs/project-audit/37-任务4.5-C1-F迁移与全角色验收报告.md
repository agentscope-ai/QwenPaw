# Task 4.5-C/1-F 旧记忆迁移与全角色验收报告

## 1. 结论

已完成旧 Agent 记忆向“公共记忆”语义的非破坏性登记迁移，并完成 Task 4.5-C/1 全角色回归。迁移不移动、不删除、不改写原 Markdown；管理员仍拥有普通用户能力，但显式代管只能维护公共记忆，不能访问任何用户的私有记忆。

本任务已升级验收数据库 Schema 至 Alembic `0008_agent_user_workspaces`。数据库升级在用户明确确认后执行，原有用户与 Agent 数量保持不变。

## 2. 迁移设计与结果

- 启动时扫描现有 Agent workspace 的 `MEMORY.md`、`memory/daily`、`memory/digest` Markdown 和受支持的旧索引元数据。
- 在 `WORKING_DIR/migrations/memory_scope_public.json` 登记公共作用域、相对路径、SHA-256、文件大小和索引状态。
- 不在迁移清单中写入 Secret、正文内容或用户私有物理路径。
- 仅在首次登记或文件哈希发生变化时标记 ReMe `needs_reindex`。
- 使用原子替换写入清单；重复运行不会重复登记或反复修改 Agent 配置。
- 验收环境共登记 5 个已有 Agent、5 个 `MEMORY.md`；再次运行的 `changed=false`，第二次内部运行同样幂等。

## 3. 数据边界

| 数据 | 存储位置 | 边界 |
|---|---|---|
| Agent 公共 Markdown | 原 Agent workspace 文件 | 保持原路径和原内容，由 owner/collaborator 或显式治理管理员维护 |
| 用户私有记忆元数据 | PostgreSQL `agent_user_workspaces` | `(user_id, agent_id, scope)` 隔离，只保存逻辑工作区键和索引状态 |
| 用户私有 Markdown/索引 | 用户逻辑工作区 | API 永不接收任意用户 ID，服务端从登录身份解析 |
| 迁移清单 | `WORKING_DIR/migrations/memory_scope_public.json` | 只登记相对路径、哈希和状态，不复制正文 |
| Agent 删除后的私有工作区 | PostgreSQL 状态 | 先标记 `cleanup_pending`，不在删除请求内同步递归删除目录 |

真实验收后，数据库仅存在管理员和普通用户各自针对 `default` Agent 的两条私有工作区记录，逻辑键分别归属于各自用户；没有跨用户复用记录。

## 6. 非侵入性说明

- 未修改聊天消息、工具执行过程、模型切换、Agent 对话协议或原文件内容。
- 未把记忆正文整体搬入 PostgreSQL；数据库只保存适合事务查询的归属和状态。
- 未删除历史 Markdown、旧索引、用户、Agent 或模型数据。
- 管理员通过普通路径仍按实际使用角色工作；只有显式治理入口增加公共记忆维护权。
- 单用户模式继续使用公共工作区语义，不强制创建用户私有工作区。

## 7. 验收步骤

1. 管理员选择自己的 Agent，进入“文件 → 日记”，确认有“公共记忆 / 我的记忆”。
2. 在“智能体管理 → 全部智能体”对他人 Agent 点击“代管公共记忆”，确认只出现公共记忆。
3. 普通用户选择平台公用 Agent，确认公共记忆不能保存或重建；切换“我的记忆”后可保存和重建。
4. 分别用两个用户访问同一 Agent，确认各自私有记忆互不可见。
5. 重启服务两次，确认旧公共 Markdown 内容、数量和路径不变，迁移清单不产生重复记录。
