# 模型供应商配置与模型使用专项分析

## 1. 结论

原项目的模型能力实际包含三种性质不同的入口：

1. **供应商与模型治理**：配置 API Key、Base URL、协议类、请求头、模型目录、本地运行时和全局默认模型。
2. **Agent 默认模型配置**：在 Agent 创建/编辑页为该 Agent 选择默认模型。
3. **对话运行时选择**：普通用户在聊天页右上角从管理员授权的模型中切换当前使用模型。

单用户版本不仅把三者放在同一认证边界内，而且 Agent 创建/编辑页和聊天页最终都会写同一个 `agent.json.active_model`。多用户版本必须拆开：供应商、密钥、模型目录、本地模型和全局默认模型只允许管理员管理；普通用户可以在创建/编辑自己的 Agent 时设置默认模型，也可以在普通对话中切换授权模型；共享应用的模型由创建/编辑配置锁定，普通使用者不能在对话页切换。

## 2. “模型”设置页原有功能

### 页面结构

模型设置页分为云端和本地两个标签，并将供应商划分为已配置和可配置区域。页面支持搜索、供应商分组、变体展示和全局默认模型提示。

主要操作包括：

- 配置内置云模型供应商。
- 新增、重命名和删除自定义供应商。
- 配置 API Key、Base URL、聊天模型协议类、生成参数、自定义请求头和认证模式。
- 测试供应商连接。
- 自动发现远端模型。
- 新增、编辑、测试和删除供应商下的额外模型。
- 配置模型上下文长度、输出长度、生成参数、思考模式、思考预算、推理强度和 reasoning 转发。
- 探测或维护多模态能力。
- 处理部分供应商的 OAuth 授权流程。
- 设置部署实例的全局默认模型。
- 管理内嵌本地模型运行时及下载模型。

这些全部属于部署级管理能力，在已确认的多用户目标中只能由管理员访问。

## 3. 供应商与模型数据

`ProviderManager` 将供应商状态保存在：

```text
~/.qwenpaw/secret/providers/
  builtin/
  custom/
  plugin/
  active_model.json
```

核心数据包括：

- 供应商 ID、名称、类型、默认地址和实际 Base URL。
- API Key、认证模式和自定义请求头。
- ChatModel 协议实现。
- 内置模型与用户添加的额外模型。
- 供应商级生成参数和模型级覆盖参数。
- 模型能力、上下文长度、多模态和推理配置。
- 全局激活的 `provider_id + model`。

API Key 等敏感字段在落盘前通过主密钥加密，文件权限被限制；读取旧版明文配置时会尝试原地迁移为加密格式。返回供应商信息时通常通过 `mock_secret=True` 对 API Key 脱敏。

脱敏不等于可向普通用户公开。供应商响应仍包含管理元数据、地址、模型配置、认证类型和“是否已配置”等信息，多用户版本应提供独立的用户模型目录 DTO，而不是复用管理员供应商响应。

## 4. 供应商管理 API 原有能力

后端 `/models` 路由包含：

- 列出全部供应商。
- 修改供应商配置。
- 创建和删除自定义供应商。
- 测试供应商或单个模型连接。
- 发现远端模型。
- 新增、编辑和删除额外模型。
- 发起、轮询或完成 OAuth 流程。
- 读取和设置全局或 Agent 级激活模型。

当前这些接口只经过原项目的单账户认证，没有角色判断。前端隐藏菜单不足以满足目标权限，所有写接口以及包含管理信息的读接口都必须在服务端要求管理员角色。

供应商连接测试和模型发现允许请求体临时提交 API Key、Base URL 和请求头，这些也是管理员专属能力，并且不得写入普通审计文本或错误日志。

## 5. 本地模型原有功能

本地标签以 `llama.cpp` 为运行时，提供完整生命周期管理：

- 检查当前平台是否支持安装，以及运行时是否已安装。
- 检查更新、下载或更新 `llama.cpp`、查看进度和取消下载。
- 查看推荐模型与已下载模型。
- 从指定来源下载模型、查看进度和取消下载。
- 删除未运行的本地模型；运行中的模型禁止删除。
- 启动指定模型的本地服务，并选择端口。
- 停止本地服务。
- 设置最大上下文长度、固定端口和生成参数。

本地服务启动后，后端会更新 `qwenpaw-local` 供应商的 Base URL 和模型列表，并立即把该模型设为全局激活模型。停止服务或更新过程中停止服务时，会清空该供应商的运行状态和全局激活引用。

本地模型下载、删除和启动会消耗磁盘、网络、CPU/GPU 和端口资源，属于部署基础设施管理，必须仅管理员可操作。普通用户只能在服务运行且模型被授权时使用它，不能看到主机路径、设备枚举、下载源或端口管理入口。

## 6. 全局模型、Agent 模型与生效顺序

### 持久化层级

- 全局模型保存在 `providers/active_model.json`。
- Agent 模型保存在对应 `agent.json` 的 `active_model`。

读取接口支持：

- `scope=global`：只读取全局模型。
- `scope=agent`：只读取指定 Agent 自己保存的模型。
- `scope=effective`：优先 Agent 模型，没有时回退全局模型。

模型工厂实际创建实例时也遵循相同主干规则：

1. 请求级 `model_slot_override` 最高优先。
2. 读取当前 Agent 的 `active_model`。
3. Agent 未配置时使用全局激活模型。
4. 解析供应商并创建对应 ChatModel 和 formatter。

请求级覆盖能力必须纳入授权，否则普通用户可能绕过前端选择器，直接指定未授权供应商或模型。

### 写入行为

设置全局模型时，`ProviderManager` 更新全局激活记录；如果当前活动 Agent 没有自己的模型，接口还会把该模型写入当前 Agent 并触发热重载。

设置 Agent 模型时，接口校验供应商和模型存在，直接写入目标 Agent 的 `active_model`，然后异步热重载该 Agent，并触发多模态探测。

源码表明，Agent 创建/编辑表单和聊天页右上角目前没有独立的数据层级：

- 创建/编辑表单提交 `active_model`，写入 Agent 配置。
- 聊天页 `ModelSelector` 调用同一个 `/models/active` 写接口，使用 `scope=agent`，同样改写 Agent 配置并触发热重载。

所以当前“对话中切换模型”实质上是修改 Agent 的持久化默认模型。这个单用户行为不能原样搬到多用户系统，否则一个共享应用的普通使用者切换模型会影响所有使用者。

这里存在一个重要语义：一旦全局模型被写入 Agent，之后修改全局默认模型并不会自动改变这个已经具有独立 `active_model` 的 Agent。目标方案需要明确区分：

- `inherit_global`：Agent 始终使用管理员当前默认模型。
- `explicit`：Agent 保存一个管理员授权范围内的明确模型。

不应继续通过“是否为空”隐式表达继承，否则管理员变更默认模型、撤销模型授权或删除供应商时难以判断影响范围。

目标模型解析至少需要区分以下层级：

1. 管理员维护的部署级模型目录和全局兜底模型。
2. Agent 创建/编辑时保存的 `default_model`。
3. 非共享 Agent 当前对话中的用户运行时选择；选择绑定当前会话，新建对话重新使用 Agent 默认模型。
4. 合法的内部请求级覆盖。

共享应用必须跳过第 3 层，始终使用创建/编辑时保存的 `default_model`。普通用户自己的 Agent 可以保留对话页切换能力，但选择只写入当前会话，不修改 Agent 默认模型；新建对话重新使用 `default_model`。

## 7. 聊天页模型选择原有交互

原生 QwenPaw Agent 的聊天页显示 `ModelSelector`。它会：

- 拉取供应商列表。
- 读取当前 Agent 的有效模型。
- 过滤看起来已经配置且包含模型的供应商。
- 显示模型及部分能力信息。
- 用户选择后调用 `PUT /models/active`，以 `scope=agent` 和当前 `agent_id` 写入 Agent 配置。
- 某些供应商需要 OAuth 时，可能从选择器触发授权确认流程。

Harness Agent 使用独立的 `HarnessModelSelector`，由后端能力决定可选模型，不完全复用 QwenPaw 供应商体系。

这与 Agent 创建/编辑页存在明确区别：

- 智能体管理表格中的模型列展示 Agent 配置模型；目标版本应将其定义并标识为“默认模型”。
- 创建/编辑页的模型字段设置 Agent 的默认模型，属于 Agent 配置。
- 对话页右上角定义用户在对话中的模型选择，属于使用交互。
- 模型设置页定义系统有哪些供应商和模型可用，属于管理员治理。

目标多用户版本中，普通用户在非共享 Agent 对话里仍可切换模型，但只能：

- 获取管理员发布且自己有权使用的模型目录。
- 切换自己当前对话所使用的模型，选择仅绑定当前会话；不能借此修改 Agent 默认模型、供应商或系统模型配置。
- 选择不暴露密钥、Base URL、请求头、协议类和供应商管理状态的模型条目。
- 在模型被停用、撤权或本地服务下线时得到明确的不可用提示和回退策略。

普通用户的选择器不得发起供应商 OAuth，不得跳转模型设置页，也不得通过“连接未配置”提示暴露管理员配置细节。

对于共享应用，聊天页模型选择器应改为只读展示或直接隐藏切换入口。其模型只能通过共享 Agent 创建/编辑页设置；普通使用者不能切换。即使用户本人在其他个人 Agent 对话中拥有模型切换能力，也不能把这项能力带入共享应用。

| 操作 | 普通用户 | Agent 协作者/所有者 | 管理员 |
|---|---|---|---|
| 进入左侧“模型”设置菜单 | 禁止 | 禁止 | 允许 |
| 查看供应商管理信息 | 禁止 | 禁止 | 允许 |
| 配置 API Key/Base URL/请求头/OAuth | 禁止 | 禁止 | 允许 |
| 创建、修改、删除供应商 | 禁止 | 禁止 | 允许 |
| 发现、测试、增加、修改、删除模型 | 禁止 | 禁止 | 允许 |
| 管理本地运行时和模型文件 | 禁止 | 禁止 | 允许 |
| 设置全局默认模型 | 禁止 | 禁止 | 允许 |
| 查看授权后的可用模型目录 | 允许 | 允许 | 允许 |
| 创建/编辑自己的 Agent 默认模型 | 允许，限授权目录 | 允许，限有配置权的 Agent | 允许 |

菜单可见性只是交互优化；每个后端接口都必须独立执行角色和资源权限校验。

## 9. 目标数据与服务边界

建议将模型域拆成以下职责：

- `ProviderAdminService`：供应商、密钥、OAuth、连接测试和发现，仅管理员。
- `ModelCatalogService`：管理员维护模型目录、启停状态、展示名称、能力和可用范围。
- `ModelEntitlementService`：判断用户、角色或 Agent 是否可使用某个模型。
- `AgentDefaultModelService`：维护 Agent 创建/编辑时的默认模型，并校验 Agent 配置权限与模型授权。
- `ConversationModelSelectionService`：将非共享 Agent 的用户选择绑定当前会话；新会话回到 Agent 默认模型，遇到共享应用时强制返回其默认模型。
- `SecretStore`：保存 API Key、OAuth token 和敏感请求头；业务表只保存引用。
- `LocalModelRuntimeService`：管理下载、磁盘、进程、端口和健康状态，仅管理员。

PostgreSQL 适合保存供应商非敏感元数据、模型目录、授权策略、Agent 选择、状态和审计记录。密钥应保留在专用加密存储中，不能以可逆明文直接进入普通业务表、日志或前端响应。

模型目录和 Agent 默认模型之间必须建立可查询的引用关系：

- 管理员删除供应商或模型前，系统列出全部受影响 Agent 和共享应用。
- 只要仍有 Agent 默认模型引用，普通删除操作必须被阻止。
- 管理员需要先批量或逐个替换这些 Agent 的默认模型，之后才能删除。
- 紧急停用允许立即阻止模型调用，但受影响 Agent 应进入明确的“模型不可用”状态。
- 模型不可用时禁止静默回退到全局模型或其他模型，避免成本、能力、安全策略和输出行为在用户不知情时变化。
- 恢复模型或重新配置默认模型后，系统再恢复 Agent 对话能力，并记录完整审计日志。

## 10. 当前实现的迁移风险

- 供应商列表接口过宽，不能直接给普通用户复用。
- Agent 选择接口目前只校验 Agent 存在/启用，未校验登录用户对 Agent 的权限。
- 请求级模型覆盖可能绕开前端目录限制。
- 新 Agent 会复制全局模型，导致默认模型变更无法自然传播。
- 删除或停用供应商/模型后，已有 Agent 可能保留失效的 `active_model` 引用；目标版本必须通过引用检查和显式不可用状态消除此风险。
- 启动本地模型会直接修改全局激活模型，管理员操作可能影响全体 Agent。
- 管理接口错误信息、连接测试和 OAuth 状态可能泄露供应商配置细节。
- 当前对话选择器会直接改写 `agent.active_model`；共享应用中会造成一个普通使用者影响所有用户。

共享应用的规则已经明确：创建/编辑页配置的模型是共享默认模型，普通使用者不能切换。有配置权的协作者、所有者和管理员也应从 Agent 编辑入口修改，而不是在对话页产生不透明的配置变化。个人/非共享 Agent 仍保留原有右上角模型切换体验。

## 11. 必须保留的原功能与回归用例

- 管理员可以配置内置和自定义供应商、密钥、地址、请求头及协议类。
- 管理员可以测试连接、发现模型并管理额外模型与模型参数。
- 密钥落盘保持加密和权限保护，API 响应与日志不泄露明文。
- 管理员可以安装/更新本地运行时、下载/删除模型、启动/停止服务和配置运行参数。
- 普通用户看不到模型设置菜单，直接调用管理 API 返回权限错误。
- 普通用户的聊天选择器只展示管理员授权且当前可用的模型。
- 普通用户可以在自己的非共享 Agent 对话中切换授权模型。
- 普通用户创建/编辑自己的 Agent 时可以设置授权范围内的默认模型。
- 共享应用对话页不能切换模型，只能使用创建/编辑时配置的默认模型。
- 用户不能通过篡改 `agent_id` 将对话选择写入共享应用或他人 Agent。
- 未授权的请求级模型覆盖被后端拒绝。
- Agent 创建/编辑页修改默认模型后只热重载目标 Agent。
- 对话页切换模型只影响当前用户的当前对话，不改变 Agent 默认模型、共享应用或其他用户；新建对话重新使用 Agent 默认模型。
- 全局继承和显式选择语义清晰，管理员改变默认模型时行为可预测。
- 模型删除前必须列出受影响 Agent 并阻止删除，直到管理员完成默认模型替换。
- 紧急停用模型后，受影响 Agent 明确不可对话，不静默切换到全局模型或其他模型。
- 共享应用的任何对话使用者都不能通过右上角选择器改变默认模型；变更必须走有权限的 Agent 编辑入口。
- 所有供应商、密钥、目录、授权和模型切换管理操作写入审计日志。
