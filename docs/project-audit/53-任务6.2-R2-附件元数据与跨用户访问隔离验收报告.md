# Task 6.2-R/2 附件元数据与跨用户访问隔离验收报告

日期：2026-09-02  
验收环境：`http://127.0.0.1:18089`，多用户模式，PostgreSQL Schema `qwenpaw_task21_acceptance`

## 1. 实现结果

附件不再以磁盘绝对路径作为浏览器访问凭证：

- 上传时生成独立附件 ID，并持久化所有者、Agent、原始文件名、存储位置、类型、大小和内容哈希；
- 附件允许先处于待发送状态，发送后绑定实际会话和用户消息 ID；
- 同一附件不能跨用户、跨 Agent、跨会话或跨消息重复绑定；
- 前端保存和展示 `/api/console/attachments/{attachment_id}`，不再返回用户运行空间绝对路径；
- 受保护预览 URL 自动附加当前登录令牌，兼容 `<img>` 和普通下载链接无法设置 Bearer Header 的场景；
- 下载接口按当前登录用户查询附件，未拥有该附件统一返回 404；
- 历史消息中的已登记本地附件路径会转换为受保护 URL；只读会话查看者不会得到其他用户的本地路径；
- Legacy 单用户模式继续沿用原上传返回形式，避免侵入原功能。

实现复用统一 Conversation Repository，在 JSON 与 PostgreSQL 两个适配器中保持同一附件契约；授权判断集中在后端，不依赖前端隐藏，符合 DRY、SOLID 和最小权限原则。

## 2. 数据库变更

新增迁移：`0011_attachment_scope`。

- `attachments.agent_id`：非空，关联 `agents.id`；
- `attachments.original_name`：非空；
- `attachments.conversation_id`：改为可空，支持“上传后、发送前”的待绑定状态；
- 新增所有者、Agent、创建时间组合索引；
- 附件 RLS 改为严格的所有者 SELECT/INSERT/UPDATE/DELETE；
- 旧数据通过所属会话回填 Agent，并从 `storage_key` 回填原文件名。

真实旧数据回填测试先升级到 `0010`、写入旧结构附件，再升级到 `0011`，确认附件保留且 Agent、原文件名回填正确。

验收 Schema 已从 `0010_runtime_workspace_grants` 升级到 `0011_attachment_scope`。升级前附件表为 0 行，没有删除或覆盖会话、消息或附件数据。

## 4. 用户验收步骤

1. 使用普通用户 A 登录 `http://127.0.0.1:18089`，选择公用或仅使用 Agent。
2. 在对话输入区上传图片或文档，确认预览正常；浏览器地址不应显示本地磁盘绝对路径。
3. 发送消息并刷新页面，确认附件仍可预览或下载。
4. 使用普通用户 B 登录；即使复制用户 A 的 `/api/console/attachments/{id}` 地址，也应返回 404。
5. 使用用户 A 重新访问该地址，应正常下载原文件名的附件。
6. 可在文件页面确认附件物理文件仍位于当前用户的个人运行空间 `media` 目录。
