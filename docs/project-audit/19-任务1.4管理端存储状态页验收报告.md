# Task 1.4 管理端存储状态页验收报告

## 1. 任务结论

Task 1.4 已完成实现与技术验收，当前停在阶段 1 用户确认门，未进入 Task 2.1。

本任务只增加脱敏、只读的存储状态展示，没有执行数据库迁移、表结构变更、
业务数据写入、Repository 切换或运行服务重启。

## 2. 后端实现

新增独立路由：

```text
GET /api/system/storage-status
```

响应字段：

| 字段 | 含义 |
|---|---|
| `status` | `legacy`、`disconnected` 或 `ready` |
| `connected` | PostgreSQL 连通性 |
| `schema_version` | 当前 Alembic revision；Legacy/断连时为 `null` |
| `expected_schema_version` | 当前代码期望的 revision |
| `schema_ready` | 当前与期望 revision 是否一致 |
| `storage_mode` | 配置的存储模式 |
| `active_repository` | 正式业务当前实际使用的 Repository |
| `migration_lock_state` | `not_applicable`、`not_configured` 或 `unknown` |
| `error_code` | 脱敏后的稳定错误码 |

响应模型没有 DSN、密码、Secret、`DATABASE_URL` 或数据库连接目标字段。

### 状态语义

- Legacy：不访问 PostgreSQL，不读取迁移版本，迁移锁为 `not_applicable`。
- PostgreSQL 断连：不继续读取 Schema，迁移锁为 `unknown`。
- PostgreSQL 连通：只读查询 Alembic revision；当前阶段迁移锁执行器尚未实现，
  如实返回 `not_configured`。
- 当前正式业务 Repository 仍固定显示为 `legacy`，避免把配置模式误当作已经切换。

## 3. 前端实现

新增设置入口“系统状态”和路由：

```text
/system-status
```

页面包含：

- 当前存储总览；
- 数据库连通性；
- 当前业务 Repository 与配置模式；
- 当前/期望 Schema 版本；
- 迁移锁状态；
- 脱敏、只读安全说明；
- 加载、错误、重试和刷新状态。

页面唯一业务操作是“刷新”。不存在迁移、重建、DROP、删除或切换存储按钮。

## 4. 权限边界

该页面位于管理设置区域，但阶段 2 的身份登录与管理员 capability 尚未实施。
因此 Task 1.4 只注册管理入口，尚未声称已经具备服务端管理员鉴权。

后续必须在统一 Principal 与 capability 层完成以下门禁：

- 管理员可访问状态页与状态 API；
- 普通用户不可访问管理状态 API；
- 前端菜单隐藏只能作为体验优化，服务端授权仍是最终边界。
