## 3. 实现范围

### 3.1 后端身份闭环

- PostgreSQL 用户、Argon2id 密码凭据、个人偏好和登录会话。
- 登录、会话恢复、刷新、单设备退出、全设备撤销和禁用用户拒绝登录。
- `/api/me` 返回当前数据库用户，语言和时区按用户保存。
- Multi-user 的 `/api/auth/verify` 基于当前数据库会话；Legacy 模式仍保留原认证逻辑。

### 3.2 前端认证闭环

- 登录页支持管理员和普通用户登录，刷新页面可恢复会话。
- 侧边栏账户区显示用户名和角色，提供个人偏好、登录设备、全设备撤销和退出。
- 访问令牌只保留在运行内存，刷新凭据使用 HttpOnly/SameSite Cookie；`localStorage` 不保存访问令牌、刷新令牌或密码。
- 账户变更、退出和 401 会清理用户级 Agent、聊天草稿、消息队列、最近 Agent 和审批级别缓存。

## 4. API 与会话证据

| 核验项 | 结果 |
|---|---|
| 匿名访问 `/api/me` | `401` |
| 管理员登录 | `200`，返回 `admin` 角色 |
| 普通用户登录 | `200`，返回 `member` 角色 |
| 禁用普通用户后登录 | `401`；恢复 active 后再次登录为 `200` |
| 管理员单设备退出 | 管理员会话失效，普通用户会话仍为 `200` |
| 普通用户全设备撤销 | 普通用户返回登录页，管理员会话不受影响 |
| Multi-user `/api/auth/verify` | 返回当前数据库用户 |
| Legacy `/api/auth/status` | 仍为 `enabled: false`，无 Multi-user 模式注入 |

## 5. PostgreSQL 脱敏证据

- Schema 已迁移至 `0004_identity_sessions`。
- 验收用户角色/状态为 `admin/admin/active` 和 `member/member/active`。
- 密码列只核验到 `$argon2id` 前缀，未输出完整哈希。
- 访问/刷新会话指纹长度均为 64，数据库不保存可直接使用的原始令牌。
- 两名用户的偏好分别为 `zh-CN / Asia/Shanghai` 和 `en / UTC`。

## 8. 当前边界与非目标

1. 普通用户当前仍能进入“模型设置”等管理菜单。这是 Task 2.1 建立身份后暴露出的明确授权缺口，必须由阶段 3 的 ActorContext、后端授权和前端菜单可见性同时关闭。
2. 当前两名用户仍可看到验收实例复制的共享 Legacy 业务数据。用户资源所有权和工作空间隔离不在 Task 2.1 范围内。
3. 验收实例未携带原模型密钥，因此需要模型供应商的记忆运行状态接口可能返回 `503`。这是验收环境的 Secret 隔离结果，不是原功能路由缺失。
4. ACP 路由仅做原功能回归保真，按已确认产品方向不在后续多用户平台中开启。

## 9. 用户验收步骤

1. 在两个独立浏览器或无痕窗口打开 `http://127.0.0.1:18089`，分别使用管理员和普通用户登录。
2. 确认侧边栏显示不同用户名/角色，刷新后仍保持正确会话。
3. 打开账户菜单，分别修改语言/时区，确认互不影响；查看登录设备。
4. 让普通用户执行“撤销全部设备”，确认普通用户回到登录页而管理员仍保持登录。
5. 分别打开聊天、Agent、技能、技能池、MCP、频道、模型和其他原菜单，确认页面、对话丰富事件和原交互仍存在。
6. 此时普通用户能看到模型设置是已归档的阶段 3 待修复项，不应误判为最终权限设计已完成。
