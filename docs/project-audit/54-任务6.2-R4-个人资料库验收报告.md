# 任务 6.2-R/4：个人资料库验收报告

更新时间：2026-09-04

## 实现边界

- 文件正文保存于 `WORKING_DIR/user_libraries/{user_id}/`，路径为英文、用户隔离的 POSIX 相对路径。
- PostgreSQL 迁移 `0013_user_personal_library` 仅保存文件元数据和 Agent 授权记录：
  `user_library_documents`、`user_library_agent_grants`；两表均启用基于 `owner_user_id` 的 RLS。
- 临时附件、个人运行空间文件和 `artifacts/` 产物只能显式复制进入资料库；源文件、附件生命周期及原路径均不改变。
- 授权是“用户 → Agent”的整库只读授权。管理员没有其他用户个人资料库的默认查看或授权权限。
- Agent 仅在用户授权当前 Agent 后获得 `personal_library_search` 与 `personal_library_read`；两项工具每次调用重新核验授权，撤销立即生效。

- 迁移契约测试：现有适配环境下通过；未配置 PostgreSQL 的 3 个集成测试按原项目条件跳过。
- 前端资料库与附件复制交互测试通过，TypeScript 类型检查通过。
- 验收服务已重启并验证 `GET /api/auth/status` 返回 `mode=multi_user`。

## 未伪造的验证结论

本次环境中浏览器自动化启动失败，尚未取得双用户真实浏览器证据。因此 R/4 尚不应标记为最终验收完成。需要用户在界面上执行以下最终检查：

1. 两个普通用户分别以相同路径新建资料，确认互不可见；
2. 两人授权同一个公用 Agent，各自只可检索自己的唯一关键词；
3. 撤销用户 A 的授权后，A 被拒绝而 B 保持可用；
4. 将附件和 `artifacts/` 产物复制到资料库，确认源文件仍在；
5. 管理员登录确认没有其他用户资料库入口；
6. 刷新、重新登录和切换 Agent 后重复确认归属及授权仍保持。
