# 维护协调与剩余缺陷修复报告

日期：2026-09-09。依据第 56 号报告继续修复；保留原工作区变更，未提交、未建分支、未恢复现有业务数据或修改系统权限。

## 修复结果

### 1. 备份与恢复统一维护协调

新增 `platform_ops/maintenance.py`，同一工作目录下使用两个 OS 文件锁：准入锁和数据共享／独占锁。Windows 使用 LockFileEx，POSIX 使用 flock。

- 普通操作持共享租约，正常请求仍可并发。
- 维护先关闭新操作准入，等在途操作完成后取得独占租约；超时拒绝操作，不静默继续。
- 租约根目录为 `WORKING_DIR/.maintenance`，不在正文恢复交换目录中。进程退出由操作系统释放锁。
- 同任务可重入；独立子任务持自己的共享锁，父任务退出不会提前释放子任务的保护。维护内部仅当前任务可重入，不能让普通后台任务继承独占权限。
- 修复异步生成器在另一任务关闭时 ContextVar.reset 抛错而遗漏关闭文件锁的问题。

接入范围：

| 入口 | 租约边界 |
|---|---|
| HTTP ASGI 中间件 | 覆盖请求、响应正文和清理；取消后等待持租约工作结束；繁忙返回 503 和 Retry-After |
| 长期只读 SSE | 不让订阅本身阻挡维护；资源初始化及数据库访问另有租约 |
| 数据库 | 覆盖事务 begin 至 commit／rollback，不只保护 SQL 发起阶段 |
| Agent／工具 | Workspace stream、独立工具执行、后台收尾、Agent 初始化／停止／重载 |
| 会话 | TaskTracker producer、断线后的持久化、后台 Console、会话分叉／标题收尾 |
| 自动化 | Cron 执行和历史写入、服务回调、Heartbeat、检查点定时器 |
| 频道 | 普通消费、微信／飞书／企微／元宝入队前写入、微信扫码后 Token 保存、Matrix 单轮同步和加密存储维护 |

监听入口在维护期间等待并保留当前消息；只在取得准入前重试，不重放已执行的业务副作用。永久监听循环不永久占有租约。

### 2. 备份／恢复生命周期

- `create_platform_stream` 在同一独占租约内完成文件压缩和数据库导出，成功后才发送 done。
- 客户端断开不会提前释放尚未完成的压缩／快照工作。测试覆盖断开后新写入仍不能进入。
- 恢复的保护备份、数据库、正文、失败回滚均在同一独占租约内。
- 停止及重新加载 Agent 在独占区之外执行，避免生命周期子任务等待自身独占锁；原有编排锁仍覆盖整个恢复与重启流程。
- 快照清单在真实独占范围内记录 `cross_store_consistency=coordinated_maintenance`；低层独立采集仍标记 sequential，不伪造一致性标签。

一致性保证针对使用同一工作目录并遵守维护门的应用操作和进程。任意外部编辑器、直接操作数据库的管理工具或绕过平台接口的第三方代码不受此门控制；维护期间这些外部写入仍应停止。这是协作式应用维护边界，不是文件系统或 PostgreSQL 的全局强制写保护。

### 3. 不完整旧备份

新增 `validate_platform_restore`：多用户恢复全局数据库前校验数据库清单及四类平台正文前缀，HTTP 入口和取得独占后的恢复编排均执行校验。

旧归档缺少正文时返回 `platform_backup_incomplete_recreate_backup`，避免全库已经回退而正文被静默跳过。关闭全局数据库恢复时仍保留原文件范围恢复。旧文件未被删除或改写，丢失的正文不会凭空重建；需从当前完整数据生成新备份。

### 4. Windows 符号链接权限

- CLI 创建临时 overlay 仅在 WinError 1314 时回退为临时复制，保留外部技能／提示的读取能力，临时修改不会污染源目录。其他 I/O 错误仍抛出。
- 两个必须创建真实符号链接的扫描测试在缺少权限时明确跳过；新增不依赖操作系统权限的链接排除和哈希不变测试。没有放宽生产扫描规则或修改 Windows 权限。

### 5. WeChat 退出清理

- 停止后拒绝晚到消息及 Token 文件写入。
- 即使 enabled 已关闭，stop 仍清理已存在的线程。
- 异步等待线程结束；超时保留线程引用并显式失败，避免误报停止完成。
- 测试 fixture 使用独立 Token 目录、完整 await stop，并使客户端 Mock 覆盖线程整个生命周期。
