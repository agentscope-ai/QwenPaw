# Task 4.2-B：用户个人频道绑定验收报告

## 1. 结论与确认门

Task 4.2-B 已完成实现和本地验收，当前等待用户确认。管理员与普通用户都可以在自己可使用的 Agent 上建立、修改、启停和删除个人频道绑定；管理员仍同时拥有普通用户能力。个人绑定不改写 Agent 原有频道文件配置，也不会把 Secret 明文返回前端。

本报告只覆盖个人频道绑定，不包含 Task 4.2-C“撤销公用后历史只读”。

## 2. 数据模型与迁移

- Alembic 版本升级为 `0006_user_channel_bindings`。
- `channel_bindings` 新增非空 `owner_user_id`，历史数据从 `created_by` 回填。
- 唯一约束由 `(agent_id, channel_type)` 调整为 `(agent_id, owner_user_id, channel_type)`。
- 同一 Agent、同一频道类型可以由不同用户分别绑定；同一用户仍保持每种类型一个绑定。
- Secret 存入 `credential_records.encrypted_value`，普通 `config` JSON 不保存 Secret。

验收 Schema `qwenpaw_task21_acceptance` 已核验：版本为 `0006_user_channel_bindings`，`owner_user_id` 非空，唯一约束为 `uq_channel_bindings_agent_owner_type`。

## 3. 权限与 API

新增 API：

- `GET /api/agents/{agentId}/channel-bindings`
- `PUT /api/agents/{agentId}/channel-bindings/{channel_type}`
- `DELETE /api/agents/{agentId}/channel-bindings/{channel_type}`
- `POST /api/agents/{agentId}/channel-bindings/{channel_type}/conflict-check`

权限规则：

- owner、collaborator、user 只要对 Agent 具有当前有效使用权，都可维护自己的绑定。
- 服务端只使用认证 Actor 的用户 UUID，客户端不能指定或冒充 `owner_user_id`。
- 列表只返回当前用户的记录；管理员不会因为平台角色而读取或覆盖其他用户的个人绑定。
- Secret 字段返回 `configured_secret_fields` 提示，不回传明文；空 Secret 表示保留已有值。

## 4. 运行时隔离

- 每个个人绑定以 `binding_id` 建立独立 `ChannelManager`，不复用或覆盖 Agent 原有 manager。
- 外部频道发送者被映射为绑定所有者的平台 UUID，同时在 `channel_meta.external_user_id` 中保留外部身份。
- 更新绑定时先停止旧监听器，再启动新监听器；启动失败会清理半启动 manager。
- 停用和删除均停止对应监听器；应用关闭时统一回收个人绑定运行时。

真实实例已执行 Console 个人绑定的“启用 → 停用 → 删除”生命周期，日志确认监听器启动、队列清理和 ChannelManager 停止。

## 5. 前端交互

- 频道页新增“智能体频道 / 我的频道绑定”视图。
- owner、collaborator 可以在两个视图之间切换；只具有使用权的 user 直接进入个人绑定视图。
- 管理员访问他人公用 Agent 时同样以普通使用者身份维护自己的个人绑定。
- Drawer 支持保存和删除个人绑定，并显示已安全配置的 Secret 字段名，Secret 输入框保持为空。
- 修复了视图/Agent 快速切换时旧请求覆盖新请求的竞态，过期响应不再覆盖当前个人绑定状态。

## 9. 工程原则

- **KISS：** 个人绑定沿用现有频道类型和表单，只增加独立视图与存储边界。
- **DRY：** Secret 分区、Agent 访问校验和运行时重建集中在单一服务中。
- **SOLID：** Repository 负责持久化，Service 负责权限，Runtime Registry 负责监听器生命周期，页面 Hook 负责视图数据。
- **YAGNI：** 本阶段不引入组织、频道共享组或多实例同类型频道模型。

## 10. 用户验收步骤

1. 在两个独立浏览器上下文打开 `http://127.0.0.1:18089`，分别登录管理员与普通用户。
2. 两边都切换到 `Task 4.1 普通用户智能体`，进入“频道 → 我的频道绑定”。
3. 打开 Telegram：管理员应看到前缀 `task-4-2-b-admin-task21`，普通用户应看到 `task-4-2-b-task42-user`。
4. 两边都应看到 Bot Token 已安全配置提示，但输入框不显示原值。
5. 修改各自 Bot Prefix 并保存，刷新后应只影响当前账号。
6. 可新增一个测试频道绑定，执行启用、停用、删除；不应改变“智能体频道”中的原配置。

用户确认本报告后，才进入 Task 4.2-C。
