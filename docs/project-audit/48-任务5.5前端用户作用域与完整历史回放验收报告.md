# Task 5.5 前端用户作用域与完整历史回放验收报告

## 1. 验收结论

Task 5.5 已完成实现和自动化验证，当前等待用户进行阶段 5 确认。

本任务没有新建简化版消息页面，历史会话仍通过原有 `HostBubbles` 和 ToolCards 展示 Thinking、文件读取、Skill、浏览器及其他工具执行过程。

## 2. 实现范围

### 2.1 用户作用域前端状态

- Agent 选择、最近使用 Agent、消息队列、输入草稿、审批级别和 Harness 审批偏好均按 `user_id` 分区。
- 请求头只读取当前登录用户命名空间内的 Agent 选择。
- 消息队列广播携带用户身份，其他用户的浏览器消息不会被当前用户消费。
- 登录用户切换或退出时，清空当前用户的会话 API 缓存、会话列表、后台任务和运行时身份；不会删除其他用户的独立命名空间。
- 兼容未启用多用户时的旧存储键，避免侵入 Legacy 运行方式。

### 2.2 完整历史回放

- 修复历史响应节点重复 React key，避免相同类型、相同 ID 的工具事件在回放时丢失或重复。
- 保留现有丰富事件适配器和 ToolCards，不改变工具过程消息的数据结构和 UI 语义。
- 刷新与重连继续使用原有事件流和快速回放机制。

### 2.3 停止与身份切换

- 停止生成时先将前端临时会话 ID 解析为真实数据库会话 ID，再调用停止接口。
- 同一 Agent 的身份重置也会推进会话缓存代次，防止切用户后复用前一用户的同名 Agent 缓存。
- 切换 Agent 后重新加载该 Agent 自己的会话与工具历史，不沿用上一 Agent 状态。

- 从默认 Agent 切换到用户自有 Agent 后，默认 Agent 的历史标记立即消失。
- 页面加载并保存用户自有 Agent 的选择。
- 强制刷新后仍处于同一 Agent、同一会话，工具执行过程完整保留。

### 4.3 同一浏览器切用户

- 普通用户退出后，仅保留与身份无关的桌面提示键；用户身份、Agent 选择和最近使用 Agent 键全部移除。
- 在同一浏览器登录管理员后，只创建管理员自己的用户作用域 Agent 存储。
- 管理员恢复默认 Agent 和管理员治理菜单，没有出现普通用户的账号标记、历史标记或 Agent 选择。

- 未改造或替换原有 ToolCards 展示体系。

- 未修改模型供应商、Agent 配置、Memory、MCP 或文件工作区业务语义。
- 用户作用域逻辑集中在存储键、身份重置和请求上下文边界，避免在各页面重复实现隔离判断。

1. 使用普通用户打开一条含 Thinking、文件读取和工具执行的历史会话。
