# Task 6.1：WorkspaceResolver 验收报告

## 1. 验收结论

Task 6.1 已完成。平台新增统一的 `WorkspaceResolver`，工作区不再由调用方直接拼接任意路径，而是从已授权的资源 ID、用户 ID 和已登记的 Legacy 映射解析路径。

本任务只建立路径解析、安全边界、兼容适配和可视化元数据，不改变现有文件页业务能力，也未执行数据库结构或数据变更。普通用户个人运行空间的全面接入属于下一项 Task 6.2。

## 2. 工作区类型

| 类型 | 输入资源 | 解析结果 | 权限语义 |
| --- | --- | --- | --- |
| Agent 草稿 | `agent_id` | `WORKING_DIR/workspaces/{agent_id}` | 可写，后续由 Agent 授权层决定使用者 |
| 发布基线 | `publication_id` | `WORKING_DIR/published_workspaces/{publication_id}` | 只读，不允许解析器自动创建缺失基线 |
| 用户运行空间 | `user_id + agent_id` | `WORKING_DIR/user_workspaces/{user_id}/{agent_id}` | 当前用户独立可写 |
| 已登记旧目录 | `resource_id` | 管理端登记映射中的精确路径 | 保持原 Agent 工作区兼容 |

## 3. 授权/拒绝路径矩阵

### 允许

| 场景 | 示例 | 结果 |
| --- | --- | --- |
| 草稿逻辑键与资源 ID 一致 | `workspaces/agent-a` | 解析为 Agent 草稿 |
| 发布基线逻辑键与发布 ID 一致 | `published_workspaces/publication-a` | 解析为只读发布基线 |
| 当前用户运行键一致 | `user_workspaces/{当前用户}/agent-a` | 解析为当前用户运行空间 |
| Legacy 路径存在登记映射 | `legacy-agent -> E:/.../agent` | 精确解析为已登记旧目录 |

### 拒绝

| 场景 | 示例 | 拒绝原因 |
| --- | --- | --- |
| 绝对逻辑路径 | `/tmp/agent-a`、`C:/tmp/agent-a` | 调用方不能直接指定物理路径 |
| 上级目录穿越 | `workspaces/../agent-a` | 禁止 `..` 逃逸 |
| 非法资源 ID | `../agent-a` | 资源 ID 不符合安全格式 |
| 跨用户逻辑键 | 用户 A 请求 `user_workspaces/{用户B}/agent-a` | 逻辑键与当前用户不一致 |
| 托管目录符号链接 | `workspaces/agent-a -> outside` | 禁止符号链接逃逸 |
| Legacy 符号链接 | 已登记路径或其上级包含符号链接 | 禁止借登记映射绕过边界 |
| 未登记 Legacy 路径 | 任意本地绝对路径 | 仅允许登记映射 |
| 缺失发布基线 | 发布基线目录不存在 | 只读基线不能被运行时隐式创建 |
