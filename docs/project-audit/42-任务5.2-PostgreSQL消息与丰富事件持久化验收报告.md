## 实现范围

- `PostgresChatRunPersistence` 包裹 `TaskTracker.attach_or_start()` 实际消费的后台事件源，浏览器断线不会停止落库。
- 每个 Run 使用 UUID，事件按 Run 内 `sequence` 单调递增；非 UUID 的 wire ID 使用稳定 UUIDv5 映射，同时保留原始 wire JSON。
- 每帧在一个事务内写入 `run_events`，并按事件类型写入或更新 `messages`、`tool_calls`、`approval_requests`、`attachments`。
- `final`、`error`、取消和异常分别收敛为 completed、failed、cancelled；原始 SSE 字符串原样返回。
- 超过 64 KiB 的事件正文写入 Agent workspace 的 `.qwenpaw/chat-event-payloads`，数据库和消息内容仅保存引用、大小及 SHA-256。
- Console 前台新 Run 和后台任务入口均接入；重连只订阅既有 TaskTracker，不重复创建 PostgreSQL Run。
