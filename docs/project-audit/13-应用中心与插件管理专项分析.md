# 应用中心与插件管理专项分析

## 1. 分析范围与结论

本专项核验以下内容：

- 应用中心的已安装应用、官方应用、应用市场、搜索、分类、打开、刷新和卸载。
- 插件管理的已安装、官方、市场、URL/ZIP 安装、强制重装、热加载、卸载和状态查看。
- PawApp 与普通插件的真实关系。
- 插件可扩展的后端、前端、Agent、模型、频道和运行时能力。
- 多用户改造后的安装治理、使用授权、数据隔离和存储边界。

核心结论：PawApp 不是独立于插件系统的轻量页面。它是带 `meta.pawapp` 标记的 `app` 类型插件，安装在同一全局插件目录、使用同一插件加载器，并可注册后端路由、前端代码、Agent 工具、命令和生命周期 Hook。因此必须把“平台安装代码”和“用户使用应用”拆成两类权限。

## 2. 浏览器实况

2026-08-20 在当前运行中的 QwenPaw v2.1.0 核验：

### 2.1 应用中心 `/apps`

页面包含三个视图：

- 我的应用，并显示已安装数量。
- 官方应用。
- 应用市场。

没有已安装应用时提供“浏览官方应用”和“浏览应用市场”入口。官方应用页面提供搜索框。当前实例已安装应用数量为 0，因此无法在本实例实测具体 PawApp 的内嵌运行页面；内嵌打开、返回、刷新、关于和卸载行为由页面源码及现有前端测试补充确认。

### 2.2 插件管理 `/plugin-manager`

页面包含：

- 发布插件外链。
- 安装插件。
- 已安装插件、官方插件、插件市场三个标签。
- 本地 ZIP 拖放/选择安装。
- HTTP(S) URL 安装。
- 已安装插件列表和卸载操作。

当前实例没有已安装插件。安装弹窗已通过浏览器实际打开核验，但未执行安装等外部代码写入操作。

## 3. PawApp 与插件的实现关系

### 3.1 统一安装目录与加载器

PawApp 安装在 `get_plugins_dir()` 返回的全局插件目录中，与工具、模型供应商、频道和前端插件共用目录及 `PluginLoader`。后端通过插件 manifest 中的 `meta.pawapp` 识别并在应用中心展示。

应用市场和官方应用的安装最终也调用插件安装接口；市场安装会使用强制重装语义，因此可能替换现有版本并影响正在使用该插件的 Agent。

### 3.2 插件类型

原项目定义的插件类型包括：

- `tool`：注册一个或多个 Agent 工具。
- `provider`：注册模型供应商或模型端点。
- `hook`：执行启动、关闭等生命周期代码。
- `command`：注册斜杠控制命令。
- `channel`：注册自定义消息频道。
- `frontend`：加载前端 JavaScript。
- `app`：PawApp，可同时包含后端路由和应用页面。
- `general`：其他综合扩展。

插件能力不是简单的静态资源扩展，可能改变平台全局运行行为。

## 4. 安装、热加载和卸载链路

### 4.1 安装来源

后端支持：

- 本地目录路径。
- 远程 HTTP(S) ZIP。
- 浏览器上传 ZIP。
- 官方插件目录和插件市场下载地址。

安装过程包含 ZIP 路径穿越检查、manifest 解析、版本兼容检查、依赖安装、代码加载和后续集成。

### 4.2 实际代码执行

后端插件使用 Python 动态模块导入并执行入口文件。若插件包含 `requirements.txt`，加载器会调用 `pip` 或 `uv pip install` 安装依赖。前端插件源码会被下载后包装为 Blob URL，并通过动态 `import()` 在用户控制台页面中执行。

因此安装插件等价于允许第三方代码：

- 在后端进程中执行 Python。
- 修改 Python 运行依赖。
- 在登录用户浏览器上下文中执行前端 JavaScript。
- 注册平台 API、Agent 工具、模型供应商、频道、命令和 Hook。

### 4.3 对全部 Agent 的影响

工具型插件安装后会把工具配置项同步到所有现有 Agent，默认禁用；随后调度所有 Agent 重载。卸载时会清理该插件注册的运行能力、删除相关工具配置、删除插件文件并再次重载所有 Agent。

这证明插件安装、升级、强制重装和卸载是部署级变更，不是某个普通用户或单个 Agent 的私有操作。

### 4.4 卸载语义

应用中心和插件管理都提供卸载入口。卸载会物理删除插件目录，并可能移除工具、供应商、命令、前端路由和其他运行时注册。现有应用中心提示该操作不可撤销。

目标版本必须在卸载前展示引用影响，并优先采用“停用 + 可恢复隔离”流程；真正物理删除需要管理员明确确认并形成审计。

## 5. PawApp 运行能力

PawApp SDK 可以：

- 注册 HTTP 路由或整个 FastAPI Router。
- 注册 Agent 工具。
- 注册斜杠命令。
- 注册启动、关闭、安装和卸载 Hook。
- 调用 Agent 对话并接收流式事件。
- 读取会话历史。
- 调用已注册工具。
- 使用应用命名空间 KV 存储。
- 通过 SSE 向前端推送事件、Toast 和确认请求。
- 发起多频道通知接口。

应用页面可由前端插件注册路由后在应用中心内嵌呈现。当前前端插件在所有加载控制台的用户浏览器中执行，因此目标版本必须只下发该用户有权使用且平台已启用的前端插件清单。

## 6. 当前多用户阻断点

### 6.1 请求身份不可直接沿用

当前 `PawAppContext` 从请求查询参数或 Header 读取 `agent_id`、`channel` 和 `user_id`，缺省值为 `default`。在多用户环境中客户端可伪造这些值，不能作为授权依据。

目标实现必须：

1. 从认证中间件获得不可伪造的 `ActorContext`。
2. 将 URL/Header 中的 Agent ID 只视为资源选择参数。
3. 服务端验证当前主体是否有权使用该 Agent 和 PawApp。
4. 会话、存储、工具调用、审批和通知全部继承同一 ActorContext。

### 6.2 当前应用 KV 缺少用户隔离维度

当前应用存储主要按 `pawapp:<app_id>` 命名空间组织。多用户后至少需要明确：

- 平台级应用配置。
- Agent 级应用配置。
- 用户级应用数据。
- 用户在特定 Agent/共享应用版本下的运行数据。

不能继续依赖一个部署级 JSON 命名空间保存所有用户数据。

### 6.3 manifest 权限不是完整授权系统

应用信息和测试模型中存在 permissions 等元数据，但当前核心运行链路仍可直接注册路由、工具和 Hook。目标版本不能只展示权限文案，必须在安装审核、能力注册和每次调用三个阶段执行服务端授权。

### 6.4 前端插件是可信代码边界

前端插件脚本在控制台页面上下文中执行，可以访问宿主暴露的 SDK 和浏览器能力。安装来源、版本、哈希、签名/扫描状态和允许能力必须由管理员治理；不能允许普通用户上传任意前端插件。

## 7. 已确认权限方案

### 7.1 平台安装与治理

建议仅管理员可以：

- 打开插件管理页面。
- 从 URL、本地 ZIP、官方目录或市场安装插件/PawApp。
- 升级、强制重装、停用、启用和卸载。
- 审核插件声明的后端路由、前端脚本、工具、供应商、频道、命令、Hook、网络和文件能力。
- 配置插件的部署级 Secret 和系统设置。
- 查看全局插件错误、依赖安装日志和引用影响。

理由是这些操作会执行代码、安装依赖并影响全部 Agent。

### 7.2 普通用户使用应用

建议普通用户可以：

- 打开应用中心。
- 查看平台已安装、已启用并授权给自己的应用。
- 运行应用并保存自己的应用数据。
- 在应用中选择自己有权使用的 Agent。
- 对应用发起的高风险工具或外部副作用进行本人审批。

普通用户不能安装、升级、强制重装或卸载应用，也不能查看部署级 Secret、依赖日志或其他用户的应用数据。

管理员同时拥有上述普通用户使用能力，并拥有自己的应用数据和会话；管理员使用应用时默认仍以本人普通用户身份运行，不自动获得其他用户数据。

### 7.3 Agent 级配置

建议 Agent 所有者和协作者可以：

- 为有编辑权的 Agent 启用或停用管理员已安装且允许使用的插件工具、频道类型或 PawApp 能力。
- 配置 Agent 级非敏感参数和 Agent 级 Secret 引用。
- 查看该 Agent 使用的插件版本及平台停用状态。

但不能安装插件代码、改变插件全局版本、注册新供应商或降低平台安全策略。插件新增模型供应商仍由管理员进入模型设置完成配置；插件新增频道类型可由用户按已确认的频道绑定规则配置到自己的 Agent。

### 7.4 应用授权范围

第一版建议采用简单授权：

- `all_members`：所有平台用户可使用。
- `selected_users`：仅管理员选择的用户可使用。
- `disabled`：平台停用。

暂不建设复杂用户组、应用商店购买、计费和自定义角色，符合 YAGNI。

## 8. 推荐数据与文件落点

### PostgreSQL

- 插件 ID、版本、类型、来源、状态、内容哈希和兼容性。
- 安装、升级、停用和卸载状态及操作审计。
- 插件能力清单和审核结果。
- 应用授权范围。
- Agent 与插件能力的启用关系及非敏感配置。
- 用户应用 KV、小型结构化业务数据和任务状态。
- 插件引用、运行错误摘要和必要用量记录。

### 文件系统

- 插件 Python/JavaScript/静态资源。
- 插件隔离依赖目录。
- PawApp 大型内容、缓存和可移植资源。
- 安装 staging、回滚包和停用隔离目录。

### Secret Store

- 插件部署级密钥。
- Agent 级插件密钥。
- 应用调用外部服务使用的 Token。

### 内容存储

- 用户上传到应用的大附件、图片、音频、视频和生成结果。

## 9. 目标数据模型建议

```text
plugin_installations
  id, plugin_id, version, plugin_type, source_type, source_ref,
  content_hash, status, installed_by, installed_at, disabled_at?

plugin_capabilities
  plugin_installation_id, capability_type, capability_key,
  declared_config, review_status, reviewed_by?, reviewed_at?

app_grants
  plugin_installation_id, subject_type, subject_id?, enabled,
  granted_by, created_at

agent_plugin_settings
  agent_id, plugin_installation_id, enabled, config,
  credential_ref?, updated_by, updated_at

app_user_data
  plugin_installation_id, user_id, agent_id?, namespace,
  key, value, updated_at
```

插件代码和依赖不进入 PostgreSQL。`app_user_data` 只承载小型结构化数据；大型内容使用内容引用。

## 10. 功能保真验收

### 应用中心

- 我的应用、官方应用、应用市场、搜索和分类保持可用。
- 应用可内嵌打开、返回、刷新、显示关于信息和支持深链刷新。
- 普通用户只看到获准使用的应用。
- 用户切换后不残留上一用户的应用数据、活动应用、确认请求和会话。
- 管理员使用应用时具有独立私人数据，不默认进入管理代操作模式。

### 插件管理

- 管理员保留已安装、官方、市场、URL/ZIP 安装、升级、状态和卸载能力。
- 普通用户菜单不可见，直接 API 调用也必须拒绝。
- 安装失败不能留下半安装目录、半注册路由或失效依赖。
- 强制重装和卸载前展示受影响 Agent、工具、模型供应商、频道、应用和会话。
- 停用或卸载后，所有 Agent 热重载结果一致，不出现旧工具残留。
- 前端插件只向获授权用户加载，加载失败按插件隔离，不能阻断主控制台。

### 安全与隔离

- PawApp 不得通过伪造 `user_id`、`agent_id` 或 Header 越权。
- 应用存储以用户和必要的 Agent/发布版本隔离。
- 工具执行、审批和外部副作用记录实际操作用户。
- 插件异常、日志和审计不得泄露 Secret 或其他用户数据。

## 11. 本组确认结果

2026-08-20 用户已确认以下方案：

1. 插件/PawApp 的安装、升级、强制重装、全局停用和卸载仅管理员可执行。
2. 普通用户保留应用中心，可以使用管理员已安装、启用并授权的应用。
3. Agent 所有者/协作者可以配置管理员已安装能力在自己可编辑 Agent 中的启停和 Agent 级参数，但不能安装代码或改变全局版本。
4. 应用首期支持全体成员、指定用户和停用三种授权范围。
5. 管理员使用应用时与普通用户相同，拥有自己的应用数据；只有显式代操作才进入管理上下文。
