# 四类文件归属修复验收

日期：2026-09-15。范围来自用户确认的 [修复计划](../superpowers/plans/2026-09-15-private-file-lifecycle-repair.md)。当前使用说明见 [四类文件存储](../file-storage.md)。

## 修复结果

1. Console 普通多用户聊天，包括管理员和智能体所有者，Shell/文件工具默认进入 `user_workspaces/<user>/<agent>/artifacts/<conversation>/`。目录由服务端认证用户与会话派生；`user_task` 标记不能单独使客户端路径获得信任。授权显式代码项目保留，交付物仍进入私人归档。
2. 技能继续读取安装位置，任务产物自动归档；`.work` 等中间目录不登记。后台工具在实际执行结束时收集，正常会话在终态事件发出前收集，异常/取消还有收尾。取消不会使收集覆盖原任务结果或跳过清理。
3. 多用户发送缺身份或归档失败返回 ERROR，保留源文件，不再回退共享发送。快照先完整写入临时文件再原子发布；内容变化、目录错误、登记失败可重试。
4. PostgreSQL 事务锁及事务内重查保证同一用户、智能体、会话、内容重复登记幂等。删除墓碑阻止自动复活。可信项目根不能绕过其他用户/智能体的 `user_workspaces` 或 `user_libraries` 边界。
5. 四类面板的请求明确携带当前 Agent；切换后清空旧数据并忽略迟到响应。产物提供来源说明、源会话、保存个人库及“检查未登记文件”。补收只遍历数据库确认归属的当前 Agent 会话，本次新增数排除已有记录。
6. 旧版“跨 Agent 个人库授权”文档已标注为历史设计；当前个人库是用户 × Agent 隔离。

## 环境与限制

审查过程中误用 `uv run` 触发共享虚拟环境自动同步，在服务占用 orjson 文件时失败，导致部分依赖缺失。随后正常停止服务，恢复缺失依赖及同步前可确认的版本；未改 `uv.lock`，依赖一致性检查通过。恢复后重新执行上述后端验证、构建与服务启动。后续测试使用已有解释器，避免对运行服务的环境执行自动同步。

此次修复完成应用层的默认目录、登记、归属检查和失败恢复；不把它表述为任意 Shell/恶意技能的操作系统级沙箱。缺少可信会话标识的旧渠道或自动化不会自动猜测产物归属。其他旧共享产物尚未迁移；ReMe 机制未变更。

服务状态以正式命令 `python -m qwenpaw service status` 为准，访问地址为 `http://127.0.0.1:18089`。
