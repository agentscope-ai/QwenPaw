## 3. 用户模型

公开用户记录：

```python
class PlatformRole(StrEnum):
    ADMIN = "admin"
    MEMBER = "member"

@dataclass(frozen=True, slots=True)
class UserRecord:
    id: UUID
    username: str
    platform_role: PlatformRole
    status: Literal["active", "disabled"]
```

`UserRecord` 不包含 `password_hash`。密码哈希只存在于身份服务和 Repository
之间使用的内部 `CredentialRecord`。

## 4. 密码安全

### 新用户

- 使用 Argon2id；
- 每次哈希包含独立随机盐；
- 盐和算法参数编码在标准 Argon2 字符串中；
- 数据库不保存明文密码或可解密密码；
- 日志只记录用户 ID、用户名和角色，不记录密码。

### 参数升级

认证使用 `verify_and_update()`：

- 当前参数有效：验证成功，不写回；
- Argon2 参数过期：验证成功并生成新哈希；
- 未知哈希或错误密码：返回失败，不更新数据库。

### 旧 salted SHA-256

旧 `auth.json` 只提取：

- `user.username`；
- `user.password_hash`；
- `user.password_salt`。

不会迁移 `jwt_secret`、旧 Token 或撤销列表。旧 SHA-256 只允许一次性验证，
成功登录后立即替换为 Argon2id；失败登录不会改变哈希。

## 5. 首用户和并发安全

首个用户无论调用方请求 `admin` 还是 `member`，最终都必须是 `admin`。

该规则没有只依赖服务层的“先 count 再 insert”，PostgreSQL Repository 会：

1. 获取固定 PostgreSQL advisory transaction lock；
2. 在锁内重新检查 `users` 是否为空；
3. 空表时强制角色为 `admin`；
4. 非空表时保留管理员指定的目标角色；
5. 在同一事务内插入用户。

旧管理员迁移也使用同一个事务锁；如果锁内发现已经存在用户，则不再迁移旧
`auth.json`，避免并发产生第二个“首管理员”。

## 6. Repository 边界

PostgreSQL Repository 支持：

- 统计用户；
- 创建用户凭据；
- 按用户名读取凭据；
- 更新自适应密码哈希；
- 更新最后登录时间；
- 仅空库创建旧管理员。

所有 SQL 使用显式 Schema 限定表名。Schema 名只接受安全标识符。

用户名唯一冲突只在 PostgreSQL SQLSTATE `23505` 时映射为
`DuplicateUsernameError`；其他完整性错误保持原异常，不会被误报为用户名重复。
