# 正式部署与运行验收

日期：2026-09-15。对应设计：`docs/superpowers/specs/2026-09-15-deployment-runtime-design.md`。

## 交付

- 正式 `qwenpaw service` 命令组：init/check/run/start/stop/restart/status/logs/exec/database-upgrade。
- 独立实例配置、受控子进程、跨平台文件锁、真实服务 PID 校验、本机就绪心跳。
- Windows 缺少 PROCESSOR_ARCHITECTURE 时根据 Python 平台补全；识别虚拟环境重定向进程，避免登记启动器 PID。
- 部署手册及 README 入口、Windows 登录自启动脚本、Linux systemd 模板、源码构建 Compose 和配置示例。
- 当前机器私有配置位于 deploy/service.local.json，Git 忽略；新进程状态和启动日志分别为 data/run 和 data/logs。

## 实测

命令：`.venv/Scripts/python.exe -m pytest tests/unit/service/test_service.py tests/integration/test_service_deployment.py -q`。

结果：16 passed。数据库测试启用 QWENPAW_TEST_POSTGRES_CONTAINER=qwenpaw-pg、QWENPAW_TEST_POSTGRES_DATABASE=qwenpaw_test_migrations；测试 fixture 仅创建和清理独立随机 schema。

覆盖配置相对路径、凭据脱敏、环境变量隔离与引用、PID 复用/非目标进程、端口冲突、实例锁、过期就绪心跳、重复启动、禁止覆盖配置以及数据库升级显式确认。

隔离集成测试覆盖：空 schema 升级至 head、重复升级、全新工作区初始化、启动就绪、重复启动 PID 相同、首次注册管理员、正常关闭和端口释放。

当前 18089 实例实测：check 通过；start 成功；restart 完成正常关闭再启动；重复 start 复用 PID；status 返回 ready 且数据库检查通过；logs 可读。沿用已有数据库与工作目录，不修改账号密码或迁移业务数据。

模板验证：Docker Compose config --quiet 通过；Windows PowerShell AST 语法检查通过；新增 Python 文件编译通过。

## 验证边界

- Windows 自启动任务未安装；系统启动策略及运行账户未改动。
- Linux systemd 和多用户容器模板未在真实 Linux 服务器安装运行，未构建完整镜像；不能将模板语法检查等同于生产验收。
- 原业务数据仍在 tmp/task-2-1-acceptance。正式入口已接管，数据迁出 tmp 未执行，文档明确要求单独生成路径映射并备份后处理。
- 日志保留和归档由手册/系统托管负责，当前 CLI 不自动删除旧日志。
- 没有执行 Git 提交、推送或新建分支。
