# Task 1.2 数据库表与约束报告

## 1. 执行边界

- PostgreSQL 容器：`qwenpaw-pg`。
- 遗留数据库：`qwenpaw_test_single_node`，只读核验，禁止迁移和写入。
- 新建测试数据库：`qwenpaw_test_migrations`。
- 迁移测试只允许使用 `qwenpaw_test_<20 位十六进制>` 临时 Schema。
- 每次测试结束均降级到 base，并删除对应临时 Schema。
- 本任务只建立 Schema，不写入正式用户、Agent、会话或配置数据。

## 2. 迁移版本

| Revision | 范围 |
|---|---|
| `0001_identity_access` | 用户、登录会话、外部身份、模型治理、Agent 所有权与成员权限 |
| `0002_agent_conversation` | 会话、消息、Run、工具过程、附件、技能、MCP、频道 |
| `0003_governance_operations` | Secret、插件、自动化、通知审批、用量、共享应用、系统治理、备份与审计 |

迁移链为单线：

```text
base
  -> 0001_identity_access
  -> 0002_agent_conversation
  -> 0003_governance_operations
```

## 3. 表清单

### 3.1 身份、模型与 Agent 权限（9 张）

`users`、`user_sessions`、`external_identities`、`model_providers`、`models`、`model_grants`、`agents`、`agent_members`、`agent_config_revisions`。

### 3.2 会话与运行过程（8 张）

`conversations`、`conversation_members`、`runs`、`messages`、`run_events`、`tool_calls`、`attachments`、`user_agent_preferences`。

其中 `messages + runs + run_events + tool_calls` 共同保存对话页面需要重放的消息、推理、工具调用、审批关联、进度、错误和最终结果，不把对话退化为仅保存最终文本。

### 3.3 技能、MCP 与频道（10 张）

`skill_pool_items`、`skill_pool_versions`、`agent_skills`、`skill_publish_requests`、`agent_drivers`、`driver_revisions`、`mcp_oauth_sessions`、`channel_bindings`、`channel_external_identities`、`channel_access_rules`。

`channel_bindings` 直接归属于 Agent，并以 `(agent_id, channel_type)` 保持首期“每种内置频道类型一个绑定”的原有边界。

### 3.4 Secret、插件与 Agent 插件配置（7 张）

`credential_records`、`credential_bindings`、`plugin_installations`、`plugin_capabilities`、`app_grants`、`agent_plugin_settings`、`app_user_data`。

真实 Secret 只进入 `credential_records.encrypted_value`；其他表只保存引用，不建立重复凭据事实来源。

### 3.5 自动化、通知、审批与用量（7 张）

`automation_schedules`、`automation_grants`、`automation_executions`、`notifications`、`notification_receipts`、`approval_requests`、`usage_records`。

### 3.6 公共共享应用（4 张）

`shared_apps`、`shared_app_drafts`、`shared_app_publications`、`shared_app_user_workspaces`。

发布版本与用户私有运行 workspace 分开建模，共享应用的默认模型由不可变发布配置锁定。

### 3.7 平台设置、安全、备份与审计（8 张）

`system_settings`、`system_setting_revisions`、`user_preferences`、`security_policies`、`security_events`、`backup_artifacts`、`backup_operations`、`audit_logs`。

业务表合计 **53 张**；加上 Alembic 自身的 `alembic_version`，升级到 head 后共 **54 张表**。

## 4. 实库约束统计

在一次全新临时 Schema 升级到 `0003_governance_operations` 后，PostgreSQL 系统目录报告：

| 项目 | 数量 |
|---|---:|
| 表（含 `alembic_version`） | 54 |
| 全部约束 | 212 |
| 外键 | 120 |
| Unique Constraint | 26 |
| Check Constraint | 12 |
| 索引 | 92 |

`model_grants.subject_id` 与 `app_grants.subject_id` 保持可空，以支持平台级授权；唯一性使用 PostgreSQL `NULLS NOT DISTINCT` 唯一索引，避免平台级空主体产生重复授权记录。

## 5. 验证结果

- 空 Schema 可升级到 head。
- 对已到 head 的 Schema 再次执行升级不会重复建表。
- 可从 head 逐段降级到 base；业务表全部移除，只保留空的 `alembic_version`。
- 非空且没有 Alembic 版本的 Schema 返回 `nonempty_unversioned_schema`，原表和数据保持不变。
- 遗留数据库迁移前后只读指纹一致：数据库大小 `13622295`，关系数量 `123`。
- 迁移连接地址不会进入 fixture 的 `repr` 或测试报告。

## 6. 当前限制

- 当前只建立结构，不代表业务 Repository 已切换到 PostgreSQL。
- 当前不会导入遗留用户、Agent、会话、技能、MCP 或配置数据。
- RLS、Repository 选择器、正式写入、数据迁移和事实来源切换属于后续独立任务。
- 在本报告获得确认前，不进入 Task 1.3，也不允许业务代码向这些表写入。
