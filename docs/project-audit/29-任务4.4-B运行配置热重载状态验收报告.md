# Task 4.4-B 运行配置热重载状态验收报告

## 1. 验收结论

Task 4.4-B 已完成前后端实现，当前停在用户确认点。

- 运行配置保存与运行时热重载结果不再混为一个状态。
- 配置写盘成功后，即使 Agent 热重载失败，也不会把已保存配置回滚或误报为保存失败。
- 后端在当前进程内记录 `applied` 或 `pending_reload`。
- 配置页检测到 `pending_reload` 时持续显示黄色提示条和“重试热重载”按钮。
- 重试成功后状态恢复为 `applied`，提示条自动消失。
- Embedding 配置原有的运行时应用和回滚规则保持不变。

## 2. 后端实现

- 新增 `GET /api/workspace/running-config/runtime-status`。
- 新增 `POST /api/workspace/running-config/reload`。
- `PUT /api/workspace/running-config` 在持久化完成后同步尝试重载 Agent，并记录结果。
- 状态只保存在 FastAPI 当前进程内；进程重启后 Agent 从磁盘重新加载，因此默认状态重新视为 `applied`。
- 状态和重试接口继续经过当前 Agent 的访问授权，不绕过多用户权限边界。

## 3. 前端实现

- 配置页首次加载时同时查询当前运行时状态。
- 保存后再次查询状态：
  - `applied`：显示普通保存成功提示。
  - `pending_reload`：显示“已保存但尚未热重载”的警告。
- `pending_reload` 会在页面顶部展示持续可见的黄色状态条。
- 用户可以点击“重试热重载”；成功后状态条消失，失败则保留并允许再次尝试。
- 中英文文案已补齐。
