# Task 4.2-C 撤销公用与历史只读验收报告

## 1. 验收结论

Task 4.2-C 已完成实现，并于 2026-08-23 通过用户验收确认。

当管理员撤销 Agent 的平台公用状态后：

- 从未使用过该 Agent 的普通用户不再获得访问权限。
- 已创建过会话的用户仍能看到该 Agent 和自己的既有会话，但被标记为“历史只读”。
- 历史只读用户只能读取自己的会话列表、消息和工具执行过程，不能创建新会话、发送消息、运行 Agent、切换模型或修改会话。
- owner、有效成员以及仍具备公开访问权的用户不受历史只读规则影响。
- 管理员仍以普通用户身份拥有自己的会话数据，同时通过治理入口管理平台公用状态。

## 2. 数据库实现

- 新增迁移：`0007_agent_history_access`。
- 新增表：`agent_history_access`。
- 以 `(agent_id, user_id)` 作为联合主键，记录用户首次和最近一次创建会话的时间。
- 会话创建时幂等登记历史访问事实；应用启动时对已有会话执行幂等回填。
- 非平台 UUID 的历史外部身份不会错误写入平台用户关系表。

验收环境数据库已升级至 `0007_agent_history_access`，迁移升级、重复执行和降级路径均已验证。

## 3. 后端权限闭环

后端将“历史只读”作为独立访问状态，不提升为成员角色：

- Agent 列表返回 `historical_read_only=true`。
- 只允许历史用户通过 GET/HEAD/OPTIONS 读取聊天资源。
- 同时兼容 `/api/chats` 加 `X-Agent-Id` 的原有前端路径和 `/agents/{agent_id}/chats` 的 Agent scoped 路径。
- 新建会话、批量归档、删除、重命名、发送消息和其他写接口继续由统一权限门禁拒绝。
- 所有编辑、复制、启停、排序、成员管理等能力标志均为 false。

## 4. 前端交互闭环

- Agent 选择器显示“历史只读”标识。
- 对话页显示“该智能体已撤销使用权限，仅可查看你已有的历史会话。”提示。
- 既有消息及工具执行过程继续按原消息结构展示，没有降级为纯文本摘要。
- 输入框被真实禁用，不能提交消息。
- 新建会话、模型切换、附件、语音、Loop、审批和项目上下文等写操作入口被禁用或隐藏。
- 会话列表仍可打开既有会话，但不显示重命名、置顶、归档、删除等菜单入口。
- 前后端均实施限制，避免仅依赖界面隐藏形成越权漏洞。

## 8. 补充修复：仅使用与公用 Agent 的技能/工具只读

用户复核发现，“仅使用”成员和平台公用访问者虽然会被后端写权限门禁拒绝，但技能、工具页面仍展示新增和修改入口。现已补齐前端资源权限闭环：

- `access_role=user` 或 `can_edit=false` 时，技能页面仅展示技能库存和启停状态。
- 隐藏创建、从技能池载入、市场安装、ZIP 上传、批量操作、编辑、启停和删除入口。
- 工具页面仅展示工具库存、状态和配置摘要。
- 隐藏全部启停、单项启停、异步执行切换和工具配置入口。
- 技能和工具数据 Hook 同时增加只读防线，即使通过非预期交互触发，也不会调用写接口。
- owner 和 collaborator 保持原有维护权限，不改变既定资源角色设计。
- 后端 scoped 与旧版 `X-Agent-Id` 写接口继续返回 403，形成前后端双重防护。
