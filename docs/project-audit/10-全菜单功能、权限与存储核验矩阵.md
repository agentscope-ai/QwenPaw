# 全菜单功能、权限与存储核验矩阵

## 1. 核验结论

此前 `02-产品功能与页面目录.md` 完成了全部菜单的入口、主要交互和页面可达性盘点，但只有 Agent、模型、技能和 MCP 完成了独立的源码级专项分析。因此不能宣称“其他菜单已经全部确认”。

本文件补充其余菜单的：

- 页面原有功能。
- 前端 API 与后端服务链路。
- 当前持久化位置。
- 多用户后的推荐数据位置。
- 已逐组确认的权限边界。
- 必须保留的回归验收点。

本文件曾用于逐组确认；截至 2026-08-20，所有菜单权限组均已确认。后续若出现“推荐”字样，仅表示目标存储或实现方式建议，不表示权限仍未确认。

## 8. 全菜单统一验收模板

每个页面都必须验证：

管理员测试必须同时覆盖“作为普通用户管理自己的资源”和“使用额外管理 capability 治理他人/平台资源”两条路径，不能把管理员仅当作后台管理账号。

1. 管理员、所有者、协作者、使用者和未授权用户的菜单可见性。
2. 直接调用 API 时的服务端权限，不能只验证前端隐藏。
3. 用户切换、Agent 切换和浏览器重载后不残留前一主体的数据。
4. 列表、详情、创建、编辑、删除、批量、上传下载和流式操作。
5. 保存失败、运行时重载失败、部分失败和并发编辑冲突。
6. 原有文件、会话、工具、技能、模型和插件功能没有因权限改造丢失。
7. Secret、绝对路径、内部地址和其他用户标识不出现在无权响应、错误或日志中。
