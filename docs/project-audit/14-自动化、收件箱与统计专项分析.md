# 自动化、收件箱与统计专项分析

## 1. 分析范围

本专项分析：

- 定时任务。
- 心跳。
- 收件箱与审批。
- 智能体统计。
- Token 消耗。

这些功能相互联动：定时任务和心跳会运行 Agent、创建会话与 Trace、向频道投递、写入收件箱并产生 Token 和 Agent 统计。多用户设计不能把它们拆成互不相关的页面权限。

## 2. 浏览器实况

2026-08-20 对当前运行中的 QwenPaw v2.1.0 进行了页面核验。

### 2.1 定时任务 `/cron-jobs`

页面提供：

- 列表视图和日历视图。
- 创建任务。
- 从模板创建。
- 编辑、删除、暂停、恢复和立即运行。
- 查看运行状态和执行历史。

创建/编辑抽屉还支持一次性与周期任务、重复规则、时区、固定文本任务、Agent 任务、频道/用户/会话目标、流式或最终结果投递、静默运行、共享会话、工具安全、并发数、超时和结果写入收件箱。

### 2.2 心跳 `/heartbeat`

页面提供：

- 启用/停用。
- 分钟、小时或天级间隔。
- 单次执行超时。
- `main`、`last`、`inbox` 三种目标。
- 可选活跃时间段。
- 保存后热重排心跳任务。

心跳执行内容来自 Agent workspace 的 `HEARTBEAT.md`。后端还保留立即执行一次的 API。

### 2.3 智能体统计 `/agent-stats`

页面跟随当前选中的 Agent，并支持日期范围。展示：

- 活跃会话、消息、输入/输出 Token、LLM 调用和工具调用汇总。
- 消息、会话、Token、LLM/工具调用趋势。
- 按频道统计会话和消息的饼图。

### 2.4 Token 消耗 `/token-usage`

页面支持日期范围，展示：

- 总调用次数。
- 输入、输出和总 Token。
- 模型趋势与 Token 类型趋势。
- 按模型和按日期的数据表。

### 2.5 收件箱 `/inbox`

当前实例页面包含：

- 推送消息和审批两个标签。
- 按 Agent 和来源筛选。
- 批量操作。
- 全部标记已读。
- 查看和删除事件。
- Cron、心跳等运行结果。
- 工具审批及运行 Trace 查看。

## 3. 定时任务原有实现

### 3.1 Agent 作用域

每个 Agent 拥有自己的 `CronManager`。API 通过当前 Agent 获取对应 Manager，任务保存在 Agent workspace 的 `jobs.json`，历史记录保存在 `jobs_history/<job-id>.json`。

### 3.2 调度与任务类型

支持：

- 标准 Cron 表达式。
- 一次性时间。
- 一次性任务后的按天重复、截止时间或次数限制。
- 固定文本投递。
- Agent 请求执行。
- 时区、错过执行宽限、最大并发和超时。

### 3.3 投递

任务目标包含频道、外部/渠道用户 ID 和会话 ID。目标候选来源于该 Agent 的已有聊天，但当前前端也允许输入自定义值。

Agent 任务可以：

- 实时转发完整事件流。
- 只投递最终完成消息。
- 静默执行但仍保存会话和 Trace。
- 与目标会话共享上下文。
- 使用独立 Cron 会话。
- 将结果写入收件箱。

### 3.4 工具安全风险

当前 `tool_safety=false` 会把工具执行级别设为 `OFF`，即后台任务可以不经过审批执行工具。该行为在单用户可信本地环境中存在使用场景，但不能直接进入多用户版本，否则定时任务可能借 Agent、频道、MCP 或文件工具长期绕过实际用户授权。

## 4. 心跳原有实现

心跳是一个特殊的 Agent 级定时任务：

1. 在活跃时间段内读取 `HEARTBEAT.md`。
2. 使用固定 `main` 用户与会话标识运行 Agent。
3. `last` 目标会使用 Agent 配置中最后一次投递目标。
4. `inbox` 目标会保存 Trace 并生成收件箱事件。
5. `main` 或没有有效最后目标时只运行，不对外投递。

当前 `last_dispatch` 是 Agent 级状态。多用户后如果继续直接使用，可能把心跳结果发送给最后使用该 Agent 的另一个用户，因此必须改成明确授权的自动化目标。

## 5. 收件箱与审批原有实现

### 5.1 全局事件文件

当前所有通知保存在部署级 `inbox_events.json`。事件包含 Agent、来源、状态、标题、正文、payload、已读状态和时间，但没有接收用户。

因此当前：

- 事件列表是部署全局列表。
- “全部标记已读”会修改全部事件。
- 删除事件按全局事件 ID 执行。
- Trace 删除依赖剩余事件引用。

### 5.2 审批

当前推送接口会返回所有会话中的全部待审批请求，由前端再按会话过滤。这在多用户环境中会泄露其他用户的工具名、参数摘要、Agent 和会话信息，也可能导致越权审批。

目标版本必须在服务端按 `approval_user_id` 和 ActorContext 过滤，并确保只有被指定的实际用户可以决定审批。

## 6. 智能体统计原有实现

智能体统计从当前 Agent workspace 的 `chats.json` 和 `sessions` 目录扫描：

- 会话与消息数量。
- 用户/助手消息数量。
- 工具调用。
- 每轮消息元数据中的 Agent Token。
- 按频道的会话和消息。

服务还读取部署级 TokenUsageManager 的全局汇总并叠加到返回结果。当前前端主要使用新增的当前 Agent Token 字段，但接口仍保留全局总量字段。多用户目标模型必须删除“单个 Agent 统计混入部署全局 Token”的事实混淆。

## 7. Token 消耗原有实现

TokenUsageManager 当前按日期、Provider 和模型记录：

- 输入 Token。
- 输出 Token。
- 调用次数。

数据保存在部署级 Token JSON 文件，记录没有用户、Agent、会话、Run 或自动化来源维度。当前 API 直接返回全局汇总与原始聚合记录。

多用户后必须在模型调用发生时记录实际主体和资源归属，不能在查询阶段猜测 Token 属于谁。

## 8. 已确认的权限与运行方案

### 8.1 定时任务管理

建议：

- Agent 所有者和协作者可以创建、编辑、暂停、恢复、立即运行和删除自己可编辑 Agent 的任务。
- Agent 使用者不能修改 Agent 级任务。
- 每个任务必须保存 `created_by_user_id`、`automation_owner_user_id` 和最后修改人。
- 任务执行使用自动化所有者授权形成的 ActorContext，不能默认继承 Agent 所有者、最后登录用户或管理员身份。
- 创建者被禁用、失去 Agent 权限，或者 Agent、模型、频道、MCP 被停用时，相关任务自动暂停并通知自动化所有者。

### 8.2 后台工具授权

建议不再提供可长期绕过安全策略的 `Tool Guard OFF`：

- 普通只读或低风险能力可以按平台安全策略自动运行。
- 需要文件写入、删除、外部消息、远程网络写入、MCP 副作用等能力时，在启用任务前生成明确的“长期自动化授权范围”。
- 授权记录包含工具、能力、资源范围、网络目标、有效期和授权用户。
- 运行时超出授权范围则阻断该步骤、记录失败并通知授权用户，不静默扩大权限。
- 协作者创建涉及外部投递或高风险能力的任务时，需要 Agent 所有者确认；所有者本人创建时可自行确认。

这样既保留无人值守自动化，又不把一次关闭开关变成永久越权入口。

### 8.3 任务投递

建议：

- 目标频道必须是该 Agent 已绑定并启用的频道。
- 目标平台用户、外部身份和会话必须由服务端解析并验证，不能信任任意自定义用户 ID。
- 向任务创建者自己的会话或收件箱投递可以直接配置。
- 向其他平台用户投递必须存在会话分享、Agent 成员关系或明确通知授权。
- 向外部频道发送固定文本或 Agent 结果属于外部副作用，纳入长期自动化授权。
- 运行结果、错误和需要处理的阻断默认进入自动化所有者的收件箱。

### 8.4 心跳

建议心跳仍是每个 Agent 一套的 Agent 级自动化：

- 所有者和协作者可以编辑 `HEARTBEAT.md`、间隔、超时和活跃时间。
- 心跳使用受限的 `agent_automation` 主体运行，并保存 `authorized_by_user_id`，不能伪装成某个普通聊天用户。
- 涉及外部投递或高风险工具的心跳变更需要 Agent 所有者确认。
- `last` 只允许解析为自动化授权用户最后一个仍有权访问的目标，禁止使用其他用户的最后会话。
- `inbox` 写入授权用户的私人收件箱。
- `main` 使用专用的自动化会话，不混入任何用户的普通私人会话。

### 8.5 收件箱和审批

建议：

- 所有通知必须有明确 `recipient_user_id`。
- 用户只能查看、标记和删除自己的通知。
- 删除通知不等于删除安全审计、共享 Run 或其他用户通知。
- 审批请求必须绑定 `approval_user_id`，只有该用户可以批准或拒绝。
- 管理员拥有自己的私人收件箱；全局治理告警和审计查询进入独立管理视图，不混入管理员个人收件箱。
- 管理员显式代操作查看他人通知或审批记录时必须记录审计，但不能替用户批准普通工具副作用。

### 8.6 智能体统计

建议：

- 用户始终可以查看自己在各 Agent 中产生的个人使用统计。
- Agent 所有者和协作者可以查看该 Agent 的聚合运行统计，包括会话数、消息数、Token、工具调用和频道分布，但不显示其他用户的消息内容、标题或逐用户明细。
- Agent 使用者只能查看自己的使用统计。
- 公共共享应用所有者/协作者可以查看发布版本的匿名聚合统计。
- 管理员可以查看平台全局聚合；查看用户级明细必须进入审计场景。

### 8.7 Token 消耗

建议：

- 普通用户查看自己的 Token、调用次数、模型和日期趋势。
- Agent 所有者/协作者查看 Agent 聚合 Token，不读取其他用户消息，也不默认显示逐用户排行。
- 管理员查看平台、Provider、模型、Agent 和用户维度的全局用量。
- 普通用户可以看到 Provider/模型显示名称，但不能看到 API Key、Base URL Secret 或管理员成本配置。
- Agent 内置的 Token 查询工具必须使用当前 ActorContext 限定范围，不能返回部署全局数据。
- 首期保留原项目 Token/调用统计，不额外建设计费、余额或配额产品。

## 9. 推荐数据模型

```text
automation_schedules
  id, agent_id, created_by_user_id, automation_owner_user_id,
  type, name, schedule, timezone, task, dispatch, status,
  config_version, created_at, updated_at

automation_grants
  id, schedule_id, authorized_by_user_id, capability,
  resource_scope, target_scope, expires_at?, revoked_at?

automation_executions
  id, schedule_id, run_id?, status, trigger,
  started_at, finished_at, delivery_status, error_summary?

notifications
  id, recipient_user_id, agent_id?, source_type, source_id?,
  event_type, status, severity, title, body, payload_ref?, created_at

notification_receipts
  notification_id, user_id, read_at?, deleted_at?

approval_requests
  id, approval_user_id, agent_id, conversation_id?, run_id?,
  tool_call_id?, capability, redacted_arguments,
  status, created_at, decided_at?, expires_at?

usage_records
  id, occurred_at, user_id?, actor_type, agent_id?,
  conversation_id?, run_id?, automation_schedule_id?,
  provider_id, model_id, prompt_tokens, completion_tokens, call_count
```

任务定义、状态、授权、运行摘要、通知、审批和用量进入 PostgreSQL。大型运行输出、Trace 内容和媒体使用内容存储引用；workspace 中保留 `HEARTBEAT.md` 等人类可编辑内容文件。

## 10. 功能保真验收

### 定时任务

- 列表、日历、模板、一次性/周期、时区和自定义 Cron 保持可用。
- 固定文本和 Agent 任务、stream/final/silent、共享/独立会话和收件箱结果保持可用。
- 创建、编辑、暂停、恢复、立即运行、删除、状态和历史保持可用。
- 用户切换和 Agent 切换后不残留其他主体任务。
- 任务执行身份、目标和授权范围可追溯。

### 心跳

- 启停、间隔、超时、main/last/inbox、活跃时间和 `HEARTBEAT.md` 保持可用。
- 热重排失败必须回滚或显示明确失败状态。
- `last` 不得跨用户发送。

### 收件箱

- 标签、筛选、未读、批量、全部已读、删除、审批和 Trace 查看保持可用。
- 每个用户的未读计数、批量操作和审批严格隔离。
- 删除个人通知不破坏其他用户通知、Run 或安全审计。

### 统计与 Token

- 原有日期筛选、汇总卡片、趋势图、频道分布和数据表保持可用。
- 个人、Agent 聚合和平台全局三个视图结果与权限一致。
- 统计不能通过聚合接口反推出其他用户消息内容或身份。
- 自动化、频道和普通对话产生的用量均有明确归属。

## 11. 本组确认结果

用户已于 2026-08-20 确认：

1. 所有者和协作者都可以管理可编辑 Agent 的定时任务与心跳；使用者不能修改。
2. 后台任务不再允许简单关闭 Tool Guard 永久绕过审批，改为明确的长期自动化授权范围。
3. 协作者创建外部投递或高风险自动化时，需要 Agent 所有者确认。
4. 心跳是 Agent 级自动化，`last` 只能使用授权用户自己的最后有效目标，不能使用其他用户会话。
5. 收件箱和审批按接收用户隔离；管理员个人收件箱与全局治理视图分开，管理员不能替用户批准普通工具副作用。
6. 所有者/协作者查看 Agent 匿名聚合统计，使用者只看自己的统计；不向所有者/协作者显示其他用户的消息内容或逐用户明细。
7. Token 页面采用个人、Agent 聚合、平台全局三层视图；首期不增加计费、余额和配额。
