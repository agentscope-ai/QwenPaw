# Task 4.5-C/1-E 记忆文件页验收报告

## 1. 范围

本任务实现 Agent 文件页的“公共记忆 / 我的记忆”作用域切换、索引状态展示、索引重建入口，以及 owner、collaborator、普通使用者和管理员显式代管的前后端权限边界。

ACP、模型供应商配置、记忆正文数据库化和旧公共 Markdown 迁移不在本任务范围内。

## 2. 实现结果

- 文件页 Agent 作用域进入时请求 `/agents/{agentId}/memory/scopes`，只返回公共作用域和当前登录用户自己的私有作用域摘要，不返回物理路径或其他用户 ID。
- “公共记忆”和“我的记忆”切换会清空当前文件页缓存、图谱视图和错误状态，避免跨作用域复用旧内容。
- 公共记忆的索引状态来自 Agent 运行配置和运行时状态；私有记忆的状态来自 `agent_user_workspaces` 记录。
- owner、collaborator 可维护公共记忆；普通使用者公共记忆只读，但可以维护自己的私有记忆。
- 管理员代管必须从“全部智能体”表格的“代管公共记忆”入口进入，URL 明确携带目标 Agent ID 和治理标记；代管上下文透传到作用域、文件、图谱和重建请求，且只允许公共作用域。
- 直接调用接口时，普通使用者无法通过修改 query、请求头或用户 ID 访问其他用户私有目录，也无法写入公共记忆。
- 私有索引重建返回空响应、失败响应或异常时，服务端均把当前用户的索引状态落为 `reindex_failed`。

## 4. 真实页面检查

- 使用本机验收账号登录页面成功，管理员“全部智能体”页显示“代管公共记忆”入口；点击入口生成 `/files?governance=runtime-config&agentId=...`，页面显示“正在代管 … 的公共记忆”提示。
- 真实旧验收进程 `18089` 在本次代码修改前已启动且未启用热加载。该进程的旧白名单会对新 `/memory/scopes` 沿用 403，因此不能把旧进程的 403 当作当前代码结果。当前代码已通过后端白名单单测和新增治理路径测试；需要用本次代码重启 18089 后再做最终浏览器回归。
- 当前 18089 进程仍保持原有工作目录、Secret/backup 目录和数据库 Schema；本任务未删除、迁移或批量修改用户数据。

## 5. 验收步骤

1. 重启使用当前源码的多用户验收服务，打开 `http://127.0.0.1:18089`。
2. 管理员登录后进入“智能体管理 → 全部智能体”，点击任一 Agent 的“代管公共记忆”。
3. 进入文件页的“日记”或“知识库”，确认出现“公共记忆”标签、索引状态和“重建索引”按钮；确认没有“我的记忆”标签。
4. 返回普通用户登录，选择可使用 Agent，进入文件页；确认同时出现“公共记忆 / 我的记忆”。公共记忆打开后编辑器不可保存；切换到我的记忆后可以编辑并保存。
5. 用普通用户直接请求公共记忆 PUT，应为 403；将 `scope=private` 改为其他用户标识仍不能跨用户读取。
6. 撤销成员关系后刷新文件页，确认作用域标签和已打开缓存被清除。
