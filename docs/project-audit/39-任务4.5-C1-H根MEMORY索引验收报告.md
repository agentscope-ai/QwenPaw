# Task 4.5-C/1-H 根 MEMORY.md 索引验收报告

## 1. 验收结论

Task 4.5-C/1-H 已完成实现与验证，当前停在用户验收确认门，未进入 Task 4.5-C/2。

本任务已确认：

- 新建或缺省配置的 Agent 默认开启自动记忆检索；已显式关闭的 Agent 保持关闭。
- 根目录固定文件 `MEMORY.md` 可在启动、手动重建和运行期变更时同步到 ReMe。
- 根目录的 `PROFILE.md`、`SOUL.md` 等其他 Markdown 不会被该桥接逻辑扫描。
- 同一 Agent 下，普通用户检索结果为“公共记忆 + 当前用户个人记忆”，不包含其他用户的私有记忆。
- 管理员作为普通使用者与 Agent 对话时，可检索公共记忆和管理员自己的个人记忆；管理员治理上下文不会任意进入其他用户私有 ReMe。

## 5. 真实 memory_search 作用域验收

在临时 Agent 的公共根 `MEMORY.md`、管理员个人根 `MEMORY.md`、普通用户个人根 `MEMORY.md` 分别写入不同的唯一验收词，对三个范围分别重建索引，再通过真实 `/api/console/chat` 对话调用 `memory_search` 工具。

| 身份 | 应检索 | 不得检索 | 真实工具输出 |
| --- | --- | --- | --- |
| 管理员对话 | 公共 + 管理员个人 | 普通用户个人 | 仅返回 `c1hpublicneedle`、`c1hadminneedle` |
| 普通用户对话 | 公共 + 当前用户个人 | 管理员个人 | 仅返回 `c1hpublicneedle`、`c1hmemberneedle` |

验收脚本的初始布尔统计会命中用户提示词中的三个 token，因此未将该统计用作隔离证据；最终结论以 `memory_search` 工具返回段和助手最终回答为准。

## 7. 已知问题与非阻塞警告

1. 新建临时 Agent 选择“使用全局默认模型”时，生成的 `agent.json` 没有 `active_model`，导致该 Agent 的记忆服务首次启动报 `No active model configured`。本次验收通过管理员治理 API 为临时 Agent 补全与默认 Agent 一致的 `active_model` 后继续。这是 Agent 初始化/全局默认模型继承缺陷，不是根 `MEMORY.md` 索引缺陷，需作为后续独立任务修复。
2. 前端生产构建仍有现有 chunk size 警告，不影响构建成功或本任务功能。
3. pytest 中的 1 个 warning 为现有非阻塞警告，本任务没有新增失败基线。
