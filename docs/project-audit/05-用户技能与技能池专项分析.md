# 用户技能与技能池专项分析

## 1. 结论

当前技能系统是清晰的双层模型：

- **Agent 技能（Workspace Skill）**：属于某个 Agent workspace 的可运行、可编辑技能副本。
- **技能池（Skill Pool）**：部署实例级的共享技能模板库，用于复用、分发、内置版本管理和自动更新。

“从技能池载入技能”当前并不是创建引用关系，而是将技能目录完整复制到目标 Agent workspace，再写入该 Agent 的 `skill.json`。因此，载入后的技能具有独立的运行状态和部分独立元数据。

## 2. Agent 技能原有实现

### 数据位置

```text
~/.qwenpaw/workspaces/<agent-id>/
  skills/<skill-name>/
    SKILL.md
    references/
    scripts/
    ...
  skill.json
```

- `skills/<skill-name>` 是技能内容的事实来源。
- `skill.json` 是运行状态的事实来源，保存 `enabled`、`channels`、`config`、`tags`、来源和同步元数据。
- `reconcile_workspace_manifest()` 会扫描真实目录，补齐新技能、移除已不存在的技能，并保留启停、频道和配置状态。

### 页面能力

Agent 的“技能”页面当前支持：

- 查看已启用和已停用技能。
- 搜索、标签过滤、卡片/列表视图和批量选择。
- 创建技能并编辑 `SKILL.md`、配置和名称。
- 上传 ZIP 技能。
- 从外部 Hub URL 异步导入，可取消、超时和处理重名。
- 从市场安装技能。
- 从技能池选择一个或多个技能载入当前 Agent。
- 将当前 Agent 技能上传到技能池。
- 启用、停用、删除、批量启停和批量删除。
- 设置技能可用频道、标签和配置。
- 启用前执行 Skill Scanner；内容写入采用暂存目录、扫描和回滚保护。
- 修改启用状态或内容后触发 Agent reload。

删除规则保持了安全顺序：技能必须先停用，之后才能删除其目录和 manifest 项。

## 3. 技能池原有实现

### 数据位置

```text
~/.qwenpaw/skill_pool/
  <skill-name>/
    SKILL.md
    references/
    scripts/
    ...
  skill.json
```

技能池目录是共享内容的事实来源，manifest 保存：

- 技能来源：`builtin` 或 `customized`。
- 内置技能语言和版本。
- 安装来源、配置和标签。
- 外部技能目录标识。
- 自动更新开关、目标 Agent 和最近同步哈希。

### 页面能力

技能池页面当前支持：

- 查看、搜索、标签过滤和卡片/列表展示。
- 创建、编辑、重命名和删除共享技能。
- ZIP 上传、Hub URL 导入和市场入口。
- 导入内置技能，识别新增、缺失、更新、移除、语言和版本状态。
- 从某个 Agent workspace 上传技能到技能池。
- 将一个或多个技能广播到一个或多个 Agent workspace。
- 冲突预检、覆盖确认、内置升级确认和语言切换确认。
- 标签、配置、自动更新目标和批量删除。
- 在技能池内容变化后，将启用自动更新的技能推送到指定 Agent。

## 4. 技能池与 Agent 之间的传输语义

### 从技能池载入 Agent

1. 对目标 Agent 进行冲突预检。
2. 区分普通重名、内置版本升级和内置语言切换。
3. 用户确认覆盖后，将技能目录复制到 Agent 的 `skills` 目录。
4. 新载入技能默认启用；如果目标 Agent 原来已有同名技能，则保留其启停、频道、个人配置和个人标签。
5. 技能池配置和标签只在 Agent 没有对应个人值时作为初始值。
6. 载入过程经过安全扫描和暂存目录。

这说明技能池提供的是**可复制模板**，Agent manifest 持有**运行时个性化状态**。

### 从 Agent 上传到技能池

1. 从指定 Agent 的技能目录复制内容。
2. 执行安全扫描。
3. 同名技能需要预检和覆盖确认。
4. 将 Agent 技能的配置、标签和安装来源复制为技能池模板元数据。
5. Agent 原副本仍然保留，不会被移动或删除。

### 技能池广播

- 本质是对多个 Agent 执行批量“从池载入”。
- 前端先对所有技能和目标 workspace 预检冲突。
- 后端为目标技能保存快照；多目标执行失败时尝试回滚，避免只更新部分 Agent。

### 自动更新

- 技能池记录内容哈希和目标 Agent。
- 池内容发生变化后，仅向开启自动更新的目标 Agent 推送。
- 自动更新仍然是复制覆盖，不是运行时共享读取。

## 5. 多用户改造后的权限映射

根据已确认需求，建议保留原有双层语义，并应用以下权限：

| 操作 | 普通用户 | Agent 协作者 | Agent 所有者 | 管理员 |
|---|---|---|---|---|
| 查看授权技能池目录 | 允许 | 允许 | 允许 | 允许 |
| 从技能池载入可用技能 | 自己可修改的 Agent | 具备协作权限的 Agent | 允许 | 任意 Agent |
| 启停/配置 Agent 技能 | 自己 Agent | 允许 | 允许 | 任意 Agent |
| 创建/编辑 Agent 私有技能 | 自己 Agent | 允许 | 允许 | 任意 Agent |
| ZIP/Hub 导入 Agent 私有技能 | 自己 Agent，受安全策略约束 | 允许 | 允许 | 任意 Agent |
| 直接进入技能池管理页 | 禁止 | 禁止 | 禁止 | 允许 |
| 创建/编辑/删除技能池内容 | 禁止 | 禁止 | 禁止 | 允许 |
| 广播技能到多个 Agent | 禁止 | 禁止 | 禁止 | 允许 |
| 配置技能池自动更新 | 禁止 | 禁止 | 禁止 | 允许 |
| 将 Agent 技能直接发布到技能池 | 禁止直接发布 | 禁止直接发布 | 提交申请 | 审核并发布 |

普通用户的 Agent 技能页面仍应保留“从技能池载入”入口，但必须移除或替换“直接上传到技能池”操作。推荐将其改为“申请发布到技能池”，由管理员审核后生成共享模板。

## 6. 数据与授权约束

- 技能池记录由管理员域管理，不能归属某个 Agent workspace。
- Agent 技能记录必须同时绑定 `agent_id`，并通过 Agent 所有权/共享授权校验。
- 技能文件仍适合保存在文件系统或对象存储；PostgreSQL 保存身份、归属、版本、配置、状态、发布申请和审计信息。
- `/skills/workspaces` 当前会枚举所有 Agent，改造后普通用户不得调用或只能看到自己有权限的 Agent；管理员广播接口才能枚举全体 Agent。
- `/skills/pool/upload`、`/skills/pool/download`、广播和自动更新必须在后端逐目标校验权限，不能相信前端提交的 `workspace_id`。
- 全局技能池读取与管理权限应分开：普通用户可读取管理员授权的可发布版本，但不能读取管理元数据、外部路径或敏感配置。
- 技能配置可能包含密钥或内部地址，响应模型必须提供脱敏值，实际秘密进入专用 Secret Store。
- 所有发布、覆盖、广播、自动更新和管理员代操作都需要审计日志。

## 7. 必须保留的回归用例

- Agent 切换后技能列表严格切换到对应 Agent。
- 普通用户只能载入授权技能池条目和自己可编辑的目标 Agent。
- 载入新技能默认启用，已有技能覆盖时保留原启停、频道、个人配置和标签。
- 普通重名、内置升级和语言切换显示不同确认信息。
- ZIP/Hub/池载入均经过安全扫描，失败不留下半成品目录或数据库记录。
- 广播多目标失败时不产生部分成功的不可追踪状态。
- 用户无权直接写入技能池；管理员发布后用户才可载入。
- 自动更新仅影响管理员配置的目标 Agent，并记录覆盖前后的版本和操作者。
- 删除 Agent 技能仍要求先停用；删除池模板不自动删除 Agent 已有副本。
