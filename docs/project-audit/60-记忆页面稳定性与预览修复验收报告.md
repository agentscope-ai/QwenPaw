# 记忆页面稳定性与预览修复验收报告

> 验收日期：2026-09-16  
> 服务地址：`http://127.0.0.1:18089`  
> Agent：`QwenPaw_QA_Agent_0.2`

## 问题根因

记忆文件打开后会把 `FileLocator` 回写到文件中心。原实现因回写产生新的回调和请求上下文对象，自动打开副作用会再次执行，形成“打开 → 回写 → 重新加载作用域 → 再次打开”的循环。失败测试在 80 毫秒内观察到 73 次作用域请求，服务日志也记录了同一文件的大量重复 `200` 请求。

预览还存在请求竞态：用户快速切换文件时，较早请求如果晚于新请求失败，会清空已经成功显示的新文件并留下“记忆文件加载失败”。

`needs_reindex` 是记忆检索索引的维护状态，文件列表和 Markdown 正文读取不依赖该索引。原页面直接显示内部枚举值，使正常可读的文件看起来像加载故障。

## 修复内容

1. 用 Agent ID 和治理标记构造稳定请求上下文，移除对象引用变化造成的重复副作用。
2. 自动打开按 `scope + section + path` 去重，父组件回写同一定位时不重复读取。
3. 作用域、文件列表和正文使用独立加载/错误状态，正文错误不再污染列表状态。
4. 为列表和正文请求增加序号保护，只允许最新请求更新界面。
5. 将“会话记忆/记忆沉淀”更名为“日记记忆/长期记忆”，并补充来源说明。
6. 将索引内部状态映射为非阻断说明，不再显示 `needs_reindex` 等内部枚举值。
7. 对当前用户的 QA Agent 私有记忆执行一次正式索引重建，状态从 `needs_reindex` 更新为 `ready`，版本更新为 `1`。
