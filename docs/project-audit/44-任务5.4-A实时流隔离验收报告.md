# Task 5.4-A 实时流隔离验收报告

## 1. 验收结论

Task 5.4-A 已完成 Console 实时流与断线重连的用户、会话双重绑定。多用户模式下，客户端不能再仅凭可伪造的 `session_id` 重连运行流；后端会先校验 PostgreSQL 会话写权限，再核对 `conversation_id` 与实际解析出的 Chat ID，并由 TaskTracker 拒绝跨作用域订阅或复用活动任务。

本项只覆盖 Task 5.4 的实时流隔离。审批请求按 `approval_user_id` 过滤属于 Task 5.4-B，后台任务 ActorContext/会话/审批人保真属于 Task 5.4-C。

## 2. 实现内容

### 2.1 重连请求显式携带会话 ID

- 前端断线重连载荷新增 `conversation_id`。
- 会话 ID 使用 SessionApi 已解析的 PostgreSQL 会话 UUID，不信任展示 ID或临时本地 ID。
- 单用户模式保持原协议兼容，不强制要求该字段。

### 2.2 后端重连门禁

- 多用户重连缺少 `conversation_id` 时返回 `400`。
- 重连前按认证主体校验会话所有者写权限。
- 权限校验通过后，再核对 `session_id` 实际解析出的 Chat ID 是否等于 `conversation_id`；不一致统一返回 `404`，避免泄露会话存在性。

### 2.3 TaskTracker 运行流作用域

- 活动运行新增可选 `access_scope`，Console 使用“可信用户 ID + 实际 Chat ID”形成作用域。
- `attach()` 对跨作用域重连返回不可订阅。
- `attach_or_start()` 对跨作用域复用同一运行键抛出权限错误，路由统一转换为 `404`。
- 非 Console 渠道和单用户调用未传作用域时保持现有行为。

## 4. 可视化验收步骤

服务更新后可按以下步骤验收：

1. 用户 A 在某个自有会话中发送一条需要较长时间生成的消息。
2. 生成期间刷新页面或切换到其他会话后再返回，页面应只重放该会话自己的事件并继续实时输出。
3. 用户 B 在另一浏览器登录，即使知道用户 A 的前端 `session_id`，也不能通过重连请求读取用户 A 的运行流；接口返回空流或 `404`，不会出现用户 A 的内容。
4. 用户 A 的原有停止生成、历史回放和新消息发送仍可正常使用。
