# Task 6.2 文件页面全功能隔离验收报告

## 1. 验收结论

Task 6.2 已完成实现和自动化验证，当前等待用户界面验收确认。

- Agent owner/collaborator 继续使用原 Agent 项目和配置目录。
- 仅使用公用或共享 Agent 的普通用户使用独立个人运行空间。
- 普通用户可在个人运行空间读写、上传、下载和恢复 ZIP。
- Agent 工作区、档案和配置文件对仅使用用户保持前后端只读。
- 两个普通用户在同一公用 Agent 下创建同名文件时互不覆盖。

## 2. 目录与权限模型

| 访问身份 | 项目目录 | Agent 配置目录 |
|---|---|---|
| owner / collaborator | 原 Agent 项目，可写 | Agent 草稿，可写 |
| user | `user_workspaces/{user_id}/{agent_id}`，可写 | Agent 草稿或登记旧目录，只读 |
| historical | 原历史上下文，只读 | 只读 |

项目目录接口会同时返回：

- `project_kind`
- `project_key`
- `project_read_only`
- `workspace_kind`
- `workspace_key`
- `workspace_read_only`

前端以这些服务端结果控制目录身份、编辑器、上传按钮和项目目录管理入口。

## 3. 实现内容

### 3.1 后端

- 为文件页统一解析 project/workspace 两个根目录。
- user 角色自动登记并使用个人运行空间。
- 文件内容、批量上传、Coding 文件和 workspace ZIP 统一使用根目录级只读判定。
- 公共 Agent 配置目录写入返回 HTTP 403。
- ZIP 路径检查使用真实父子路径判断，拒绝同名前缀目录逃逸。
- Agent 上层授权允许文件写请求到达根目录策略层，最终权限仍由 `read_only` 强制判定。

### 3.2 数据库

新增迁移：`0010_runtime_workspace_grants`。

该迁移只向应用角色 `qwenpaw_runtime` 授予以下表的 `SELECT、INSERT、UPDATE、DELETE`：

- `agent_history_access`
- `agent_user_workspaces`

没有修改表结构或批量改写业务数据。

### 3.3 前端

- 权限拆分为项目文件权限和 Agent 配置文件权限。
- 普通用户项目根显示“个人运行空间”。
- 普通用户不显示可修改 Agent 项目目录的按钮。
- 切换到 Agent 工作区或档案时保持只读。
- 页面显示的个人运行空间路径与后端实际访问路径一致。

## 6. 用户界面复验步骤

1. 打开 `http://127.0.0.1:18089` 并使用普通用户登录。
2. 选择“默认智能体”，进入“文件”。
3. 确认顶部显示“项目目录 · 个人运行空间”。
4. 确认没有“Agent 项目目录”修改按钮，项目根上传按钮可用。
5. 在项目根上传或编辑一个文件并保存。
6. 切换到 Agent 工作区或“档案”，确认编辑和上传能力被禁用。
7. 使用第二个普通用户登录，在同一 Agent 下创建同名文件并写入不同内容。
8. 分别重新登录两个账号，确认各自只能读取自己的内容。
