## 4. 有意的安全行为变化

这些差异属于设计后的安全收紧，不判定为原功能退化：

1. 多用户模式必须建立可信 ActorContext；客户端 `user_id`、`owner_user_id` 或伪造 Header 不构成授权依据。
2. 普通管理员身份不会自动读取全部用户数据；代管他人资源必须进入显式治理路径并记录理由与审计。
3. Agent owner/collaborator 不自动读取使用者私人会话；会话只有创建者和被显式分享者可读。
4. 公用 Agent 使用者可以创建自己的会话、文件、频道绑定和模型覆盖，但不能修改公用 Agent 配置或再次分享。
5. 密码、访问/刷新令牌、API Key、频道 Token、MCP/OAuth 凭据和部署环境变量不提供明文回读。
6. ACP 从产品菜单和新建写 API 关闭；历史 Harness/MCP 兼容读取继续保留。
7. Legacy 业务文件在 PostgreSQL 多用户模式下仅用于迁移、归档或运行寻址投影，禁止继续承担已切换领域的权威写入。
