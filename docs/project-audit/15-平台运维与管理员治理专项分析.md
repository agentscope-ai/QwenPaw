# 平台运维与管理员治理专项分析

## 1. 分析范围

本专项覆盖最后一组部署级菜单及其与多用户体系的关系：

- 环境变量。
- 工具后台策略。
- 安全治理。
- 备份、导入、恢复和导出。
- 调试日志。
- 顶部语言、时区等部署设置与用户偏好的边界。

这些入口都能影响多个 Agent、全部用户或宿主进程，不能仅通过前端隐藏菜单实现权限控制。

## 2. 浏览器实况

2026-08-20 对当前运行中的 QwenPaw v2.1.0 进行了页面核验。

### 2.1 环境变量 `/environments`

页面支持查看全部变量名和值、密码框遮罩与明文显示、新增、批量编辑、批量删除和保存。当前实例已经配置真实第三方凭据类变量。

### 2.2 工具后台策略 `/offload-policy`

页面提供部署级二选一默认行为：倒计时结束后保持前台执行，或者自动转入后台执行并让 Agent 继续处理其他任务。

### 2.3 安全 `/security`

页面包含四个标签：

- 工具防护：总开关、沙箱、受保护工具、禁止工具、内置/自定义规则、自动拒绝和 Shell 逃逸检测。
- 文件防护：敏感路径、工作区外预览等策略。
- 技能扫描器：扫描策略、阻断历史和白名单。
- 免认证主机白名单：允许指定 IP 绕过认证。

### 2.4 备份 `/backups`

页面支持备份列表与搜索、创建、删除、导出、恢复、ZIP 导入、冲突处理、legacy/foreign 信任确认、完整/部分备份、恢复前保护性备份和 SSE 进度。范围可以包含 Agent、全局设置、技能池和 Secret；完整备份说明明确包含全部 Agent workspace、全局设置、技能池和密钥信息。

### 2.5 调试 `/debug`

页面提供后端日志自动刷新、正序/倒序、日志级别和关键词筛选、手动刷新、复制，以及当前日志文件绝对路径和原始尾部内容。

## 3. 环境变量原有实现与风险

环境变量保存在 `SECRET_DIR/envs.json`，值使用本地 Secret Store 加密，并同步到当前 `os.environ`，供主进程、子进程、插件、技能、MCP 和工具使用。

当前 API 的关键行为：

- `GET /envs` 解密后返回全部明文值。
- `PUT /envs` 使用请求中的完整字典替换全部变量，未提交的键会被删除。
- 删除会同步移除进程环境中的对应值。
- `QWENPAW_WORKING_DIR` 和 `QWENPAW_SECRET_DIR` 等引导键不会从持久化文件注入，但接口层仍缺少多用户权限。

多用户风险包括读取平台全部凭据、一次保存覆盖其他功能变量、修改即时影响所有 Agent/插件/任务，以及明文进入浏览器状态、开发者工具、日志或恶意插件前端。

## 4. 工具后台策略原有实现

策略保存在部署级 `settings.json`，启动时加载到共享 ToolCallCoordinator。修改后立即改变当前进程中全部用户、Agent 和会话的超时转后台默认行为。

该策略只决定执行呈现和调度方式，不应改变工具调用主体、会话与 Run 归属、审批责任人、自动化授权范围，以及用户退出或权限撤销后的生命周期规则。当前设置路由文件明确标记全部接口为无需认证，目标版本必须取消这一行为。

## 5. 安全治理原有实现

### 5.1 部署级安全基线

当前全局配置可以关闭 Tool Guard、File Guard，启停沙箱，修改受保护/禁止工具和规则，调整技能扫描器和全局白名单，并允许工作区外预览。这些设置决定平台安全下限，必须由管理员治理并记录修订与审计。

### 5.2 Agent 级安全配置

源码和集成测试还保留 Agent 级 Tool Guard、File Guard 和 Skill Scanner 配置。目标版本不能简单删除这一层，否则会丢失原 Agent 个性化运行能力。

推荐采用“平台基线 + Agent 收紧策略”：

- 管理员定义平台最低安全基线。
- Agent 所有者和协作者可以增加保护、提高审批等级或缩小允许范围。
- Agent 配置不能关闭平台强制规则、扩大文件边界、添加全局技能白名单或降低部署级安全等级。
- 最终有效策略由服务端合并，前端显示被平台锁定的字段和原因。

### 5.3 免认证主机

现有功能按字面 IP 配置白名单并允许请求绕过认证。在反向代理、NAT 或共享终端环境下，多个用户可能呈现为同一来源 IP，因此它与严格多用户登录存在根本冲突。

目标版本不应让来源 IP 自动获得普通用户、Agent 所有者或管理员身份。若为本地兼容保留，也只能在管理员显式启用的受限部署模式中映射为最小权限服务主体，并记录高风险配置审计。

## 6. 备份原有实现与边界

### 6.1 原有能力

备份系统已有归档元数据和版本、本机 HMAC 签名、外部/旧备份显式信任、ZIP 与恢复目标校验、进程内/跨进程恢复锁、临时目录、原子交换、异常回滚、启动恢复、受影响 Agent 停止与重载，以及完整和选择性恢复。这些能力必须保留，不能在数据库迁移后退化为直接覆盖目录。

### 6.2 平台备份

包含全局配置、Secret、技能池或多个用户 Agent 的备份是平台级运维能力：

- 创建、查看、导出、导入、删除和恢复仅管理员执行。
- 恢复前明确显示影响用户、Agent、数据库、workspace、技能池和 Secret 范围。
- 数据库、workspace、内容存储和 Secret Store 使用同一备份清单和一致性点。
- 恢复不能在无审计的单个请求中直接覆盖全部事实来源。

### 6.3 用户可移植 Agent 包

普通用户迁移自己的 Agent 时不应复用平台完整备份权限。建议提供独立的 Agent 可移植导出/导入：

- 所有者可导出自己的 Agent 配置、workspace、私有技能和非敏感引用清单。
- 协作者是否可导出由所有者显式授权，默认不可导出完整资产。
- 包中不包含平台全局配置、技能池、其他用户数据或可直接使用的 Secret 明文/密文。
- 导入默认创建归属于当前用户的新 Agent 或草稿，不覆盖现有 Agent、他人资源或平台设置。
- 模型、插件、频道和 MCP 依赖只记录逻辑需求，目标平台重新授权并重新绑定 Secret。

## 7. 调试日志原有实现与风险

当前接口返回日志绝对路径、文件大小、更新时间和原始尾部内容。日志可能包含用户输入、会话/Agent/文件/外部身份标识、工具参数、错误堆栈、URL、Header、环境变量或其他用户运行信息。

因此：

- 全局调试菜单和原始日志只对管理员开放。
- 返回前必须对 Secret、认证 Header、Cookie、Token 和常见凭据格式脱敏。
- Web UI 只返回逻辑日志源名称，不需要返回宿主绝对路径。
- 管理员查看和导出日志记审计。
- 普通用户继续在自己的对话、Run、Trace 和收件箱中查看本人运行的脱敏错误和工具执行过程。

## 8. 用户偏好与平台设置

当前 `settings.json` 同时承载语言和工具后台策略，且路由原本公开。多用户后应拆分：

- 界面语言、时区进入 `user_preferences`，每个用户独立保存。
- 上传限制、后台策略和部署安全基线进入管理员维护的 `system_settings`。
- 管理员自己的语言和时区仍是个人偏好，不因管理员身份变成全局值。

## 9. 推荐数据与文件边界

```text
system_settings
  key, value, version, updated_by, updated_at

system_setting_revisions
  id, key, old_value, new_value, changed_by, reason?, created_at

secret_records
  id, scope_type, scope_id, secret_type, encrypted_value,
  key_version, status, created_by, rotated_at?, revoked_at?

secret_bindings
  id, secret_id, consumer_type, consumer_id, purpose, created_by

security_policies
  id, scope_type, scope_id, policy_type, config, version,
  enforced, updated_by, updated_at

security_events
  id, occurred_at, user_id?, agent_id?, run_id?, event_type,
  severity, action, redacted_detail, rule_id?

backup_artifacts
  id, name, backup_type, storage_key, manifest_hash,
  signature, status, created_by, created_at

backup_operations
  id, artifact_id, operation_type, requested_by, status,
  scope_manifest, started_at, finished_at, error_summary?
```

Secret 密文可进入 PostgreSQL Secret Store 表，主密钥必须位于数据库之外。备份 ZIP、日志、规则包和扫描签名继续保存在文件或对象存储。数据库保存权限、元数据、修订、操作状态和审计，不保存全量日志正文。用户可移植 Agent 包与平台灾备归档使用不同类型、API 和权限检查。

## 10. 功能保真验收

### 环境变量

- 新增、修改、删除、批量保存和即时注入保持可用。
- 普通用户和无权 API 无法枚举变量名或值。
- 已保存值只显示“已配置”和掩码，更新时允许留空表示保持原值。
- 变量变更引发的 Agent、插件、MCP 和后台任务影响可追溯。

### 工具后台策略

- 保持前台和自动转后台两种行为保持可用并可热更新。
- 用户在具体工具执行中的原有前台/后台交互保持可用。
- 转后台后 ActorContext、审批、会话和 Run 归属不改变。

### 安全

- 四个原有标签、规则编辑、沙箱状态、阻断历史和白名单管理保持可用。
- Agent 级配置可以收紧但不能削弱平台基线。
- 安全策略更新失败时不产生部分生效状态。
- 免认证模式不能获得用户或管理员身份。

### 备份

- 创建、列表、搜索、删除、导入、导出、冲突、信任、恢复、SSE 进度和恢复前保护备份保持可用。
- PostgreSQL、workspace、内容存储和 Secret Store 的备份清单一致。
- 普通用户的 Agent 包不能包含其他用户数据或有效 Secret。
- 恢复失败可以回滚，不留下数据库与文件事实不一致。

### 调试

- 自动刷新、排序、级别/关键词筛选、刷新和复制保持可用。
- 普通用户仍能查看自己的丰富 Run/Trace 错误过程。
- 全局日志响应不泄露 Secret、其他用户内容和宿主绝对路径。

## 11. 本组确认结果

用户已于 2026-08-20 确认：

1. 部署级环境变量菜单仅管理员可见和可操作；保存后的 Secret 不再向任何浏览器回传明文，管理员只能替换、删除和查看“已配置”状态。
2. Agent 所有者/协作者需要的频道、MCP、插件等凭据通过独立 Agent Secret 绑定入口管理，不能访问部署级环境变量；Secret 同样不可回读明文。
3. 工具后台默认策略由管理员配置；普通用户仍保留具体工具执行时原有的前台/后台交互，转后台不改变权限、审批或数据归属。
4. Tool Guard、File Guard、Sandbox、Skill Scanner 和全局白名单由管理员定义平台基线；所有者/协作者只能为可编辑 Agent 增加更严格配置，不能降低基线。
5. 免认证主机不再直接绕过登录并获得普通用户或管理员身份；默认关闭，仅在管理员显式启用的兼容模式中映射为受限服务主体并审计。
6. 平台完整备份、导入、导出、删除和恢复仅管理员执行；恢复继续作为需要再次明确确认的高风险操作。
7. 普通用户可以导出自己拥有的 Agent 可移植包并导入为自己的新 Agent/草稿；默认不含有效 Secret、平台配置、技能池或其他用户数据，协作者默认无完整导出权。
8. 全局调试日志仅管理员查看并执行服务端脱敏；普通用户不显示全局调试菜单，但继续在自己的对话、Run、Trace 和收件箱中查看本人运行错误和工具过程。
9. 界面语言、时区属于每个用户的个人偏好；上传限制、后台策略和安全基线属于平台设置。
