# Task 6.2-R/1 对话运行目录与附件隔离验收报告

日期：2026-09-01  
验收环境：`http://127.0.0.1:18089`，多用户模式，PostgreSQL Schema `qwenpaw_task21_acceptance`

## 1. 本项解决的问题

Task 6.2 已让文件页面中的普通使用者进入个人运行空间，但对话运行链路仍可能沿用 Agent 配置目录：

- Agent 通过文件或 Shell 工具生成的文档可能写入共享 Agent 目录；
- 对话附件可能写入共享 Console `media` 目录；
- 文件页面与对话实际运行目录不一致，用户无法可靠管理自己的输入和产物。

## 2. 实现结果

在 Console 请求边界统一解析当前用户的运行目录：

- `user`（仅使用/平台公用）角色：对话默认项目目录解析为 `user_workspaces/<user_id>/<agent_id>`；
- 聊天附件写入该个人运行空间的 `media` 子目录；
- 流式对话和后台对话任务使用同一解析逻辑；
- owner/collaborator 继续使用 Agent 已配置的项目目录和原 Console 附件目录，避免侵入原功能；
- 历史只读访问不获得新的写入能力。

本项只统一运行路径，不在当前步骤引入附件生命周期、个人资料库或新的数据库结构，符合 KISS/YAGNI；路径解析复用文件页面现有授权服务，避免重复实现权限规则，符合 DRY。

## 4. 服务启动异常说明

验收期间曾用不完整环境变量直接启动服务，`/api/auth/status` 返回 `legacy`，导致普通用户被退化识别为 Agent owner。根因是遗漏 `QWENPAW_MULTI_USER_ENABLED=true`，不是权限实现或数据库数据错误。

已改用项目既有 `tmp/start-18089.ps1` 启动脚本恢复同一工作目录、Secret 目录、数据库和 Schema。恢复后状态为：

```json
{"enabled": true, "has_users": true, "mode": "multi_user"}
```

未清空或迁移数据库数据。

## 5. 用户验收步骤

1. 使用普通用户登录并选择一个平台公用或“仅使用”Agent。
2. 在对话输入区上传一个文档。
3. 打开“文件”，确认顶部为“个人运行空间”。
4. 在项目根的 `media` 目录确认能看到刚才上传的附件。
5. 使用第二个普通用户对同一 Agent 上传同名文件，确认不会覆盖第一个用户的附件。
6. owner/collaborator 可复验其 Agent，确认仍沿用原项目目录。
