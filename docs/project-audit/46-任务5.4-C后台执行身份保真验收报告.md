# Task 5.4-C 后台执行身份保真验收报告

## 1. 验收结论

Task 5.4-C 已将 Console 后台任务和工具转后台链路绑定到服务端确认的用户、Agent、Conversation、Run 与审批人。客户端提交的 `user_id`、`approval_user_id` 或 `actor_context` 不能覆盖认证主体；即使其他用户获得后台 `task_id`、工具 `tool_call_id` 和 `session_id`，后端也不会返回任务状态、输出或控制能力。

本项未修改数据库结构、Agent 配置、模型配置和前端消息展示协议。

## 2. 实现内容

### 2.1 Console 可信执行上下文

- 多用户模式下，Console 使用认证中间件生成的 `ActorContext` 覆盖客户端用户字段。
- 执行上下文显式保存 `user_id`、`approval_user_id` 和只读主体快照。
- 实际 Chat 创建或解析后，服务端写入真实 `conversation_id` 和唯一 `run_id`。
- 后台请求若声称使用会话 A，但 `session_id` 实际解析到会话 B，统一返回 `404`。

### 2.2 后台任务所有权

- `_BackgroundTask` 保存 owner、Agent、Conversation、Run 和 ActorContext 快照。
- `GET /console/chat/task/{task_id}` 在多用户模式下校验当前认证用户。
- 非任务所有者得到 `404`，无法判断任务是否存在。
- 合法所有者可在状态响应中取得本任务的 `conversation_id` 和 `run_id`，便于核对后台结果归属。

### 2.3 PostgreSQL Run 保真

- Console 在执行开始前生成 Run ID。
- PostgreSQL 运行持久化器复用该服务端 Run ID，不再另行生成不相关的运行标识。
- 下游工具上下文与 `runs`、`run_events`、`tool_calls` 使用同一 Run 关联。

### 2.4 工具转后台保真

- ToolCoordinator 在启动工具时复制稳定执行标识，不持有可变的请求字典。
- 后续请求上下文被修改，不会改变已运行或已转后台工具的用户、会话、Run 和审批人。
- 工具列表、详情、转后台、取消、延长时限、输出和输出流均增加后端用户所有权校验。

### 2.5 审批归属

- Tool Guard、Governance Tool Adapter 和 Driver Gate 均显式向 ApprovalService 传递可信 `approval_user_id`。
- 审批扩展信息保留 `conversation_id` 与 `run_id`，便于后台审批和持久化事件关联。

## 4. 页面验收方法

1. 用户 A 在对话中启动一个耗时工具，并在工具卡片出现后选择转后台。
2. 切换到其他会话再返回，用户 A 仍可查看该任务进度和最终输出；审批出现时只由用户 A 处理。
3. 使用另一浏览器登录用户 B，同时运行自己的耗时任务。
4. 两个浏览器的工具卡片、后台状态和审批必须各自独立，不能看到或控制对方任务。
5. 用户 B 即使复制用户 A 的后台 `task_id`、`tool_call_id` 和 `session_id` 直接请求接口，也只能得到 `404`。
6. 用户 A 的任务完成后，刷新会话历史，工具过程和最终回答仍按原有消息协议显示。

## 5. 原功能无侵入核对

- 前台对话、停止生成、重连、富工具事件和最终回答协议未改变。
- 单用户模式保留原有兼容行为。
- 后台 Fork 的提交、失败、取消和超时处理未改变。
- 未新增数据库迁移，未删除或批量修改任何数据。
