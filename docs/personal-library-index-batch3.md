# 第三批：个人资料库索引基础设施

## 本批实现

现有资料库已有多格式解析、正文缓存、文件名和正文模糊匹配，但检索仍扫描所有文档正文，解析失败也不可见。本批增强检索基础设施，不按企业、旅游、产品等主题限制资料检索。

1. 使用 Python 自带 SQLite 保存用户与智能体双重隔离的派生索引，以字符和相邻字符倒排表召回候选，继续用现有正文、文件名匹配规则验证相关性。
2. 上传、文本更新、产物/附件保存、改名和删除同步更新索引；根据内容哈希、解析版本、文件大小和修改时间判断是否需要重建。
3. 记录可检索、部分索引、空正文、不支持、文件过大、解析失败及待更新状态；失败文件保留原件，未变更时不重复解析。
4. 提供只作用于当前用户、当前智能体的状态与重建接口，文件中心展示逐文件状态、重建入口和失败提示。
5. 测试增量更新、多用户隔离、旧资料自动建索引、故障恢复、中文模糊召回和前端切换后的旧请求隔离。

## 边界

- PostgreSQL 继续保存资料归属和权威元数据，SQLite 只保存可丢弃并重建的派生内容，不修改业务数据库结构。
- 不升级 ReMe，不增加 Elasticsearch 或向量模型，不改变工具授权、联网搜索策略或用户原始文件。
- 保留现有 Markdown、TXT、PDF、DOCX、PPTX、XLSX、CSV、JSON、OpenDocument 等格式解析；图片型扫描 PDF 需要 OCR，本批不增加 OCR，旧版二进制 DOC/PPT/XLS 不视为已支持。
- 单文件自动索引上限 32 MiB、正文上限 200 万字符。超过字符上限显示部分索引，超过文件大小上限保留可下载原件并显示原因。

## 使用方法

打开 **文件 → 个人资料库**。每个文件后会显示“可检索”“待建立索引”“解析失败”等状态，悬停可以查看原因。新上传或从产物/附件保存的文件会自动解析并建立索引；已有文件在首次正文检索时补建，无需重新上传，也可以主动点击“重建索引”。

重建入口每批处理 5 份文档并更新进度，接口最多接受 10 个文档 ID。切换智能体会取消前端当前请求并停止提交后续批次；服务端已开始的当前批次可能继续完成。重新进入后读取已保存的状态，不会将旧智能体的结果显示到新智能体中。重建有部分失败时明确提示，不将整个资料库标成成功。

索引解析和查询在工作线程中执行，文件级写入使用事务；同进程中相同索引的操作串行协调。这个版本没有常驻后台索引队列，首次处理大量历史文档可能较慢，建议先在资料库页面重建。

## 数据、部署与回退

索引保存在运行数据根目录的 `personal_library_indexes/<用户 UUID>/<智能体 UUID>/search.sqlite3`，与可上传的资料目录分离。沿用现有运行数据卷和 `QWENPAW_WORKING_DIR` 配置，不增加容器、服务或 Python 依赖。应放在本地可写磁盘或 Docker 数据卷；本批没有验证多台应用服务器同时写同一网络共享 SQLite 文件的部署方式。

索引中包含提取的私人正文，按用户及智能体隔离，已加入 Git 与 Docker 构建忽略项。它不能单独授予文件访问权限：候选结果仍需通过当前请求的 PostgreSQL 资料元数据过滤，并确认原文件可访问。

业务数据库与用户原件均不迁移、不改结构。旧版 `.qwenpaw-index/*.json` 缓存保留；回退旧代码时可按原有逻辑重建缓存。显式重建遇到损坏的 SQLite 索引时会保留 `search.broken-<随机值>.sqlite3` 副本，再建立新索引；备份业务数据时原始资料和 PostgreSQL 元数据仍是必需项。

## 检索方式与未包含内容

倒排表以规范化字符和相邻字符片段召回候选，只读取候选的正文缓存，继续结合关键词、文件名、正文匹配和中文片段覆盖率排序。未变更资料不会反复调用 Office/PDF 解析器；缺失原文件不会仅凭名称被返回。没有语义向量、同义词模型或按领域分类的硬编码优先规则，因此不能承诺理解所有不包含共同词语的改写。

索引损坏时，显式 `personal_library_search` 返回重建提示；自动资料推荐降级，不阻断整条聊天。此批未调整模型选择是否调用工具的策略，也不宣称修复与本功能无关的聊天流式重复渲染问题。

## 验证

- 后端相关单元测试 66 项通过，覆盖索引复用、更新、删除、旧资料补建、外部文件变更、隔离、解析失败、空文本、大小限制、部分索引、规范化匹配和损坏恢复。
- 文件中心及资料库 API 前端测试 19 个文件、97 项通过。
- 生产构建和 Monaco 样式检查通过，保留现有的大包体积提示。
- 浏览器验收通过：使用生产构建及测试 API 响应，实际上传、重建、切换浏览器标签页、三轮切换文件分类、刷新，以及“收件箱 → 文件”返回。没有改动真实用户资料。这不等同于真实模型的答案质量或所有历史聊天的验收。
