## 3. P0：扩展区入口与资源反馈跳转

**状态：代码已实现，来源链路与精确关联已有针对性测试；生产登录、提交与通知闭环不在已验证范围内。**

社区入口位于扩展共用标题区，在应用、插件和技能页面复用现有 `openExternalLink()`、URL 常量和中英文文案。访问社区无需先绑定 QwenPaw 内的社区账号，发帖仍采用社区自己的登录流程。

「我的应用」、已安装插件、Skill 工作区与技能池的卡片及列表接入统一「问题反馈」入口。仅有效平台安装来源记录可以显示入口；禁用资源仍可反馈。点击阻止卡片事件冒泡，避免同时启动应用或编辑 Skill；浏览器异步解析跳转处理弹窗阻止与失败提示。

来源链路已经实现以下规则：

- `installation_origin` 固定包含 `provider`、`resource_id`、`resource_type`、`source_url`，可选 `installed_version`。完整字段见 [契约说明](community-integration-contract.zh.md#安装来源与资源关联)。
- 插件与应用的安装记录由安装器保存在包目录之外；Skill 来源贯通工作区、技能池、安装清单和已安装 API。原 Skill 市场 provider `qwenpaw` 映射为统一平台来源。
- 来源依据可信平台安装 URL 和安装记录，不能依据名称、作者身份、本地 ID 或任意包 manifest 声明建立。平台更新与重启保留关联，本地包或其他来源覆盖清除旧关联。
- 实际版本来自已安装包；不使用市场最新版本、下载分支名或猜测值。历史记录缺少可信稳定 ID 时不按同名资源补齐，也不显示可用的关联角标。

平台反馈页的已确认规则已用于实现：

| 本地类型 | 平台实体与反馈参数                                                            |
| -------- | ----------------------------------------------------------------------------- |
| plugin   | 使用平台 `plugin_id`，打开 `/community/ask?relatedPluginId=...`               |
| app      | 平台实体仍是 plugin，且 `tech_type.code == "app"`；同样使用 `relatedPluginId` |
| skill    | 使用平台 Skill UUID，打开 `/community/ask?relatedSkillId=...`                 |

市场稳定标识 `@owner/name` 与反馈页选项 ID 不同。后端按名称后缀检索，再精确比较完整 `item.id`，解析可信 `details_url` 并校验资源详情的 ID 与类型。找不到、类型变化或地址异常时提示失败，不关联到同名资源。

平台当前问题编辑器没有版本、标题或正文的 URL 预填契约。因此 P0 URL 只传已确认的资源关联参数；已安装版本通过 P2 可审阅报告正文携带。不会添加无效的 `installed_version` 或 `relatedAppId` 参数。

已通过真实浏览器验收三类平台资源的安装来源与角标、移动端入口隐藏和 Desktop OS 社区设置复用；同名资源的完整 ID 匹配另有后端测试。公开反馈页与登录页回跳参数已核对，实际生产登录后关联保留与提交仍待授权验收。Tauri/pywebview 原生系统浏览器跳转仍待端到端验收；本轮原生 QA 未取得完整交互证据，不计入通过项。

## 4. P1：社区账号连接与原生收件箱

**状态：本地连接协议、设置界面、通知适配与持久化收件箱已实现并通过本地测试；已改为复用 CLI client，无需 Java 改动，真实账号授权与首次同步已通过；默认消息能力已启用，已有暂停偏好保留。**

设置页在普通设置与 Desktop OS 系统设置中接入，提供未配置、未连接、等待授权、已连接、授权过期、远程授权不支持等状态。已连接后可查看账号、切换账号、解除连接、暂停同步和立即同步。暂停保留消息；解绑清除该运行实例的社区凭据、同步状态与本地社区消息，并尝试远端撤销授权。

本地服务实现浏览器 PKCE：随机 `state`、S256、仅 loopback 回调、一次性消费、取消、五分钟过期、刷新与撤销。社区凭据与本地/Hub 登录分开，不复用浏览器 Cookie 或已有 CLI 凭据。请求限制固定平台域名、超时与重试边界；解绑、切换账号及暂停同步期间的旧请求不能写回旧连接状态。

收件箱已实现：

- 在既有「推送消息」中增加「QwenPaw 社区」来源，展示发送者、类型、摘要、时间、关联资源与「查看讨论」。社区消息不套用默认 Agent 或执行轨迹。
- 合并本地与社区消息后再在服务端筛选、分页、统计；社区来源清空并禁用 Agent 筛选。社区范围全部已读不影响本地消息。
- 本地维护已读、去重及删除 tombstone；暂停、重复同步、删除后同步不让旧消息复现。账号切换清理旧账号消息。
- 既有侧栏、OS Dock 和通知中心消费社区未读状态；初次历史同步避免集中弹出旧通知。
- 社区存储异常保留原文件并返回来源错误，不中断本地收件箱和 Agent。

当前远端适配覆盖已查证的 `comment-replies`、`mentions`、`interactions`、`feedback`、`notifications`，使用只读请求 `mark_read=false`。评论流中精确的 `event_type=comment_on_my_resource` 且 `resource_type` 为 `plugin`、`app` 或 `skill` 时映射为本地 `resource_feedback`；其他评论事件仍为 `reply`，社区关联资源问题归为 `resource_feedback`，其他关联为 `mention`，远端 ID 与本地去重标识保持不变。自己发布的社区文章或问题收到的评论保留为普通回复。能力列表以 `resource_comments` 表示资源评论，另以 `resource_questions` 表示已确认的社区关联资源问题通知。本地轮询有分页续传、失败退避与取消；远端没有已确认 cursor 或单条已读接口，本实现不假造这些能力。

## 5. P2：Agent 辅助反馈报告

**状态：本地报告流程已实现，采用复制交接；没有调用社区草稿或发帖接口。**

从资源反馈角标旁的可选操作进入报告弹窗，不增加全局顶部反馈菜单。用户可以手工编辑报告，选择日志或截图并预览，确认材料后调用当前配置的模型整理标题、环境、复现步骤、预期与实际结果。版本由实际安装记录进入报告正文，缺失事实标记待补充；QwenPaw 版本与操作系统仍需手填。

实现采用独立的一次性模型请求，不创建 Agent 会话、工具、记忆或自动读取工作区文件。模型未配置、生成失败或取消时保留用户编辑内容。日志进行尽力脱敏；截图由用户选择、预览和手工遮盖，不能将文字脱敏视为截图内容已自动清理。正文与日志仅暂存在页面内存中，刷新不保留；截图关闭后重开清空。

用户审阅报告后复制正文，再打开保持资源关联的社区问题反馈页，手工粘贴与提交；截图需要用户按需在社区上传。页面不能将报告生成或复制成功显示为已发帖。社区现有 `draftId` 路由和草稿写 API 的存在，不代表 QwenPaw token 已获准调用；跨站草稿保存与自动交接仍待平台授权契约。
