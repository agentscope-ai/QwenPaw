本文保留开发工作区当时的审计记录。涉及独立模型路由、重排、召回评测及其新接口的条目属于其他开发阶段。此次提交仅从混合文件中提取身份、委托、进程接管和六个插件所需的修改。准确的提交范围及独立候选版本复测结果见上方验收报告。

2026-11-19 核查了发布基线 `75982e358` 的本地源码，以及当前工作区尚待发布的模型路由、检索、资料管理和子任务修改。**现有系统可以支撑单应用进程内多个账号使用同一个智能体。若要求所有功能都遵循同样的授权、并支持撤权和故障恢复，目前仍有缺口。**

## 发现与本地处理

| 优先级 | 检查的实际路径 | 发现与处理 |
| --- | --- | --- |
| 高 | 定时任务管理页、启动时动态注册的 HTTP 和斜杠命令 | 管理页使用创建者授权服务，旧动态适配器却直接调用默认智能体管理器。多用户启动时不再注册这组旧入口；列表、创建及删除继续通过现有自动化接口。多用户模式中授权服务缺失会返回 503。回归检查注册表和正式路由的行为。 |
| 高 | 两名成员同时在同一个智能体运行工具 | 工作区是共享对象。旧实现把当前请求的资源策略放入该对象，之后还有异步等待，另一个请求有机会覆盖它。现在把资源策略直接传给每次构建的工具，用户、沙箱项目目录及审批策略跟随本次执行。回归强制两次构建交错，并检查实际工具绑定的策略对象。 |
| 高 | 聊天状态、后台任务结果、工具状态和控制 | 原先轻量状态接口缺少会话级检查。后台结果轮询没有持续要求当前智能体访问权。聊天中的工具控制命令也缺少与 HTTP 操作一致的归属检查。现在分别按会话所有者或有效分享者、后台任务创建者和父会话、工具所属用户和智能体校验；聊天命令还限制在当前会话。状态查询只读权限记录和运行状态，不加载消息历史。 |
| 高 | Console 前后台请求、定时任务和子任务技能 | 交互请求可以携带与调度器内部字段同名的元数据。现在由服务端绑定交互身份，丢弃调度快照和旧 fork 路由信息。工具允许列表只能收窄父级选择，显式加载技能时也检查真实技能目录名。SDK 自动加入的技能查看器和后注册工具在最终工具查找时接受同一限制，同时保留获准技能的说明。 |
| 中 | 多个智能体、资料批量评测、管理员代管 | 一个请求内已经取得的授权曾只用“是否已有结果”判断能否复用。现在缓存绑定目标智能体，个人资料批量评测在下一个样例开始前重新检查成员资格。补齐代管界面上的重排接口测试和公共记忆评测入口，继续使用现有平台管理员策略及审计。对私人记忆的代管访问仍返回 403。 |
| 中 | 个人资料创建、上传、复制到新路径 | 先查数据库再覆盖同名文件会留下竞争窗口。新建路径采用排他方式发布完整文件。同一账号的两个并发新建请求产生一个 201 和一个 409，成功一方可以读回完整内容。不同账号在同一智能体使用相同文件名时各自成功。 |
| 中 | 系统诊断和版本展示 | 运行诊断包含服务器解释器和虚拟环境路径，原先任何登录用户都能读取。多用户模式现复用平台设置管理权限。版本接口仍只返回版本号。 |

以上前四项在发布基线中可以从源码追溯。重排与批量评测还涉及本地新增功能。此次没有抽查正式服务器的代理暴露面、用户数据或访问日志，不能据此认定发生过越权读取。

## 已验证的业务场景

1. 在独立的本地 PostgreSQL 16 中迁移到 `0022_artifact_sample_answer`。使用真实密码登录、设备会话和 HTTP 鉴权，为两个普通账号授予同一智能体的使用角色。测试中的工作区管理器只提供临时目录，成员资格判定、资料元数据、行级权限和文件内容走实际实现。
2. 两人同时创建同名但内容不同的资料。两次 HTTP 响应都是 201，文件 ID 不同。两人的列表分别只有自己的记录，读取的内容与各自提交的一致。
3. 同一成员并发创建第二个同名文件。只允许一个创建成功，另一请求返回 409。按成功响应的 ID 读取，正文与获胜请求一致。
4. 第二名成员执行两条资料评测。第一条完成后在另一数据库事务撤销成员资格，当前请求返回 403，第二条没有进入检索。其账号会话仍有效，第一名成员的资料仍能访问。随后单方退出，另一方仍能访问自己的账号。
5. 对照静态路由基线，核对了 21 个追加的方法和路径，并将两个采用多方法装饰器的文件接口的 GET、HEAD 纳入检查。清单从 483 条扩展到 508 条静态方法与路径声明。动态生成的定时任务入口另有注册测试。接口数量用于发现覆盖遗漏，各项授权结论以对应行为测试为依据。

## 首次核查时的四项缺口

以下是确定本轮实施范围时的记录。四项对应的最终实现、保留限制和候选版本测试结果，均以[本轮验收报告](2026-11-19-multi-user-live-connections-and-recovery.md)为准。

1. **长连接中途撤权**。运行状态、待确认输入等 SSE 在订阅时按智能体和用户隔离。部分流建立后没有按当前设备会话与成员资格重新判定。下一轮应在本地用两个已连接的客户端验收单方撤权、停用、退出后停止接收，并测量数据库开销。普通请求与重连通过不代表旧连接已经断开。
2. **跨智能体委托与 fork**。同一智能体、非 fork 的子任务有服务端委托。跨智能体的前后台调用仍缺目标智能体授权、会话归属和结果回查的一致契约。旧 fork 使用共享会话文件和工作树。当前返回明确的能力限制；多用户模式关闭旧 fork 接口。发布应用仍需以固定发布版本为委托边界。
3. **重启恢复及水平扩容**。官方启动入口固定单 Worker。后台任务句柄、等待确认的 Future 和 SSE 订阅者在进程内；已保存的消息、产物和样稿确认有各自的数据库记录。后台任务表还保留已结束的结果，源码中没有按数量或时间回收的机制，长期批量派发存在内存累积风险。持久化任务状态、结果保留期限与重启接管需要一起设计。容量验收还需要并发人数、延迟目标及外部模型配额。
4. **自带前端插件与业务验收**。六份带前端入口的自带插件清单未声明 `worker-v1`，宿主会拒绝启动旧包。涉及 agent-kanban、qwenpaw-creator、chrome、cloudpaw、computer-use、qwenpaw-pet。要迁移实际前端交互和消息协议，单改清单值无法完成适配。PPT、文件和检索的真实业务成功率需用真实模型及业务样例另行验收。
