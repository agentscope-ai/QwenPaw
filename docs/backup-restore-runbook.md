# WeldonAgent 备份与恢复运行手册

本手册供生产管理员执行完整实例备份和空实例恢复。完整备份同时覆盖 PostgreSQL、工作数据与密钥目录，不能用单独复制某一个目录替代。

## 备份

备份前确认数据盘剩余空间至少大于当前 `working`、`secrets` 与数据库逻辑大小之和的 1.5 倍。

Linux：

```bash
cd /opt/weldonagent
./deploy/weldon.sh backup
```

Windows PowerShell：

```powershell
Set-Location "D:/Apps/WeldonAgent"
& "deploy/weldon.ps1" backup
```

入口会启动数据库、短暂停止应用、在一次维护窗口内生成备份，再恢复应用。成功输出类似：

```text
/data/backups/weldonagent-20260917T020000Z
```

备份目录包括：

- `database.dump`：PostgreSQL 自定义格式转储；
- `working.tar.gz`：智能体、用户文件、知识库、记忆、产物和运行数据；
- `secrets.tar.gz`：密钥存储；
- `manifest.json`：脱敏环境信息、格式版本和每个文件的 SHA-256。

备份生成后，把整个目录复制到受控的异地存储。不要只复制压缩包中的一部分。建议执行每日增量保留策略时，至少保留最近 7 个日备份、4 个周备份和 3 个版本升级前备份。

## 恢复前提

恢复只面向新实例或空数据根，禁止在原实例上原地覆盖。目标必须满足：

- `working` 和 `secrets` 目录为空；
- 目标 PostgreSQL schema 中没有业务表；
- 备份目录位于目标数据根的 `backups` 下；
- `deploy/.env` 中的数据库名、schema 和账号已经配置；
- 应用容器尚未承载业务流量。

如果目标已执行过 `init` 并创建了业务表，应使用新的空数据根重新开始。恢复程序会拒绝非空目标，不会自动清空数据库或删除文件。

## 恢复

先把完整备份复制到目标服务器的数据根，例如：

```text
<数据根>/backups/weldonagent-20260917T020000Z
```

Linux：

```bash
./deploy/weldon.sh restore /data/backups/weldonagent-20260917T020000Z
```

Windows PowerShell：

```powershell
& "deploy/weldon.ps1" restore /data/backups/weldonagent-20260917T020000Z
```

恢复过程按固定顺序执行：校验清单和 SHA-256、确认文件目录为空、确认数据库为空、恢复数据库、发布工作数据与密钥、执行数据库升级检查、启动应用。

任一预检失败都不会写入目标。数据库恢复失败时文件目录不会发布；应用保持停止状态，管理员应先查看维护容器日志并重新使用一个空目标。源备份始终保持只读。

## 恢复后验收

```bash
./deploy/weldon.sh status
./deploy/weldon.sh logs
```

管理员应依次验证：

1. 管理员和普通用户可以登录；
2. 用户只看到自己有权访问的智能体；
3. 历史会话能打开且消息不重复；
4. 个人知识库可以检索已上传文件；
5. 记忆文件和长期记忆可见且作用域正确；
6. 产物可以预览和下载；
7. 已配置密钥能被引用，页面和日志不显示明文；
8. 新建对话、上传文件和生成产物均写入新数据根。

完成验收后再接入反向代理或切换业务流量。

## 失败处置

- 备份失败：入口会尝试重新启动应用；确认服务状态后处理空间、权限或数据库连接问题，再重新备份。
- 恢复预检失败：修正备份路径，或重新准备空数据根；不要绕过空目标检查。
- 数据库恢复失败：保留日志和源备份，废弃当前空目标并重新创建实例。
- 文件校验失败：从异地存储重新复制整个备份目录；不要单独替换某个文件。
- 恢复后业务验证失败：不要切换流量，保留源实例，记录对象计数和失败模块后排查。
