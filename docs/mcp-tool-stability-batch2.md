## 多用户适配

- MCP 配置继续以 PostgreSQL 中的已提交版本为准。更新保留当前用户身份、智能体作用域和 `expected_revision` 冲突校验。
- 工具白名单保存后等待运行时刷新；刷新失败明确返回“已保存但运行时刷新失败”，不宣称已经生效。
- 工具执行即使等待过审批或 HTTP 请求锁，也会再次核对当前白名单。
- 保留凭据轮换和撤销校验；为新协议客户端补充上游未提供的原子 `reload`，使用更新后的凭据重新协商并清空旧工具缓存。
- 不向 stdio MCP 注入平台托管的全局环境变量，继续只使用已有卡片环境配置和受控凭据解析。
- 未修改数据库结构，没有运行数据库迁移，没有移动用户文件或重建记忆索引；未升级 ReMe、AgentScope 或 MCP SDK。

## 使用超时配置

在 MCP 配置编辑 JSON 中增加：

```json
{
  "http_timeout": 90
}
```

该字段单位为秒，须为有限正数，适用于 HTTP/SSE 连接、写入和连接池等待。读取预算至少为该值，默认读取预算为 300 秒；因此该值不是整次工具调用的总时限。工具的取消与执行期限仍由现有协调器管理。

创建时不填使用默认值；编辑时省略字段保留原设置，显式设置 `null` 恢复默认连接 30 秒、读取 300 秒。stdio 不使用这个配置。JSON 导入同时识别兼容字段 `timeout`，优先使用明确提供的 `http_timeout`。

工具白名单中 `null` 表示不限制，空列表表示全部禁用，非空列表只允许列出的工具。它仍需与原有访问策略共同满足，不能代替用户授权。

## 验收与边界

回归覆盖生命周期退出、挂起请求、旧会话恢复、协议回退、超时往返及重置、凭据轮换、白名单缓存和执行检查、PostgreSQL 版本校验、取消及异常终态。HTTP 兼容测试使用真实客户端和模拟协议响应，不向外部 MCP 服务发送业务数据。

前端验收包含 MCP 编辑、凭据与 OAuth 界面、聊天取消及重放契约。浏览器使用生产构建和拦截的测试 API，实际切换浏览器标签页、连续三轮“收件箱 → 当前对话”、刷新页面，检查历史工具不转圈、当前对话不丢失、消息不重复。该浏览器用例是历史恢复验收，不等于对任意真实模型长时间流式输出的全面验证。

本次执行结果：后端相关回归 377 项通过，1 项因旧 MCPClientManager 已移除而跳过；前端 12 个文件、69 项测试通过；浏览器验收 1 项通过。生产构建和 Monaco 样式检查通过，构建仍有现有的大资源包体积提示。

**暂未移植：** 上游跨智能体前台调用的远端停止通知。上游请求只携带 Agent ID，本分支需要先补齐受约束的内部调用身份与会话归属传递，不能据此绕开多用户权限。当前取消改进覆盖协调器管理的本地工具，不承诺终止远端 Agent 已接收的任务。

个人知识库索引基础设施、模型发现与每智能体路由仍留在后续批次；本批没有接入 Auto Fin、Hub 或第二套记忆存储。

## 运行与回退

更新代码后使用现有规范服务入口重启，不需执行数据库升级：

```powershell
& ".venv/Scripts/python.exe" -m qwenpaw service --config "deploy/service.local.json" restart
& ".venv/Scripts/python.exe" -m qwenpaw service --config "deploy/service.local.json" status
```

Linux 使用 `.venv/bin/python` 执行相同模块命令。回退只需部署前一份代码/镜像并重启同一配置，不应恢复或覆盖业务数据库。测试日志放在 Git 忽略的 `build/` 中，回归测试源码应保留。
