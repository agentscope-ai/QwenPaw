# 数据库容器部署与聊天状态修复阶段总结

日期：2026-09-17
基线提交：`07a3cf8b`（完善 WeldonAgent 生产部署与外部品牌）

本阶段在既有多用户架构上补充部署方式，并修复生产构建登录白屏、历史工具调用持续显示执行中的问题。此前已提交的品牌调整、知识库检索和多用户重构不重复计入本阶段新增功能。

## 1. 支持数据库运行于 Docker、应用运行于宿主机

- 新增 `deploy/compose.database.yml`，独立运行 PostgreSQL 16，容器名称为 `agent-pg`，不启动应用容器。
- 数据库默认仅向宿主机 `127.0.0.1:5432` 发布端口，可通过部署环境变量调整绑定地址及端口。
- PostgreSQL 数据挂载在配置的数据根目录下，配合首次 schema 初始化脚本、健康检查和重启策略，避免把数据库放在源码或临时目录中。
- 环境示例增加数据库端口和绑定地址配置；数据库密码继续要求显式提供。
- 新增 [数据库容器与本地服务部署指南](database-container-host-service.md)，覆盖 Linux 和 Windows 的代码安装、依赖安装、前端构建、工作目录配置、数据库初始化、服务启停、日志、开机启动及验证步骤。
- 保留内部命令和配置变量的兼容性，对外统一使用 WeldonAgent 部署说明。

本阶段提供部署配置及操作指南，没有实际迁移当前业务数据，也没有重建当前数据库。新服务器的完整初始化和重启持久化验收，应按照指南在目标环境执行。

## 2. 修复登录页白屏

### 原因

服务和静态资源请求正常并不代表页面能够执行。原先按依赖包名称手工划分 vendor 文件，在 UI、Markdown 和工具依赖之间形成循环初始化，浏览器抛出 `Object.defineProperty called on non-object`，导致登录页空白。

### 处理

- 移除上述手工分包规则，由构建工具按照依赖关系处理模块初始化；保留页面动态导入。
- 为真实部署后的登录页增加浏览器回归测试：检查密码框与提交按钮、重定向参数、JavaScript 异常，以及切换浏览器标签页后返回和刷新页面。
- 在 [部署验收说明](deployment-acceptance.md) 中补充浏览器验收入口，明确不能只以构建成功或 HTTP 200 判断页面可用。

当前构建仍有大文件体积警告。此次解决的是模块初始化正确性，尚未完成首屏包体积优化。

## 3. 修复历史工具调用一直显示“处理中”

### 原因

历史记录中可能只有工具调用消息，没有工具结果。调用消息的 `completed` 表示消息已经送达，并不证明工具执行成功。原适配逻辑将没有结果的调用一直判定为执行中，导致已经结束的回复仍显示转圈、控制按钮并持续查询工具状态。

### 处理

- 将每条回复的生命周期传给其所属工具卡片，避免通过整段会话是否正在生成来误判旧工具的状态。
- 新增“已结束，未记录结果”状态：所属回复已经结束但没有工具结果时，停止显示执行中，也不显示成功标记。
- 保留已确认成功、失败、拒绝和中断的真实结果，兼容 `canceled` 与 `cancelled` 状态。
- 历史会话恢复时，仅将正在生成会话的最后一条当前回复标记为进行中；此前回复保持结束状态。
- 工具控制按钮及状态轮询仅在工具确实处于活动状态时启用。
- 增加中英文提示，以及适配器、工具卡片、回复生命周期和历史恢复回归测试。

历史工具回归使用实际构建的前端，拦截 API 后回放与问题记录一致的数据形状，验证切换标签页和刷新后状态稳定、工具不重复、无多余轮询。该测试不登录真实业务账户、不发送真实聊天消息，也不修改数据库；不能代替所有真实工具和审批场景的端到端验收。
