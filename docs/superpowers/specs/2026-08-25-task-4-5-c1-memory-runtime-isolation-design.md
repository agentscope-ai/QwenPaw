# Task 4.5-C/1 记忆运行效果与用户隔离设计

日期：2026-08-25  
状态：设计已逐节确认，等待书面规格复核后进入实施计划。  
范围：ReMe Light、ADBPG、自动记忆、记忆检索、梦境、Daily Paper、索引重建与记忆文件页面。  
非本任务范围：Agent Loop 综合运行效果、共享应用发布版本、会话存储全面迁移、全平台收件箱重构。

## 1. 目标

在不改变原有记忆功能语义的前提下，为多用户环境建立两层记忆：

1. Agent 公共记忆：由 Agent owner、collaborator 或管理员显式代管维护，使用者可只读检索。
2. 用户私有记忆：由当前用户在当前 Agent 下的对话产生，只能由该用户读取、检索、整理和删除。

必须保证：

- 多个用户使用同一个 Agent 时，自动提取的长期记忆不会互相串读或串写。
- 管理员只有平台治理能力，不获得读取其他用户私有记忆的能力。
- 记忆 Markdown 正文继续保留在文件系统，PostgreSQL 只保存归属、运行空间、状态、版本和生命周期元数据。
- 旧记忆不根据不可靠信息猜测用户归属。
- 记忆运行失败不能阻断正常对话，也不能退化为写入公共空间或 `shared` 空间。

## 2. 已确认的核心原则

### 2.1 双层记忆

```text
Agent 公共记忆
├─ workspaces/{agent_id}/MEMORY.md
├─ workspaces/{agent_id}/memory|daily|digest
└─ 公共 ReMe 索引

用户私有记忆
├─ user_workspaces/{user_id}/{agent_id}/memory
├─ user_workspaces/{user_id}/{agent_id}/daily|digest
└─ 用户私有 ReMe 索引
```

- Agent 配置继续使用原 Agent `agent.json`，不为每个用户复制配置。
- 旧 Agent workspace 中的记忆视为公共记忆。
- 新的对话衍生记忆写入当前用户在当前 Agent 下的私有运行空间。

### 2.2 运行时隔离方案

采用“每个记忆作用域独立运行时”：

- 每个 Agent 保留一个公共 ReMe 运行时。
- 每个活跃的 `user_id + agent_id` 组合按需创建私有 ReMe 运行时。
- 公共与私有运行时使用不同 workspace、文件目录、元数据目录和索引。
- 用户私有运行时按需启动并在空闲后释放，避免所有用户实例常驻。
- 搜索服务并行查询公共运行时与当前用户私有运行时，再进行结果合并。

不采用单实例目录过滤，因为一次过滤遗漏即可造成跨用户记忆泄漏；不采用 PostgreSQL 保存全部记忆正文，因为这会破坏已经确认的文件/数据库分层。

### 2.3 ADBPG 隔离

- ADBPG 每次存储与检索必须显式获得可信的登录 `user_id` 和目标 `agent_id`。
- 禁止将私有操作回退为 `_effective_user_id = "shared"` 或 `_effective_run_id = "shared"`。
- `run_id` 使用当前会话或运行 ID，便于追踪与去重，但权限隔离以 `user_id + agent_id` 为主。
- 缺少可信用户身份时，私有写入和私有检索直接拒绝。
- 旧 ADBPG `shared` 数据不自动归属任何用户，也不默认参与普通用户检索。

## 3. 数据与存储边界

### 3.1 PostgreSQL

新增或复用一个明确表示 Agent 用户运行空间的领域表（建议命名为 `agent_user_workspaces`）；现有 `shared_app_user_workspaces` 只服务共享应用发布版本，不直接承担普通 Agent 的私有记忆归属。不得为记忆正文新增数据库事实源。

最小元数据应包含：

- 用户 ID。
- Agent ID。
- 逻辑运行空间 ID。
- 作用域类型：`public` 或 `private`。
- 物理目录引用或受控相对路径。
- 生命周期状态：`active`、`access_revoked`、`cleanup_pending`。
- 索引状态：`ready`、`needs_reindex`、`reindexing`、`reindex_failed`。
- 索引版本或内容指纹。
- 创建、更新时间及最后访问时间。

物理绝对路径不通过普通用户 API 返回。

### 3.2 文件系统

- 公共记忆继续存放在 Agent workspace。
- 私有记忆存放在受控的用户运行空间根目录。
- 路径必须由统一 resolver 根据可信 `user_id + agent_id` 生成，调用方不能提交任意路径。
- 目录创建采用原子、安全权限设置，不跟随逃逸出运行空间的符号链接。
- 用户失去 Agent 权限后保留文件但禁止访问，状态改为 `access_revoked`。
- Agent 删除后用户运行空间进入 `cleanup_pending`，不立即物理删除。

### 3.3 可重建数据

Embedding、BM25、关键词索引、图缓存和状态统计均为可重建数据，不作为长期事实进入 PostgreSQL。索引失败不得删除 Markdown 正文。

## 4. 身份与请求上下文

记忆私有操作只能消费服务端认证后形成的上下文：

```text
MemoryScopeContext
├─ actor_user_id
├─ agent_id
├─ session_id / run_id
├─ scope: public | private
└─ governance: none | runtime-config
```

规则：

- `actor_user_id` 来自认证会话或可信频道身份映射，不能来自普通请求 body/query。
- 普通对话默认使用 `private` 作用域，并允许只读合并公共记忆。
- 管理员代管运行配置只允许 `public` 作用域。
- 自动化主体的定时梦境和 Daily Paper 只允许 `public` 作用域。
- 手动 `/dream`、`/memorize` 使用命令发起人的 `private` 作用域。
- 权限在任务开始和最终写入前至少各检查一次，避免任务运行期间授权被撤销后继续落盘。

## 5. ReMe 运行时结构

### 5.1 公共运行时

- 生命周期与 Agent 一致。
- 负责公共记忆文件、公共索引、定时自动梦境和 Daily Paper。
- owner、collaborator 与管理员显式代管可以查看状态和重建索引。
- 普通使用者只通过合并搜索读取公共结果，不能直接修改或重建公共索引。

### 5.2 私有运行时

- 缓存键为 `user_id + agent_id`。
- 首次自动记忆、私有搜索、手动梦境或用户进入“我的记忆”页面时按需创建。
- 仅加载该用户运行空间的 `daily`、`digest`、会话元数据和索引。
- 用户被禁用、全部会话被撤销、失去 Agent 使用权限或 Agent 删除时关闭运行时。
- 空闲释放只清理进程资源，不删除文件或索引。

### 5.3 检索合并

```text
当前请求
  ├─ 公共 ReMe search
  └─ 当前用户私有 ReMe search
        ↓
  标准化结果
        ↓
  按作用域 + 内容哈希 + 来源位置去重
        ↓
  统一排序与 max_results 截断
```

- 结果标记为“公共记忆”或“我的记忆”。
- 不向模型或前端暴露用户 ID、物理根目录和索引目录。
- 公共和私有内容相同也保留各自原始来源信息；去重只压缩重复展示，不删除文件。
- 一个作用域失败时允许返回另一个作用域结果，同时返回局部失败状态。

## 6. 业务操作路由

| 功能 | 作用域 | 输入来源 | 通知接收者 |
|---|---|---|---|
| 自动记忆 | 当前用户私有 | 当前用户当前 Agent 会话 | 当前用户 |
| 自动记忆搜索 | 公共 + 当前用户私有 | 当前用户问题 | 不单独通知 |
| 手动 `/memorize` | 当前用户私有 | 当前会话选择的消息 | 当前用户 |
| 手动 `/dream` | 当前用户私有 | 发起用户的私有记忆 | 当前用户 |
| 定时自动梦境 | Agent 公共 | Agent 公共记忆 | Agent owner |
| Daily Paper | Agent 公共 | Agent 公共主题配置 | Agent owner |
| 公共索引重建 | Agent 公共 | owner/collaborator/管理员代管 | 操作者和 Agent owner |
| 私有索引重建 | 当前用户私有 | 当前登录用户 | 当前用户 |

在收件箱尚不能保证接收用户隔离时，用户级通知必须跳过，不能退化为无接收人的全局广播。

## 7. 前端与 API

### 7.1 文件页面

记忆视图提供两个明确作用域：

- `公共记忆`
- `我的记忆`

公共记忆遵循 Agent 文件权限；我的记忆只解析当前登录用户的运行空间。

### 7.2 能力矩阵

| 操作 | Owner/Collaborator | 普通使用者 | 管理员显式代管 |
|---|---|---|---|
| 查看公共记忆 | 是 | 是，只读 | 是 |
| 编辑公共记忆 | 是 | 否 | 是 |
| 查看/编辑自己的私有记忆 | 是 | 是 | 仅管理员自己的记忆 |
| 查看其他用户私有记忆 | 否 | 否 | 否 |
| 重建公共索引 | 是 | 否 | 是 |
| 重建自己的私有索引 | 是 | 是 | 仅管理员自己的索引 |
| 删除公共记忆 | Owner/Collaborator | 否 | 管理员代管 |
| 删除自己的私有记忆 | 是 | 是 | 仅管理员自己的记忆 |

前端隐藏不是安全边界，所有 API 都必须根据服务端身份和作用域重新授权。

### 7.3 状态呈现

- 公共和私有作用域分别显示 `ready`、`needs_reindex`、`reindexing`、`reindex_failed`、`unavailable`。
- 私有运行时不可用时，对话仍可继续，但页面和当前用户运行状态应明确提示。
- 检索结果显示来源作用域，不显示敏感路径。
- 用户失去 Agent 权限后，“我的记忆”接口返回 403，页面不保留缓存内容。

## 8. 失败处理

- 私有运行时启动失败：继续对话，不执行私有记忆写入，不改写公共记忆。
- 公共检索失败：允许返回私有结果并标记公共检索失败。
- 私有检索失败：允许返回公共结果并标记私有检索失败。
- 自动记忆写入失败：不影响已经生成的回复，记录当前用户可见的失败状态并允许重试。
- 重建失败：保留旧索引和 Markdown，设置 `reindex_failed`，不得清除 `needs_reindex`。
- 权限在任务中途撤销：停止任务，最终落盘前拒绝写入，不发送完成通知。
- ADBPG 缺少可信用户：拒绝私有存储和检索，禁止回退到 `shared`。
- 运行时关闭失败：记录诊断信息，移出可复用缓存，下一次请求创建新实例；不得复用状态不明的实例。

## 9. 迁移策略

1. 扫描已有 Agent workspace 的 `MEMORY.md`、`memory`、`daily`、`digest` 和记忆索引元数据。
2. 现有 Markdown 原地保留并登记为公共记忆，不修改正文。
3. 不把旧内容自动归属管理员、owner 或任一普通用户。
4. 为公共作用域重建独立索引；重建失败保留旧文件和可用旧索引。
5. 用户首次产生或访问私有记忆时，创建用户运行空间登记和目录。
6. 新版本部署后 ADBPG 使用真实 `user_id + agent_id`。
7. 旧 ADBPG `shared` 数据停止参与普通用户检索；转为公共记忆需要后续独立的管理员审核流程，本任务不自动迁移。
8. 迁移脚本必须可重复执行，同一 Agent 或用户运行空间不得重复登记或重复移动文件。

## 10. 分步实施与确认门

### Task 4.5-C/1-A：作用域解析、目录与数据库登记

可见成果：用户进入“我的记忆”时只能解析自己的运行空间；公共和私有 API 返回明确作用域与状态。完成目录/数据库证据和越权测试后停止等待确认。

### Task 4.5-C/1-B：ReMe 公共/私有运行时与检索合并

可见成果：两个用户使用同一 Agent 写入不同私有记忆；各自搜索得到“公共 + 自己”，不能得到对方私有内容。展示运行时状态、文件和索引证据后停止等待确认。

### Task 4.5-C/1-C：ADBPG 真实用户隔离

可见成果：存储与搜索请求包含真实 `user_id + agent_id + run_id`；无身份请求被拒绝，代码中不存在私有操作的 `shared` 回退。使用模拟 ADBPG 服务或隔离测试服务验收后停止。

### Task 4.5-C/1-D：自动记忆与后台任务路由

可见成果：自动记忆、`/memorize`、手动梦境写入当前用户；定时梦境和 Daily Paper 只写公共记忆；通知接收人符合设计。逐项展示文件和收件箱证据后停止。

### Task 4.5-C/1-E：文件页、状态与重建入口

可见成果：页面可切换“公共记忆/我的记忆”；按钮、读写状态和重建权限符合角色矩阵；直接 API 无法绕过。真实页面验收后停止。

### Task 4.5-C/1-F：迁移与全角色阶段回归

可见成果：旧记忆保持公共且正文不变；owner、collaborator、管理员代管、普通使用者和无权限用户通过完整回归；所有临时数据恢复或清理后完成 C/1 确认门。

## 11. 测试策略

每个子任务遵循测试先行：

- 单元测试：作用域解析、路径约束、运行时缓存、结果合并、ADBPG 参数、任务路由和失败降级。
- 隔离测试：两用户同 Agent、同用户两 Agent、权限撤销、管理员代管和无授权访问。
- 集成测试：PostgreSQL 运行空间登记、文件写入、索引状态、幂等迁移和重启恢复。
- 前端测试：作用域切换、只读状态、错误清空、重建状态和权限变化。
- 真实页面：使用隔离验收实例生成唯一记忆标记，证明公共可见、私有互斥，并在 `finally` 恢复测试数据。

每项验收至少包含：

1. 前端可见结果。
2. 直接 API 权限结果。
3. 文件系统归属证据。
4. PostgreSQL 登记或状态证据。
5. 另一个用户和另一个 Agent 未变化的反证。
6. 失败路径与恢复结果。

## 12. 安全与工程约束

- KISS：复用现有 Agent 公共 ReMe 实例，新增最小的私有运行时池和统一 scope resolver。
- DRY：ReMe 与 ADBPG 共用 `MemoryScopeContext`，禁止各自重复解析用户身份。
- SOLID：作用域解析、运行空间登记、运行时生命周期、结果合并与页面 API 分离职责。
- YAGNI：不在 C/1 引入跨节点缓存、Redis、完整记忆正文数据库化或旧 ADBPG 自动归属工具。
- 不修改 Agent Loop 行为；该部分属于 Task 4.5-C/2。
- 不把共享应用不可变发布版本提前混入本任务；当前先按 Agent 公共/用户私有运行空间完成底层能力。

## 13. 完成标准

Task 4.5-C/1 只有同时满足以下条件才能完成：

- 公共和私有记忆具有独立文件根目录及独立 ReMe 索引。
- 两个用户使用同一 Agent 时，自动记忆、搜索、梦境和通知不串用户。
- ADBPG 私有操作不再使用 `shared` 用户或运行 ID。
- 管理员代管不能读取用户私有记忆。
- 公共和私有索引重建互不影响，失败不丢 Markdown。
- 旧记忆原地保留并作为公共记忆，迁移幂等。
- 页面提供可感知的作用域、状态和权限反馈。
- 自动化回归、真实页面验收和恢复证据齐全。
- 用户逐项确认 C/1-A 至 C/1-F。
