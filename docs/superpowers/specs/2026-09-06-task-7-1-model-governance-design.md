## 设计

### 1. 管理与使用接口分离

复用现有管理员能力 MODELS_MANAGE。供应商配置、模型目录编辑、探测、OAuth 配置及本地运行时操作均在服务端鉴权，前端菜单限制仅为交互辅助。用户目录以字段白名单提供模型标识、名称、能力、上下文长度和可用状态，不返回密钥、认证头或供应商连接配置。

管理员响应仅返回密钥已配置状态；编辑不回填旧密钥，未提交密钥表示保留，显式替换或清除有不同语义。覆盖正常返回、连接测试失败和异常响应中的敏感值。保留运行时内部读取凭据能力，不把面向用户的脱敏对象写回运行配置。

### 2. 会话模型覆盖

聊天选择必须绑定可信当前用户、Agent 和会话，服务端核验会话修改权；不能通过指定其他用户会话或伪造身份更新。持久化会话覆盖并在刷新时回显；未创建会话时选择仅作为新对话草稿，不修改 Agent 默认，也不继承到之后的新会话。

请求进入实际模型构造前统一解析：共享应用发布模型锁定；其他私人对话按会话覆盖、Agent 默认、平台兜底解析。没有覆盖和无效覆盖必须区分，后者拒绝。授权、可用性在服务端校验，不能仅依赖选择器过滤。保留已有 ReMe 自动跟随与显式指定模型规则，不由普通聊天切换写入全局配置。

### 3. 模型生命周期与兼容

删除前检查平台默认、Agent 默认和会话覆盖等现有引用，拒绝破坏性删除并给管理员可定位的引用信息。停用后新请求明确报错；不批量重写历史会话。沿用已有持久化机制；如实现必须新增数据库结构、迁移真实配置或升级依赖，先报告并请求确认。

多用户模式执行上述边界。Legacy 保留既有管理能力与可用功能；密钥不回读仍作为接口安全要求，不影响运行时使用真实凭据。

## 验证标准

1. 隔离测试覆盖管理员/普通用户、直接 API 调用、伪造会话/身份、用户目录字段白名单和错误脱敏。
2. 使用合成密钥验证保留、替换、清除及任何角色不可回读，不读取或输出真实密钥。
3. 两个用户使用同一可用 Agent，各自在自己的新测试会话选择模型，互不影响 Agent 默认、对方会话和平台默认；刷新后回显，新会话回到默认。
4. 无效、停用或未授权模型明确失败；共享应用锁定与公用 Agent 的规则分别覆盖。
5. 前端测试覆盖模型菜单、草稿、持久会话切换与失败不误报成功；后端覆盖解析与真实授权入口。浏览器验收使用 TASK71 标记的新会话，不修改现有会话。
6. 不安装本地模型、不向陌生供应商发送数据。实际连接测试若涉及真实付费调用或供应商配置变更，提前说明。
