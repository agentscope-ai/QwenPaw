# Task 4.5-A 运行配置访问与只读边界设计

## 1. 目标

在不改变原项目运行配置字段、存储方式和热重载行为的前提下，补齐多用户环境中的运行配置访问边界：所有者和协作者可以编辑，只有使用权的用户只能查看必要的有效配置摘要，管理员配置自己的 Agent 使用普通路径，代管他人 Agent 时必须显式展示代管状态并经过后端授权。

本任务同时保证前端交互限制和后端写接口限制一致，不能依靠隐藏按钮实现权限控制。

## 2. 范围

### 2.1 包含

- 为当前 Agent 暴露稳定的运行配置访问能力：`can_view`、`can_edit`、`is_governance` 和当前访问角色。
- owner 和 collaborator 可以读取并修改完整运行配置。
- 只有 `user` 使用角色的普通用户只能读取运行所需的有效配置摘要，不能读取或修改 Agent 草稿配置。
- 平台公用 Agent、仅使用分享 Agent 对普通使用者采用同一只读规则。
- 管理员编辑自己拥有或协作的 Agent 时沿用普通用户路径和权限语义。
- 管理员代管他人 Agent 时必须通过现有显式治理入口进入，并在运行配置页面展示代管提示。
- 所有运行配置写接口在后端统一执行授权校验；无编辑权时返回 `403 forbidden`。
- 前端根据服务端返回的能力决定是否加载完整表单、是否启用控件和是否显示保存操作。

### 2.2 不包含

- 不新增或修改数据库表。
- 不改变 `agent.json` 作为 Agent 运行配置内容源的现状。
- 不调整 Task 4.4-A 的配置版本和 `If-Match` 并发控制。
- 不调整 Task 4.4-B 的 `applied/pending_reload` 状态和重试机制。
- 不修改任何运行配置字段、默认值、校验规则、Embedding 回滚或 Agent 热重载流程。
- 不在本任务逐项验证全部配置卡片；逐卡片保真属于 Task 4.5-B。
- 不在本任务验证完整记忆运行效果；记忆与循环综合验收属于 Task 4.5-C。

## 3. 角色与能力矩阵

| 主体与关系 | 查看有效摘要 | 查看完整草稿配置 | 修改运行配置 | 页面状态 |
|---|---:|---:|---:|---|
| Agent owner | 是 | 是 | 是 | 正常编辑 |
| Agent collaborator | 是 | 是 | 是 | 正常编辑 |
| Agent user（仅使用） | 是 | 否 | 否 | 只读摘要 |
| 平台公用 Agent 的普通使用者 | 是 | 否 | 否 | 只读摘要 |
| 管理员自己的 Agent | 是 | 是 | 是 | 正常编辑 |
| 管理员协作的 Agent | 是 | 是 | 是 | 正常编辑 |
| 管理员显式代管他人 Agent | 是 | 是 | 是 | 代管编辑提示 |
| 无 Agent 使用权的主体 | 否 | 否 | 否 | 拒绝访问 |

管理员身份本身不等于所有 Agent 的隐式 owner。管理员查看和修改他人 Agent 必须从现有治理视图发起显式代管操作，并保留既有审计边界。

## 4. 后端设计

### 4.1 访问上下文

复用现有 Agent 授权解析能力，不在 workspace 路由重复实现 owner、collaborator、user、公用和治理判断。

定义面向运行配置页面的访问响应：

```json
{
  "agent_id": "agent-key",
  "access_role": "owner",
  "can_view": true,
  "can_edit": true,
  "is_governance": false
}
```

`access_role` 使用现有访问角色语义；管理员代管时 `is_governance=true`，但不伪造为 owner。

### 4.2 完整配置读取

现有完整运行配置接口只允许 owner、collaborator 或获得显式代管能力的管理员调用。只有使用权的用户调用时返回 `403`，避免把草稿字段、内部路径或非必要配置暴露给使用者。

### 4.3 有效配置摘要

新增或复用一个只读摘要接口，返回当前 Agent 运行所必需且可安全展示的信息。首期摘要保持最小集合，不复制完整 `AgentsRunningConfig`：

- Agent 标识和名称。
- 当前有效模型的展示信息，不包含供应商密钥。
- 当前语言和时区的展示值。
- 当前用户能否切换模型的能力标记。
- 配置访问能力和只读原因。

不返回工作目录绝对路径、Embedding 密钥、内部工具安全细节、完整记忆参数或其他草稿配置。

### 4.4 写接口统一授权

下列写操作必须在后端进入业务逻辑前校验 `can_edit`：

- 保存运行配置。
- 修改 Agent 语言。
- 修改 Agent 默认项目目录或编码能力。
- 重试运行配置热重载。
- Task 4.5-A 检查中发现的其他运行配置关联写接口。

授权失败统一返回 `403 forbidden`，不得执行文件写入、配置版本递增、热重载或数据库修订记录写入。

用户时区属于用户个人偏好，不是 Agent 草稿配置。普通用户仍可以修改自己的时区，不受 Agent 编辑权限制。

### 4.5 并发与热重载兼容

- 有编辑权的保存请求继续携带 Task 4.4-A 的 `If-Match`。
- 版本冲突仍返回 `409 config_version_conflict`。
- 保存成功后继续执行 Task 4.4-B 的运行时状态跟踪。
- 无编辑权请求在版本读取、配置写盘和热重载之前返回 `403`。

## 5. 前端设计

### 5.1 页面入口

进入运行配置页面时先读取访问上下文，再决定加载内容：

- `can_edit=true`：加载现有完整配置表单、版本和运行时状态。
- `can_view=true && can_edit=false`：加载有效配置摘要，不请求完整草稿配置。
- `can_view=false`：显示无权访问状态并停止后续请求。

这样可以避免先加载敏感草稿配置、再通过前端隐藏表单的错误顺序。

### 5.2 编辑状态

owner、collaborator 和管理员自己的 Agent 保持原有配置页面交互，不改变配置卡片布局、字段和保存按钮。

管理员显式代管他人 Agent 时，在页面标题下方显示持续可见的提示：当前正在代管配置、目标 Agent 及所有者信息。该提示不遮挡原有配置内容，也不改变保存流程。

### 5.3 只读状态

只有使用权的用户看到独立的只读摘要视图：

- 明确标识“仅使用，配置由所有者或管理员维护”。
- 展示安全的有效模型、语言、时区等摘要。
- 不渲染可编辑配置卡片。
- 不显示保存、重置和热重载重试按钮。
- 不提供技能、工具、MCP、记忆参数或运行开关的修改入口。

此处不是把完整表单设为 disabled，而是不向普通使用者请求或渲染完整草稿配置。

## 6. 错误处理

- 访问上下文返回 `403`：显示无权限页面，不继续加载配置。
- 摘要读取失败：显示可重试的加载错误，不回退请求完整配置。
- 完整配置读取意外返回 `403`：清空已加载草稿数据并切换到权限错误状态。
- 保存返回 `403`：提示权限已经变化并重新获取访问上下文。
- 保存返回 `409`：继续使用 Task 4.4-A 的版本冲突交互。
- 保存后热重载待处理：继续使用 Task 4.4-B 的黄色状态提示和重试逻辑。

## 7. 测试设计

### 7.1 后端

- owner 可以读取完整配置并保存。
- collaborator 可以读取完整配置并保存。
- user 可以读取有效摘要，但读取完整配置返回 `403`。
- user 保存配置返回 `403`，且配置文件、版本和重载函数均未变化或调用。
- 平台公用 Agent 的普通使用者遵循相同只读规则。
- 管理员编辑自己的 Agent 使用普通路径，`is_governance=false`。
- 管理员通过显式治理上下文代管他人 Agent 时可以编辑，`is_governance=true`。
- 管理员未进入治理上下文时不能静默修改他人 Agent。
- 用户修改个人时区不受 Agent 只读权限影响。

### 7.2 前端

- 可编辑主体加载完整配置页面并保留原有保存交互。
- 只读主体只请求访问上下文和有效摘要，不请求完整配置、版本或运行时重载状态。
- 只读页面没有保存、重置和重载按钮。
- 治理上下文显示代管提示。
- 权限在页面打开后被撤销时，保存 `403` 会刷新权限并停止编辑。

### 7.3 真实验收

在 `18089` 验收实例使用管理员和普通用户分别验证：

1. 管理员编辑自己的 Agent，页面和保存功能保持原样。
2. owner 编辑自己的 Agent，保存、版本控制和热重载正常。
3. collaborator 编辑被分享 Agent，保存正常但不能获得 owner 治理能力。
4. user 打开公用或仅使用 Agent，只看到摘要，无编辑控件。
5. user 直接调用运行配置写接口得到 `403`，配置内容和版本不变。
6. 管理员从“全部智能体”进入显式代管后看到代管提示，并可按既有审计规则保存。

## 8. 验收标准

- 前端只读与后端拒绝同时成立。
- 普通使用者无法通过直接 API 请求修改运行配置。
- 普通使用者不会收到完整 Agent 草稿配置。
- owner 和 collaborator 的原有配置能力不受影响。
- 管理员自己的 Agent 不出现代管提示。
- 管理员代管他人 Agent 必须显式进入治理上下文，并有明显页面提示。
- Task 4.4-A 并发冲突和 Task 4.4-B 待重载功能继续通过。
- 不新增数据库迁移，不修改原配置字段和存储边界。
