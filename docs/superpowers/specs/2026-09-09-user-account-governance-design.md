# 用户账户资料与治理交互设计

## 1. 背景与目标

当前多用户模式已经具备账号、平台角色、状态、认证会话和个人偏好，但账户资料仅包含用户名，普通用户缺少完整的个人资料维护和多用户改密入口，管理员也不能编辑用户资料或重置遗忘的密码。

本次实现以下目标：

1. 将当前用户入口固定在左侧导航底部。
2. 通过悬停浮层提供“账户信息”和“退出登录”操作。
3. 允许当前用户维护用户名和企业基础资料，并使用旧密码修改自己的密码。
4. 允许管理员维护任意用户资料和重置密码。
5. 将管理员“用户管理”移动到插件管理下方，作为设置区最后一项。

## 2. 范围

用户资料包含：

- 用户名 `username`
- 显示名 `display_name`
- 邮箱 `email`
- 手机号 `phone`
- 部门 `department`
- 职位 `job_title`
- 备注 `remark`

保留现有系统字段：稳定用户 ID、平台角色、状态、创建时间、更新时间、最后登录时间和密码哈希。

本次不增加工号、头像、直属上级和办公地点，不引入附件或头像存储。

## 3. 数据模型

直接扩展 PostgreSQL `users` 表，避免为固定的一对一资料引入额外联表：

| 字段 | 类型 | 约束 |
|---|---|---|
| `display_name` | `varchar(128)` | 可空，写入前去除首尾空白 |
| `email` | `varchar(254)` | 可空，写入前去除首尾空白并转小写，校验基本邮箱格式 |
| `phone` | `varchar(32)` | 可空，允许国际区号、空格、短横线和括号 |
| `department` | `varchar(128)` | 可空，写入前去除首尾空白 |
| `job_title` | `varchar(128)` | 可空，写入前去除首尾空白 |
| `remark` | `varchar(500)` | 可空，写入前去除首尾空白 |

空字符串统一保存为 `NULL`。用户名继续使用现有唯一约束；邮箱和手机号本次不加唯一约束，避免企业共享号码、邮箱别名和历史脏数据阻断升级。

新增迁移版本 `0019_user_account_profiles`。迁移只增加可空列，不改变现有账号、密码哈希、角色、状态和资源归属。

领域层 `UserRecord` 增加资料字段和时间字段，密码哈希继续只存在于内部 `CredentialRecord`，任何公开响应都不包含密码哈希。

## 4. 后端接口

### 4.1 当前用户资料

`GET /api/me` 在现有用户和偏好响应中增加资料与时间字段。

`PATCH /api/me/profile` 更新当前用户的用户名和资料：

```json
{
  "username": "alice",
  "display_name": "Alice Chen",
  "email": "alice@example.com",
  "phone": "+86 138-0000-0000",
  "department": "研发部",
  "job_title": "平台工程师",
  "remark": "多用户平台维护"
}
```

该接口不接受角色、状态、用户 ID 或密码字段。用户名冲突返回 `409 username_already_exists`，字段格式错误返回 `422`。更新成功后按用户 ID 保持当前会话有效，并让前端立即刷新认证用户缓存。

### 4.2 当前用户修改密码

`POST /api/me/change-password`：

```json
{
  "current_password": "old password",
  "new_password": "new password"
}
```

服务端验证旧密码，使用现有密码策略生成 Argon2id 哈希。旧密码错误返回 `400 current_password_incorrect`。修改成功后撤销该用户全部会话，前端清除本地访问状态并跳转登录页。

### 4.3 管理员维护用户

`PATCH /api/admin/users/{user_id}/profile` 更新目标用户的用户名和企业资料。只有 `users.manage` capability 可以调用，不能通过该接口修改角色或状态。

`POST /api/admin/users/{user_id}/reset-password`：

```json
{
  "new_password": "temporary password"
}
```

管理员不需要目标用户的旧密码。重置成功后撤销目标用户全部会话，并返回撤销数量；响应不回传密码或哈希。管理员给自己重置密码时，同样撤销自己的全部会话，前端返回登录页。

现有创建用户、角色调整、状态调整和会话撤销接口保持不变。

## 5. 安全与审计

- 自助改密必须验证当前登录用户的旧密码。
- 管理员资料编辑和密码重置必须经过服务端 `users.manage` 授权。
- 密码不写入日志、审计详情、前端持久存储或 API 响应。
- 用户名冲突在 PostgreSQL 唯一约束和领域错误映射两层处理。
- 自助改密和管理员重置密码均撤销全部会话。
- 审计记录包含操作者、目标用户、动作类型、请求 ID 和脱敏后的变更字段名；不记录字段旧值、密码或密码哈希。
- 禁用、删除或不存在的用户继续遵循现有治理错误语义。

## 6. 前端交互

### 6.1 左下角账户入口

侧栏使用纵向弹性布局：菜单区域独立滚动，账户入口位于底部固定区域。菜单增加或窗口高度缩小时，账户入口仍保持在左下角。

展开侧栏时显示用户图标、显示名（为空时回退用户名）和角色标签；折叠侧栏时只显示用户图标，并通过 Tooltip 展示名称。

鼠标悬停账户入口后，在其右上方显示 Popover：

- 账户信息
- 退出登录

点击“账户信息”打开居中账户弹窗；点击“退出登录”打开居中确认弹窗。移动端不依赖悬停，点击账户入口直接打开相同操作浮层。

### 6.2 账户信息弹窗

弹窗包含两个标签页：

1. “基本资料”：用户名、显示名、邮箱、手机号、部门、职位、备注。
2. “修改密码”：旧密码、新密码、确认新密码。

基本资料保存成功后更新全局认证状态和左下角显示。密码修改成功后提示会话已失效并跳转登录页。字段错误、用户名冲突和旧密码错误在对应表单字段附近显示。

### 6.3 退出确认

退出操作使用居中确认弹窗，明确说明只退出当前设备。用户确认后调用现有 logout 接口、清理用户范围缓存并跳转登录页；取消时不产生请求。

### 6.4 管理员用户管理

用户列表增加显示名、部门、职位和最后登录时间。窄屏保留用户名、显示名、角色和状态，其余字段放入详情或横向滚动区。

每个用户操作区增加：

- 编辑资料：复用与个人资料一致的字段和校验。
- 重置密码：输入新密码和确认密码，提交前显示会话将被撤销的提示。

管理员重置其他用户密码后停留在当前页面；重置本人密码后清理认证状态并跳转登录页。

菜单注册顺序调整为插件管理之后再显示用户管理。权限过滤逻辑保持不变，普通用户仍看不到用户管理。

## 7. 组件边界

- `AccountPopover`：只负责左下角入口和两项动作。
- `AccountProfileModal`：负责当前用户资料与自助改密表单。
- `LogoutConfirm`：封装退出确认，不持有认证状态。
- 管理员用户页面的资料与重置弹窗保持在用户管理功能目录内。
- 前后端共享字段类型分别集中在现有认证 API 类型和用户治理 API 类型中，避免重复定义不同形状。

## 8. 测试与验收

后端测试覆盖：

- Repository 正确读写新增字段并处理空字符串。
- 当前用户更新本人资料，不能修改角色、状态或其他用户。
- 用户名冲突和资料格式校验。
- 自助改密要求正确旧密码，成功后撤销全部会话。
- 管理员可编辑资料和重置密码，普通用户请求返回 `403`。
- 管理员重置后旧密码失效、新密码可登录、旧会话失效。
- API 和审计响应不包含密码及密码哈希。

前端测试覆盖：

- 长菜单和不同窗口高度下账户入口固定在侧栏底部。
- 悬停和移动端点击可打开账户操作浮层。
- 账户资料保存后更新左下角名称。
- 自助改密旧密码和两次新密码校验。
- 退出登录在确认前不发请求，确认后才调用 logout。
- 管理员编辑资料、重置密码及本人重置后的退出行为。
- 用户管理位于插件管理之后，普通用户看不到该菜单。

真实验收使用两个隔离浏览器上下文分别登录管理员和普通用户，验证资料隔离、自助改密、管理员重置、会话撤销、菜单顺序和固定底部布局。验收完成后恢复测试账号密码，避免破坏现有验收凭据。

## 9. 兼容与发布

- Legacy 单用户模式继续使用现有账户更新逻辑，不读取新增多用户资料接口。
- 多用户接口仅在 `QWENPAW_MULTI_USER_ENABLED=true` 时启用。
- 前端根据认证模式显示多用户资料表单；Legacy 模式保持现有账户能力。
- 数据库迁移向前兼容且不删除数据；部署时先执行迁移，再启动新版本服务。
