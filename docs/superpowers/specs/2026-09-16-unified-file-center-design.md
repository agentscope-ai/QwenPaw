# 统一文件中心与记忆可见性设计

日期：2026-09-16  
状态：设计稿，等待用户书面复核  
范围：文件中心五类内容、记忆只读可见、对话文件预览、文件定位协议、收件箱记忆跳转、原始工作区入口收敛。  
不在范围：改变 ReMe 提取与检索算法、修改四类文件的物理隔离规则、把记忆正文迁入数据库、操作系统级 Shell 沙箱。

## 1. 背景与已确认问题

当前底层同时存在两组合理但用途不同的领域：

1. 文件生命周期：临时附件、个人资料库、Agent 资料、产物。
2. 记忆系统：公共/私有作用域下的 daily memory 与 digest memory。

前端没有明确区分这两个领域，而是同时提供两套导航：

- 独立文件页显示“临时附件、个人资料库、Agent 资料、产物”。
- 对话文件预览展开后显示“工作区、档案、日记、知识库”。

由此产生以下问题：

- “档案”与“Agent 资料”指向同一组受管理配置文件，却使用不同名称。
- “知识库”实际指 ReMe `digest`，容易与“个人资料库”混淆。
- “工作区”直接暴露 `mem_agent`、`mem_session`、`credentials.yaml`、`history.db` 等内部文件。
- 对话预览使用 session scope 时不加载记忆作用域，记忆范围保持默认 `public`；`/memorize` 写入 `private` 后，页面因此显示“无可用文件”。
- 收件箱的自动记忆通知没有结构化文件定位，用户看到文件名却无法打开文件。
- 对话预览与独立文件页使用不同导航和读取分支，同一文件的可见范围和打开结果不一致。

本设计将普通用户文件入口收敛为一个文件中心，不改变已经完成的用户、Agent、会话和记忆作用域隔离。

## 2. 目标

统一后的产品必须满足：

- 用户只需理解一套五类文件导航。
- 当前用户可以查看自己在当前 Agent 下的记忆 Markdown；第一阶段为只读。
- 有 Agent 使用权限的用户可以只读查看公共记忆。
- 对话中的预览、展开查看、文件中心打开使用同一文件身份和同一授权结果。
- 普通用户界面不显示内部运行目录、凭据文件、索引文件和物理绝对路径。
- 收件箱中的记忆结果可以直接打开对应记忆文件。
- 已登记产物只显示一个逻辑条目，源文件与不可变快照不显示为两个产物。

## 3. 统一信息架构

文件中心固定提供五个一级页签，默认打开“临时附件”：

```text
文件
├─ 临时附件
├─ 个人资料库
├─ 产物
├─ Agent 配置
└─ 记忆
```

### 3.1 临时附件

显示当前登录用户在当前 Agent 中上传、尚未长期保存的文件。文件继续按上传会话隔离。用户可以下载、删除或显式保存到个人资料库。

### 3.2 个人资料库

显示当前用户 × 当前 Agent 的长期参考资料。只接受用户明确上传或“保存到个人资料库”的文件，不自动接收生成产物或记忆文件。

### 3.3 产物

显示当前用户在当前 Agent 中由对话生成并登记的交付文件。每个逻辑产物展示：

- 文件名、类型、大小和生成时间。
- 来源对话标题与时间。
- 查看、下载、删除、保存到个人资料库。
- 可选的“打开来源对话”。

会话源文件与 `.registered` 快照是一个逻辑产物的两个内部阶段。列表只返回登记记录，不扫描并同时展示两份物理文件。

### 3.4 Agent 配置

“Agent 资料”统一改名为“Agent 配置”。这里只显示 Agent 身份与行为配置文件：

- `AGENTS.md`
- `SOUL.md`
- `PROFILE.md`
- `HEARTBEAT.md`
- `MEMORY.md`
- `BOOTSTRAP.md`（存在时）

普通使用者只读。Agent owner、collaborator 和管理员显式代管按既有权限编辑并设置是否加入系统提示词。页面说明这些文件是工作区的受管理配置子集，不代表完整工作区。

### 3.5 记忆

记忆作为第五类内容进入文件中心，不再隐藏在通用工作区浏览器中。页面提供两级导航：

```text
记忆
├─ 我的记忆（默认）
│  ├─ 日记记忆
│  └─ 长期记忆
└─ 公共记忆
   ├─ 日记记忆
   └─ 长期记忆
```

名称与目录映射：

| 页面名称 | 作用域 | 当前目录语义 |
| --- | --- | --- |
| 我的记忆 / 日记记忆 | private | 当前用户 Agent 私有运行空间中的 `memory` 或配置的 `daily_dir` |
| 我的记忆 / 长期记忆 | private | 当前用户 Agent 私有运行空间中的 `digest` 或配置的 `digest_dir` |
| 公共记忆 / 日记记忆 | public | Agent 公共工作区中的 `memory` 或配置的 `daily_dir` |
| 公共记忆 / 长期记忆 | public | Agent 公共工作区中的 `digest` 或配置的 `digest_dir` |

不再使用“日记”和“知识库”作为一级来源名称。“知识库”从本功能中移除，避免与个人资料库产生歧义。

记忆列表按日期和修改时间组织，展示标题、摘要、创建时间、来源对话和作用域。文件正文第一阶段全部只读；不在本任务中开放直接编辑和删除，以免绕过 ReMe 的索引与生命周期管理。

## 4. 用户与权限边界

| 内容 | 当前用户 | 普通 Agent 使用者 | Agent owner/collaborator | 管理员代管 |
| --- | --- | --- | --- | --- |
| 自己的临时附件 | 管理 | 管理自己的 | 管理自己的 | 管理自己的 |
| 自己的个人资料库 | 管理 | 管理自己的 | 管理自己的 | 管理自己的 |
| 自己的产物 | 管理 | 管理自己的 | 管理自己的 | 管理自己的 |
| Agent 配置 | 按 Agent 角色 | 只读 | 可编辑 | 显式代管可编辑 |
| 自己的私有记忆 | 只读 | 只读自己的 | 只读自己的 | 只读管理员自己的 |
| 其他用户私有记忆 | 禁止 | 禁止 | 禁止 | 禁止 |
| 公共记忆 | 只读 | 只读 | 只读 | 只读 |

本任务只收敛查看入口，不扩大私有数据权限。前端页签、URL 和隐藏按钮均不是安全边界，所有读取接口继续根据认证用户、目标 Agent 和作用域在服务端授权。

## 5. 统一文件定位协议

所有入口使用同一个逻辑文件定位对象 `FileLocator`，不向前端传递物理绝对路径：

```text
FileLocator
├─ category: attachment | library | artifact | agent_config | memory
├─ agent_id
├─ stable_id?               # 已登记对象使用
├─ relative_path
├─ conversation_id?        # 产物或会话附件
├─ memory_scope?           # public | private
└─ memory_section?         # daily | digest
```

规则：

- `stable_id` 对产物使用 artifact ID，对附件和个人资料使用其登记 ID；记忆和配置使用作用域内的受控相对路径，不新增登记表。
- `relative_path` 只在已解析的领域根目录中使用，不允许客户端提交文件系统根目录。
- 用户 ID 只从认证上下文取得，不进入可伪造的 query/body。
- `conversation_id` 用于来源显示和会话授权，不直接拼接物理路径。
- 文件中心、对话预览、收件箱和聊天引用共同消费 `FileLocator`。

推荐的文件中心深链接格式：

```text
/files?agentId=<agent>&category=<category>&item=<stable_id>
```

记忆文件增加：

```text
&memoryScope=private&memorySection=daily
```

路由参数只用于定位；后端仍重新解析归属和授权。

## 6. 对话文件预览

### 6.1 预览态

用户在对话中点击文件后，左侧只显示：

- 文件名称与类型。
- 文件正文、图片、PDF 或 HTML 预览。
- 下载。
- “在文件中心打开”。
- 关闭。

不再显示“工作区、档案、日记、知识库”。

### 6.2 展开态

“展开”不切换到原始工作区浏览器，而是嵌入与独立文件页相同的五类文件中心，并根据 `FileLocator` 自动选中对应页签和文件。独立文件页与展开态复用同一个导航组件、数据查询和授权逻辑。

### 6.3 原始工作区

原始工作区浏览器从普通文件流程中移除。确有排障需求时，仅在管理员“调试”页面提供独立高级入口，并额外限制：

- 不显示或读取 `credentials.yaml`、`.mcp` 等凭据文件。
- 默认隐藏 `mem_agent`、`mem_metadata`、`mem_session`、`sessions`、`history.db` 和锁文件。
- 不把高级工作区的文件自动视为产物或个人资料。

## 7. 记忆可见性与当前缺陷修复

### 7.1 记忆作用域

文件中心的记忆页始终以 `scope.kind = agent` 获取可用作用域；默认优先选择 `private`，若当前用户没有 private 作用域才回退 `public`。

对话预览不再自行维护 `memoryScope`。当预览目标是记忆时，目标携带明确的 `memory_scope` 与 `memory_section`，展开后交给统一文件中心加载。

这会修复当前 session scope 不加载 memory scopes、默认查询 public、私有记忆显示为空的问题。

### 7.2 列表与索引解耦

记忆 Markdown 列表直接从已授权的作用域目录读取。即使 ReMe 搜索索引处于 `needs_reindex` 或 `reindex_failed`，文件仍应可见并可只读打开；页面单独显示索引状态，不把索引失败误报为“无文件”。

### 7.3 空状态与错误

- 目录确实为空：显示“当前范围暂无记忆文件”。
- 没有 Agent 权限：403，并清空已缓存正文。
- 记忆运行空间不可用：显示作用域不可用，不回退读取公共或其他用户目录。
- 文件已被后台整理或移动：刷新列表并提示“记忆文件位置已更新”。
- 索引不可用：文件仍可浏览，检索状态单独提示。

## 8. 收件箱记忆跳转

`auto_memory`、手动 `/memorize`、手动 `/dream` 的成功事件增加：

```text
agent_id
memory_scope
memory_section
memory_path
source_conversation_id
```

收件箱详情根据结构化字段显示“查看记忆”和“打开来源对话”。旧事件没有结构化字段时继续展示文本，不根据正文中的文件名猜测路径。

后台任务写入成功但通知写入失败时不回滚记忆文件；通知失败记录诊断信息。通知成功但文件随后被整理或删除时，打开动作刷新列表并明确提示原路径已失效，不猜测同名文件。

## 9. 产物源文件与登记快照

当前产物目录继续保持：

```text
user_workspaces/<user>/<agent>/
  artifacts/<conversation>/...       # 会话源文件
  artifacts/.registered/<record>/... # 登记快照
```

两份物理文件服务于不同生命周期，不代表两个逻辑产物：

- 会话源文件便于 Agent 在当前会话继续修改。
- 登记快照保证下载、预览和历史记录不随源文件变化。

文件中心只展示数据库中的产物登记记录。预览和下载优先读取登记快照；“继续编辑”如后续需要，再显式复制到当前会话输出目录。本设计不新增“继续编辑”。

## 10. 组件边界

前端建议拆分为：

- `UnifiedFileCenter`：五类一级导航和深链接状态。
- `FilePreviewPane`：只负责单个文件预览与通用操作。
- `MemoryPanel`：公共/我的记忆、日记记忆/长期记忆和只读列表。
- `AgentConfigPanel`：受管理 Agent 配置文件及提示词开关。
- 现有 `TemporaryAttachmentsPanel`、`PersonalLibraryPanel`、`ArtifactPanel` 继续复用。
- `FileLocator` 与打开动作集中在单一模块，替代各入口按 `source` 自行分支。

后端继续复用现有附件、个人资料、产物、工作区记忆 API；只补充统一文件描述和记忆事件定位字段，不建立能够任意读取五类物理路径的通用文件接口。

## 11. 兼容与迁移

- 不移动现有附件、资料库、产物、Agent 配置或记忆正文。
- 不修改现有 user × Agent 目录结构。
- 已有聊天文件链接继续解析，并在解析后转换为 `FileLocator`。
- 旧收件箱事件保持只读展示，没有路径时不提供跳转按钮。
- 原“档案、日记、知识库”标签从普通界面移除；API 的 `daily`、`digest` 字段作为内部兼容名称保留。
- 浏览器中已经打开的旧工作区标签在版本升级后关闭，不把旧标签状态迁入新的五类文件中心。

## 12. 验证与验收

### 12.1 文件中心

- 五个一级页签名称、顺序和空状态一致。
- 切换 Agent 后五类内容同时切换，不残留上一 Agent 的缓存。
- 普通用户看不到物理绝对路径和内部运行目录。

### 12.2 记忆

- 用户 A 在 Agent X 执行 `/memorize` 后，可在“记忆 → 我的记忆 → 日记记忆”看到并打开文件。
- 用户 B 使用同一 Agent X 时看不到用户 A 的私有记忆。
- 用户 A 可以只读查看 Agent X 的公共记忆。
- 索引不可用时文件仍可浏览。
- 管理员代管不能借此查看其他用户私有记忆。

### 12.3 对话预览一致性

- 对话预览和文件中心打开同一 `FileLocator` 时，文件内容、名称和授权结果一致。
- 点击“在文件中心打开”一次即可定位到正确分类和文件。
- 预览和展开态均不出现“工作区、档案、日记、知识库”旧导航。
- HTML、Markdown、图片和 PDF 均通过登记文件接口正常预览和下载。

### 12.4 产物

- 同一内容的源文件和登记快照只显示一个逻辑产物。
- 产物明确显示当前 Agent 与来源对话，不显示用户 UUID 和绝对目录。
- 删除产物后自动扫描不会将墓碑记录重新登记。

### 12.5 收件箱

- 新的自动记忆通知可直接打开对应记忆。
- 来源对话存在时可直接返回该对话。
- 旧通知仍能查看，不出现错误跳转。

## 13. 完成标准

以下条件全部满足后，本次优化才算完成：

1. 独立文件页和对话展开态共用五类文件中心。
2. 私有记忆文件对所属用户只读可见，公共记忆对有权使用 Agent 的用户只读可见。
3. “工作区、档案、日记、知识库”不再作为普通用户文件导航。
4. 对话文件预览不暴露内部工作区内容。
5. 收件箱新记忆通知可以定位文件。
6. 原有多用户文件、产物和记忆隔离测试继续通过。
7. 青岛 HTML 等历史登记产物可以从对话和文件中心打开同一逻辑产物。
