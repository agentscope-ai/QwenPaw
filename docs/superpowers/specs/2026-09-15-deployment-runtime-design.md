# 多用户部署与服务运行设计（2026-09-15 已确认）

## 目标和现状

为当前多用户、多智能体平台提供正式部署和运维入口，支持 Windows 本机运行和 Linux 服务器部署。日常运行不依赖 tmp 中的脚本或 Codex 缓存路径。

现有 qwenpaw app 是前台应用命令；daemon restart 只打印说明，不是操作系统进程管理。根目录 docker-compose.yml 使用上游镜像，没有配置当前多用户数据库。当前实例的数据目录位于 tmp/task-2-1-acceptance，数据库为 qwenpaw_test_migrations，schema 为 qwenpaw_task21_acceptance，端口为 18089。

## 方案取舍

1. 推荐：新增正式 service CLI，复用 qwenpaw app；部署模板和文档统一配置约定。保留 Windows 原生工具能力，并支持 Linux。
2. 仅移动 PowerShell 脚本：工作量小，但仍缺跨平台运行和完整进程管理，不满足本次目标。
3. 全部容器化：服务器托管简单，但现有智能体使用 Windows 命令、宿主路径和工具，需要额外迁移验证，不作为本机强制切换方案。

## 正式入口

拟新增 qwenpaw service 命令组：init、check、run、start、stop、restart、status、logs。

- init：生成配置模板，拒绝覆盖已有配置。生成配置不等于初始化数据库。
- check：检查配置、解释器、Git、前端资源、数据库连通性与版本，以及多用户存储切换状态。
- run：按同一配置前台启动，供故障诊断和操作系统托管使用。
- start：后台启动，重复调用不重复创建进程；启动失败返回非零退出码与日志位置。
- stop/restart：核验进程身份和创建时间后操作，防止 PID 复用或端口冲突误停其他服务。优先正常关闭，超时终止需明确报告。
- status：区分未运行、启动中、就绪、异常；不能只凭首页 HTTP 200 判定数据库和智能体已就绪。
- logs：查看应用日志与启动错误，支持末尾行数及持续输出。

上述为拟实现接口，当前不能当作已有命令执行。

## 配置与数据布局

- deploy/：提交到仓库的配置示例、容器构建和服务器托管模板。
- docs/deployment.md：正式中文部署运行手册，并从 README_zh.md 与 scripts/README.md 链接。
- 实例配置与密码：存放在 Git 忽略的本机配置中；模板不包含真实账号或数据库密码。
- 新实例使用明确指定的持久目录，分别保存 working、secrets、backups、logs 和进程状态文件。
- 配置覆盖解释器、监听地址、端口、数据库、schema、工作目录和可选工具路径；禁止写死开发者盘符和 Codex 专属依赖。
- 配置必须在应用模块导入前生效，因为现有路径常量在导入时解析。管理命令应采用隔离子进程传递配置，避免父进程已导入常量造成串实例。

## 全新部署与现有实例接管

文档分别描述两条流程：全新安装和现有实例接管。

全新安装涵盖依赖、前端构建、数据库创建和版本升级、管理员初始化、多用户切换校验、模型配置与首次登录。复用现有迁移代码和密码哈希逻辑，不复制实现。不得通过无条件设置 CUTOVER_* 为 all 来冒充验收通过。

现有实例首先生成正式配置，指向已存在的数据库和数据位置，由新命令接管运行。此阶段不更换数据库，不自动创建新管理员。

数据迁出 tmp 作为显式迁移步骤：列出实际数据量和数据库/配置中的路径引用，生成备份与路径映射，停服复制，更新引用并验证，失败可以切回旧配置。执行数据批量更新前按项目规则单独确认；旧目录不自动删除。最终文档必须明确是否仍有数据位于旧目录，不能把入口迁移宣称为数据迁移完成。

## 长期运行和升级

提供 Windows 开机运行模板和 Linux systemd 模板；安装自启动是显式步骤，日常启动不自动修改系统设置。Linux 容器部署从当前源码构建，包含 PostgreSQL、持久卷和健康检查，不假定上游 latest 包含本地多用户改动。

手册覆盖启动、停止、重启、状态、日志、升级前备份、前后端同步更新、数据库升级、恢复与回滚条件，以及端口冲突、缺失模型、数据库不可用和前端旧资源排查。数据库升级不自动混入普通 start。

## 验收

- 管理命令帮助、配置优先级、敏感字段脱敏、路径含空格和中文。
- 重复启动、端口占用、失效 PID、错误配置、启动超时和数据库不可用。
- 停止后无残留服务；重启后加载同一实例；新建用户、聊天、智能体资料不丢失。
- 新安装数据库初始化与管理员引导在隔离环境验证，不改现有验收库。
- 本机 Windows 实际验证正式入口并检查登录、当前智能体和模型；Linux/容器部分单独标注静态检查和实机验证范围。
- README 展示的每个新增日常命令均与实际 --help 一致。
