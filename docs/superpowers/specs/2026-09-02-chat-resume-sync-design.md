# 聊天页面恢复焦点同步优化设计

## 目标

消除用户从其他应用切回浏览器时聊天区域无条件重建造成的闪动，同时保留后台回复完成后自动呈现最新消息的能力。

## 根因

聊天页在 `visibilitychange`、`focus` 和 `pageshow` 后读取后端会话。现有逻辑把后端 `idle` 本身视为必须刷新，而正常完成的会话长期处于 `idle`，因此每次恢复焦点都会递增 `refreshKey`，使 `AgentScopeRuntimeWebUI` 被 React 卸载并重新挂载。

## 设计

新增一个无副作用判定函数，只有以下情况返回 `true`：

1. 后端消息数大于前端消息数，表示后台产生了尚未加载的新消息；
2. 前端仍显示运行中，而后端已处于 `idle`，表示隐藏期间运行刚刚结束。

前后端都空闲且消息数量一致时返回 `false`。现有三个浏览器恢复事件和 1.5 秒去重保留，避免扩大改动范围。

## 边界

- 不修改会话 API、数据库或第三方聊天组件。
- 不移除后台恢复同步。
- 不在本任务处理访问令牌过期后的静默刷新。

## 验证

- 单元测试覆盖空闲一致、新增消息、运行结束、仍在运行四类状态。
- 执行聊天页相关测试、TypeScript 编译和生产构建。
- 使用真实浏览器切换标签页，确认聊天组件不再闪动且页面 URL 不变。
