## 方案选择

推荐复用五张现有表与现有 Driver Runtime：数据库保存多用户事实，DriverCard 作为可重建运行物化结果，Legacy 保留文件 Adapter。改动范围与原架构一致，避免维护两套运行时。

仅加固 YAML 权限虽然改动小，但不满足已确认的数据库事实来源；全部重写 MCP Runtime 与 OAuth 则扩大回归范围且无当前必要性。因此不采用这两种方案。

## 权限与凭据

1. owner/collaborator 配置 Agent MCP；仅使用者保留工具调用及调用发现能力，不返回配置材料、凭据引用详情或其他用户会话信息。管理员普通路径遵循原 Agent 权限，代操作沿用现有显式治理入口。
2. Credential Store 对管理层提供 create、replace、revoke、status、bind；运行时解密仅限内部已验证的 Agent/consumer/purpose 绑定，不提供明文读取 HTTP API。
3. 复用现有加密实现和数据库外主密钥。密文带现有 key_version；本任务不轮换主密钥，不改模型或频道凭据。
4. 前端逐项显示已配置状态；编辑使用 keep/replace/delete。未编辑保存保留秘密，replace 必须提供新值，delete 明确移除，不再以掩码字符串推断操作。
5. headers/env 值按秘密处理；配置 JSON、响应、错误和日志不含原秘密片段。URL/args 等配置中的凭据不能因字段名称不同而落入普通 JSON；导入前检查并拒绝不可安全分离的内嵌凭据，返回字段级安全错误。
6. 凭据撤销是逻辑状态变化，保留绑定影响信息；运行解析不得复用撤销前缓存。并发替换/撤销必须在同一事务与版本规则下处理。

## 配置事实与运行时

- agent_drivers 保存 Agent 归属和当前修订；driver_revisions 保存非秘密配置、白名单、策略和内容哈希。凭据绑定按 static/oauth 等 purpose 区分，不依赖一个单值字段表示所有绑定。
- 创建、编辑、凭据绑定及修订推进必须事务化。并发编辑使用预期修订检查，冲突返回可恢复错误，不覆盖其他协作者修改。
- 提交后重载现有 DriverManager；重载失败明确显示“已保存、未生效”，保留可重试状态，不能把失败包装为已运行。
- 多用户已切换 Agent 禁止 YAML watcher 覆盖数据库配置；物化失败可以从数据库重建。Legacy 模式仍按文件契约运行。
- 白名单的 `null`（全部工具）与 `[]`（零工具）必须保持差异，不能因数据库默认空数组丢失原语义。
- 保留自动调用、斜杠命令、异步工具过程、审批及 ToolCards；实际调用审批沿用统一 approval_requests 和真实调用用户。

## OAuth 会话

- 开始授权时记录 driver_id、initiated_by、state_hash、过期时间和 pending 状态；仅返回协议必需的授权信息。
- PKCE verifier 短期保留进程内，不写明文数据库；进程重启后未完成授权安全失效，页面允许重新授权。本任务不实现跨进程恢复授权。
- 回调原子消费 state，并在保存 Token 前复核发起用户仍有效、仍有目标 Agent 编辑权、目标 Driver 未删除或被替换。过期、重放、撤权及不匹配回调均失败。
- Token、绑定与 Driver 修订事务保存；错误转为固定安全消息，不能回显上游响应、code、Token 或宿主绝对路径。
- 前端监听授权完成消息时校验来源与当前发起会话；切账户、Agent 或关闭后不应用迟到结果。

## 原数据与切换门

本任务不静默导入 6 项原 MCP，也不把旧文件当作可删除缓存。实施时先完成只读预览：逐 Agent 配置映射、引用完整性、哈希、重名冲突、缺失所有者、待导入数量和拒绝项。预览不得输出秘密。

测试与页面闭环先在独立环境完成。原环境导入/事实来源切换须依据具体预览单独获得危险操作确认，随后备份、幂等导入、核对数量/哈希，再开放数据库写入口。新事实写入开放前可取消切换；开放后不能直接回退旧 YAML 导致新数据丢失。遗留文件与备份保留。

预计无需新增表。实际若发现必须新增 RLS、约束或字段，先说明具体必要性并按原确认规则处理，不暗中扩大迁移。

## 验收标准

- owner/collaborator 创建与编辑生效；user 可调用而不可配置；另一 Agent、另一用户不可借用凭据。
- 秘密未编辑保存、替换、删除、撤销及引用影响展示正确；API/日志/SSE/前端存储不回显秘密。
- OAuth 成功、取消、过期、重放、撤权、Driver 删除/替换和切账户迟到响应均有真实链路证据。
- 两个协作者并发编辑不会丢失更新；数据库提交失败不留下可调用孤儿绑定；重载失败可见并能恢复。
- 白名单、访问策略、自动调用、斜杠命令和真实用户审批保持原语义及事件展示。
- 独立 PostgreSQL 和本机协议服务演示实际配置、授权及调用，至少双账户浏览器验证；不以商业 OAuth 服务可用性作未经验证的承诺。
- Legacy 合同、受影响回归、前端类型检查与构建通过。已存在失败单列，不能算作通过。
- 6 项原 MCP 与其他领域数据有保真证据；任何原环境迁移均留确认、预览和结果记录。

## 设计自检

本设计复用既有存储和审批体系；新增仓储单独负责事务，API 单独负责授权和投影，运行时只消费已验证配置，符合 KISS、DRY 和单一职责。OAuth 重启恢复与新的凭据管理中心没有当前需求，不在本轮增加。具体设计确认后细化逐文件实施计划。
