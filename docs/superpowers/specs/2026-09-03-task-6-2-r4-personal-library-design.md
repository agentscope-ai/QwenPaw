# Task 6.2-R/4 用户个人资料库设计

> 历史设计：本文的“跨 Agent 个人库授权”已被用户后续确认的“用户 × Agent 独立个人资料库”替代，不再作为当前实现要求。当前四类文件边界及生成产物规则见 [四类文件存储说明](../../file-storage.md)。保留正文用于追溯历史决策。

日期：2026-09-03  
状态：设计已逐段确认，等待书面设计复核

## 1. 目标

为每个用户提供独立、跨会话、跨 Agent 复用的个人资料库，并通过显式授权让用户可使用的 Agent 按需只读访问。

本任务必须同时满足：

- 用户资料在物理存储、数据库元数据、接口授权和 Agent 运行时四层隔离；
- 管理员不因平台角色自动获得用户私人资料读取权限；
- 公用、协作和仅使用 Agent 均不能修改用户个人资料；
- 不改变现有公共记忆、个人记忆、ReMe、Agent 资料和产物的职责；
- 前端功能和后端权限在同一子任务中交付并可视化验收。

## 2. 范围边界

### 2.1 本任务实现

- 用户个人资料库文件管理；
- 从临时附件、个人运行空间或产物显式复制资料；
- 用户向自己可使用的 Agent 授予或撤销整库只读权限；
- Agent 对已授权资料进行按需搜索和分页读取；
- 双普通用户使用同一公用 Agent 时的端到端隔离。

### 2.2 本任务不实现

- Agent 自动写入个人资料库；
- 单文件或单目录授权；
- 回收站、版本历史或批量文件操作；
- 二进制文件全文提取、OCR 或新的向量数据库；
- 管理员代替用户查看或维护私人资料；
- Task 6.2-R/5 负责的 Agent 产物来源和保留生命周期治理。

## 3. 上下文模型

一次 Agent 对话可以使用四层信息：

1. 当前 Agent 的公共记忆；
2. 当前用户在该 Agent 下的个人记忆；
3. 当前会话上下文；
4. 当前用户显式授权给该 Agent 的个人资料库。

公共记忆与个人记忆继续由现有记忆中间件和 ReMe 链路检索，只把相关片段临时注入模型上下文。个人资料库不替代记忆体系，也不由 `/dream`、`/memorize` 或自动记忆写入。

个人资料库只通过用户主动操作写入。Agent 获得授权后只得到按需搜索和读取能力，不自动加载全部资料正文。

## 4. 授权模型

### 4.1 默认策略

- 个人资料库默认私有；
- 用户按 Agent 显式授予整库只读权限；
- 未授权 Agent 不得搜索、列出或读取资料；
- Agent 永远不能通过运行时能力创建、编辑、移动或删除个人资料。

### 4.2 可授权对象

用户可以授权自己当前可使用的任意 Agent：

- 用户自己创建的 Agent；
- 用户参与协作的 Agent；
- 平台公用 Agent；
- 他人定向分享且用户角色为“仅使用”的 Agent。

授权只对当前用户自己的资料库生效，不扩大 Agent 对其他用户资料的访问范围。

### 4.3 撤销语义

- 用户撤销授权后，后续搜索和读取立即被拒绝；
- 历史对话中已经产生的文本回答不删除；
- 历史消息不得继续提供可绕过授权的原始文件访问能力；
- 即使模型保留旧文档 ID，每次读取仍需重新执行后端授权检查。

### 4.4 管理员边界

管理员同时拥有普通用户能力，可以维护和授权自己的个人资料库，但管理员角色不自动授予其他用户私人资料的读取、下载、搜索或修改权限。

## 5. 存储架构

采用“文件系统保存正文，PostgreSQL 保存元数据与授权”的混合架构。

### 5.1 物理目录

所有新资料库使用英文物理目录：

```text
user_libraries/{user_id}/
```

该目录不属于任何 Agent 工作区。切换、停用、删除或取消使用 Agent 不得删除用户资料。

### 5.2 文件元数据

新增 `user_library_documents`，至少包含：

- `id`：稳定文档 ID；
- `owner_user_id`：资料所有者；
- `relative_path`：相对资料库根目录的规范路径；
- `name`、`media_type`、`size`、`sha256`；
- `created_at`、`updated_at`。

约束：

- 数据库不保存文件正文；
- 同一用户内规范化相对路径唯一；
- 路径禁止绝对路径、`..`、空段和符号链接逃逸；
- 文档 ID 不编码物理绝对路径。

### 5.3 Agent 授权记录

新增 `user_library_agent_grants`，至少包含：

- `owner_user_id`；
- `agent_id`；
- `status`：`active` 或 `revoked`；
- `granted_at`、`revoked_at`、`updated_at`。

同一用户和 Agent 只有一个当前授权状态，授权范围固定为整库只读。

### 5.4 一致性

- 新建、上传和复制先写临时文件，再通过原子替换落盘；
- 数据库写入失败时清理尚未正式生效的新文件；
- 文件操作失败时不提交元数据变化；
- 元数据与磁盘不一致时拒绝修改并记录错误，不静默创建或覆盖；
- 删除文件同步删除正文与元数据，第一版不提供回收站。

## 6. 文件来源与维护

个人资料通过以下显式用户操作进入资料库：

1. 在个人资料库中直接新建文件或文件夹；
2. 上传本地文件；
3. 将临时附件保存到个人资料库；
4. 将个人运行空间文件复制到个人资料库；
5. 将 Agent 产物复制到个人资料库。

从其他区域保存时一律复制，不移动或删除源文件。发生重名时必须要求用户选择重命名或覆盖，不允许静默覆盖。

## 7. 前端设计

### 7.1 文件页面入口

文件页面提供以下一级标签：

```text
临时附件 | 个人资料库 | Agent 资料 | 产物
```

“个人资料库”不随当前 Agent 切换而改变，始终指向当前登录用户的全局资料库。

### 7.2 文件能力

- 新建文件夹；
- 新建文本或 Markdown 文件；
- 上传、预览、编辑和下载；
- 重命名、移动和删除；
- 显示文件类型、大小和更新时间；
- 从临时附件、个人运行空间或产物复制保存。

删除文件或非空目录需要二次确认。第一版不提供批量操作。

### 7.3 Agent 授权界面

“Agent 授权”入口列出当前用户可使用的全部 Agent，并显示来源：

- 我的；
- 协作；
- 公用；
- 仅使用。

用户通过开关授予或撤销整库只读权限。操作完成后立即刷新状态；前端状态只用于交互反馈，最终权限由后端校验。

## 8. 后端接口与职责

新增独立接口域：

```text
/api/console/personal-library
```

接口职责包括：

- 查询目录树和文件元数据；
- 读取、预览和下载；
- 新建、上传、编辑、重命名、移动和删除；
- 从临时附件、个人运行空间或产物复制；
- 查询当前用户可授权的 Agent；
- 授予和撤销 Agent 只读访问。

个人资料库服务独立于 Agent 工作区写权限，统一处理路径规范化、所有权校验、文件与数据库一致性以及错误映射。

## 9. Agent 运行时接入

Agent 不获得资料库物理目录，而是获得受控的只读能力：

```text
personal_library_search(query)
personal_library_read(document_id, offset, limit)
```

每次调用必须同时校验：

- 当前请求的可信用户身份；
- 当前 Agent 身份；
- 文档仍属于当前用户；
- 当前用户对当前 Agent 的授权仍为有效状态。

未授权时不向 Agent 注册这两个能力。授权后，系统提示只说明存在可按需检索的个人资料库，不注入全部正文。

搜索结果只返回当前用户资料的文档 ID、相对路径、摘要和相关度。读取接口限制单次返回长度，超长文本通过 `offset` 和 `limit` 分页读取。

## 10. 文件类型与搜索

首版支持：

- `.md`、`.txt`、`.json`、`.yaml`、`.yml`、`.csv`：在线编辑、全文搜索和 Agent 分页读取；
- 图片、PDF、Office 等二进制文件：上传、预览或下载，不自动提取全文给 Agent。

文件大小、扩展名和 MIME 类型由后端共同校验，不能只信任浏览器参数。

首版搜索采用受限资料库目录内的文本检索，不引入新的向量数据库或独立索引服务。

## 11. 错误与安全策略

- 请求其他用户资料统一返回 404，避免泄露资源是否存在；
- 非法路径返回 400；
- 当前用户拥有资料但 Agent 授权已撤销时，Agent 运行时读取返回 403；
- 所有修改接口只允许资料所有者本人调用；
- 所有文件访问都经过后端服务，不依赖前端隐藏按钮；
- 服务日志记录请求 ID、用户 ID、Agent ID、文档 ID 和操作结果，不记录文件正文。

## 12. 分阶段实施与验收

### Task 6.2-R/4-A：个人资料库基础能力

- 用户可通过页面新建、上传、编辑、移动、下载和删除自己的文件；
- 第二个用户不能列出、猜测或访问第一个用户的资料；
- 前后端权限同时生效。

### Task 6.2-R/4-B：来源保存

- 临时附件、个人运行空间和产物可以显式复制到个人资料库；
- 源文件保持不变；
- 重名处理可见且不会静默覆盖。

### Task 6.2-R/4-C：Agent 授权管理

- 用户可以授权或撤销自己可使用的 Agent；
- 管理员不能读取其他用户资料；
- 撤销后后端立即拒绝后续 Agent 读取。

### Task 6.2-R/4-D：Agent 运行时读取

- 已授权 Agent 可以搜索和分页读取；
- 未授权或撤销授权后立即拒绝；
- 公共记忆、个人记忆和 ReMe 仍沿用原链路并正常工作。

### Task 6.2-R/4-E：双用户浏览器验收

- 两个普通用户使用同一个公用 Agent；
- 两人可以保存同名资料但互不覆盖；
- 两人的授权、搜索结果和正文读取不串扰；
- 刷新、切换 Agent 和重新登录后隔离关系保持正确。

## 13. 工程原则

- **KISS**：首版采用整库授权和文本检索，不引入单文件 ACL、向量库或版本管理；
- **YAGNI**：不提前实现产物生命周期、OCR、回收站和管理员代管；
- **DRY**：路径校验、Actor 身份、Agent 可使用性判断和文件响应复用现有基础设施；
- **SOLID**：文件存储、元数据仓储、授权、HTTP 接口和运行时工具保持独立职责，通过明确接口协作。

## 14. 完成标准

只有在 R/4-A 至 R/4-E 均通过自动化测试、真实浏览器双用户验收，并由用户逐项确认后，Task 6.2-R/4 才能标记完成并进入 Task 6.2-R/5。
