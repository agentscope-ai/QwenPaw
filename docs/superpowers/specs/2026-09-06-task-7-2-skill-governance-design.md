## 推荐实现

沿用文件内容与 PostgreSQL 元数据双层结构，不用 JSON manifest 兼任多用户授权数据库，不重建技能系统。

1. 增加 skill_pool_agent_grants，使用 skill_id、agent_id 唯一约束，记录 enabled、操作者及时间。服务端要求真实 Agent 编辑权限与有效技能授权同时成立。池管理与用户可载入目录分离，用户目录不返回内部路径和私有配置。
2. 发布版本内容使用不可变快照和全目录内容哈希，覆盖 SKILL.md、scripts、references。沿用现有版本表，不将可变技能目录当作已发布版本。
3. 发布申请固定提交时内容快照、哈希和来源身份；管理员批准的是该快照，不是审核时可能已被更改的源目录。申请支持待审核、通过、驳回；重复审批不得重复发布。
4. 用户载入后得到 Agent 内独立副本，绑定来源版本。修改内容后 detached=true；频道、启停、配置和标签变化不算内容脱离。更新或恢复需要明确确认，不自动覆盖 detached 副本。
5. 自动更新和广播逐目标检查权限及状态，保留已有冲突预检、暂存扫描、回滚语义。不得借自动更新绕过 detached 保护。池授权撤销只阻止后续载入、更新和恢复，不禁用已有副本。
6. 用户私有技能发布走申请，不能直写池；协作者能编辑和载入，但发布申请限所有者，管理员可以审核和治理。共享内容不能带入 Agent 私有配置或有效凭据。

## 数据结构变更边界（已单独授权）

- 只在当前根迁移链新增迁移，不修改已执行历史迁移。
- 新增技能池 Agent 授权表；为发布申请添加快照定位、内容哈希及必要审核并发约束。
- 不删除表、列、技能目录或已安装副本；不修改模型授权及治理开关。
- 真实迁移前核对目标 schema、备份和迁移 SQL；未确认前只允许代码设计及只读检查。
- 旧技能池条目不自动获得全 Agent 授权。初始化需管理员预览、登记再明确授权；不凭扫描目录推断授权。
- 数据库或快照校验失败应明确报错，不能默认为授权，也不能回读未审查的可变源。

## 替代方案与取舍

- 推荐：复用既有 PG 表并做小范围增量迁移，约束清晰，适合多用户并发。
- 仅向 skill.json 写授权和申请状态：迁移成本低，但不能可靠复用 PG 外键与事务，不采用。
- 重建独立技能商城：改动过大，超出本阶段，不采用。
