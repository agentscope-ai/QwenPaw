# Task 6.2-R/3 附件生命周期与 Agent 资料设计

日期：2026-09-02  
状态：用户已逐节确认，等待书面规格复核  
前置任务：Task 6.2-R/1、Task 6.2-R/2

## 1. 目标与范围

本任务区分会话临时附件与用户主动保存的长期资料，并提供明确的保存、移动和清理入口。

本任务只管理“当前用户 + 当前 Agent”范围：

- 会话临时附件；
- 当前 Agent 的长期资料；
- 新 Agent 首次使用时所需的标准运行目录。

以下内容不在本任务实现：

- 跨 Agent 复用的统一个人资料库，由 Task 6.2-R/4 实现；
- Agent 工具产物的来源、保留状态和清理策略，由 Task 6.2-R/5 实现；
- 按天数自动过期或后台自动清理策略；
- 管理员代替用户管理个人资料。

## 2. 核心设计决策

采用“PostgreSQL 记录生命周期，文件保留在受控个人运行空间”的方案。

- 数据库是附件生命周期、归属、来源和状态的事实来源；
- 文件系统保存附件和资料正文；
- 保存操作采用移动而非复制，避免重复文件和多个事实来源；
- 附件 ID 保存前后不变，历史消息不需要改写引用；
- 所有路径由后端解析，前端只能提交受限相对目录或文件名。

不采用纯目录推断方案，因为手工移动文件后无法可靠维持会话、消息和用户归属。不采用复制保留方案，因为会产生重复文件和复杂的删除关系。

## 3. 目录模型

仅使用或公用 Agent 的个人运行空间结构：

```text
user_workspaces/<user_id>/<agent_id>/
├── media/                       # 会话临时附件
├── 资料/                        # 当前 Agent 的长期资料
│   ├── 原文件名
│   └── 用户创建的子目录/
└── 产物/                        # Agent 工具生成文档，R/5 管理生命周期
```

目录创建规则：

- 新 Agent 第一次解析当前用户运行空间时自动确保 `media/`、`资料/`、`产物/` 存在；
- 用户上传附件自动进入 `media/`；
- 点击“保存到资料”后移动到 `资料/` 或其受控子目录；
- Agent 工具生成的文档继续在当前运行空间内产生，R/3 不强制改变现有工具输出路径；
- 用户自己创建的 Agent 保持原 Agent 项目目录机制，但初始化同名标准目录，不迁移既有项目文件。

所有目录解析必须拒绝绝对路径、`..`、符号链接逃逸和跨工作区目标。

## 4. 生命周期与数据模型

附件生命周期：

- `temporary`：会话临时附件；
- `saved`：用户已保存到当前 Agent 资料目录的长期资料；
- `deleted`：物理文件已清理，元数据保留用于历史消息状态展示和审计。

`attachments` 增加：

- `lifecycle`：`temporary | saved | deleted`；
- `saved_path`：相对 `资料/` 的受控路径；临时附件为空，保存后保留，长期资料删除后仍保留用于历史状态识别；
- `saved_at`：首次保存时间；
- `deleted_at`：物理文件清理时间；
- `updated_at`：生命周期或路径最后更新时间。

既有附件迁移为 `temporary`。来源会话、来源消息、所有者和 Agent 字段继续保留。保存后仍保留来源关系，但不再跟随会话清理。

状态约束：

- `temporary`：`saved_path/saved_at/deleted_at` 均为空；
- `saved`：`saved_path/saved_at` 非空，`deleted_at` 为空；
- `deleted`：`deleted_at` 非空；删除前的来源和原始文件名仍保留。若由 `saved` 删除，则继续保留 `saved_path/saved_at`；若由 `temporary` 删除，两者仍为空；
- 已删除附件不能再次保存、移动或下载；重复删除返回幂等成功。

## 5. 权限模型

后端是最终权限边界，前端只根据后端能力隐藏或禁用操作。

- 只有附件所有者可以查询、下载、保存、移动或删除；
- 操作目标必须属于当前选择的 Agent；
- 管理员与普通用户遵循相同的个人资料规则；
- 管理员不能直接修改其他用户的个人资料；
- 公用或仅使用 Agent 的用户只能修改自己的个人运行空间，不能修改 Agent 公共工作区；
- owner/collaborator 也不能读取或操作其他用户的个人目录；
- 移动仅允许发生在当前 Agent 的 `资料/` 内；
- 任意跨用户、跨 Agent 或越权 ID 统一返回 404，避免泄露资源存在性。

## 6. 文件操作与一致性

### 6.1 保存到资料

1. 按当前用户和 Agent 锁定附件元数据；
2. 确认附件是 `temporary` 且物理文件存在；
3. 解析 `资料/` 下的受控目标路径；未指定目标时默认使用 `资料/<原文件名>`；
4. 目标已存在时返回 409，不自动覆盖；
5. 在同一文件系统内原子移动；
6. 更新生命周期、`storage_key`、`saved_path`、`saved_at` 和 `updated_at`；
7. 数据库更新失败时将文件移回原位置。

### 6.2 资料内部移动或重命名

- 仅接受 `saved` 附件；
- 源和目标均必须位于当前 Agent 的 `资料/`；
- 附件 ID、来源会话和来源消息不变；
- 目标冲突返回 409；
- 文件与数据库更新使用与保存操作相同的补偿规则。

### 6.3 清理

- `temporary` 与 `saved` 均可由所有者显式删除；
- 删除长期资料前端必须二次确认；
- 后端删除物理文件后将元数据标记为 `deleted`，不物理删除数据库记录；
- 历史消息保留原始文件名和来源，并显示“文件已清理”或“资料已删除”；
- 已删除文件的下载接口返回 404；
- 重复删除返回幂等成功。

### 6.4 删除会话联动

- 删除会话时提供 `cleanup_temporary_attachments` 选项，前端默认勾选；
- 选中时只清理该会话的 `temporary` 附件；
- `saved` 和已删除元数据不受影响；
- 未选中时保留临时附件，后续仍可在文件页面保存或清理。

## 7. 后端接口

- `GET /console/attachments`
  - 按当前 Agent 查询；
  - 可按 `lifecycle`、`conversation_id` 分组或筛选；
  - 不返回绝对路径。
- `POST /console/attachments/{id}/save`
  - 保存到 `资料/`；
  - 可提交相对 `资料/` 的受控目标路径；未提交时保存到资料根目录并沿用原文件名。
- `POST /console/attachments/batch-save`
  - 批量保存；
  - 逐项返回成功或失败。
- `POST /console/attachments/{id}/move`
  - 在 `资料/` 内移动或重命名；`target_path` 表示包含文件名的、相对 `资料/` 的目标路径。
- `DELETE /console/attachments/{id}`
  - 显式清理一个附件或资料；
  - 幂等。
- `POST /console/attachments/batch-delete`
  - 批量清理；
  - 逐项返回结果。
- `DELETE /chats/{chat_id}?cleanup_temporary_attachments=true|false`
  - 删除会话并按选项处理临时附件。

批量接口不能因一个项目失败而回滚已成功的其他项目，也不能误报整体成功。响应包含附件 ID、状态和稳定错误码。

## 8. 前端交互

### 8.1 对话附件卡片

- 临时附件显示“临时”标识；
- 提供“保存到资料”；
- 保存成功后显示“已保存”，预览地址保持不变；
- 已清理临时附件显示“文件已清理”；
- 已删除长期资料显示“资料已删除”；
- 删除状态不再提供下载或预览操作。

### 8.2 文件页面

在现有“文件”页面内增加资料导航，不新增顶级菜单：

```text
个人运行空间
├── 临时附件
├── Agent 资料
└── 产物
```

- “临时附件”按会话分组，支持单个保存、单个删除、批量保存和批量清理；
- “Agent 资料”使用目录树，支持新建目录、重命名、内部移动、下载和删除；
- “产物”在 R/3 中只负责标准目录初始化和现有文件展示，生命周期操作留到 R/5；
- 所有操作局部刷新，不能触发整页重新加载；
- 空状态分别显示“暂无临时附件”“暂无已保存资料”“暂无 Agent 产物”。

界面沿用现有文件页面和 Ant Design 交互语言，不创建与项目风格冲突的新视觉体系。

## 9. 错误处理

- 未认证：401；
- 不属于当前用户或 Agent：404；
- 生命周期不允许当前操作：409；
- 目标文件已存在：409；
- 物理源文件缺失：409，并保留元数据供用户查看异常；
- 受控路径校验失败：400；
- 文件操作失败：返回稳定错误码，不提前更新数据库；
- 数据库更新失败：执行文件补偿移动，补偿失败记录服务端错误并返回 500；
- 批量操作逐项报告，不包含磁盘绝对路径或其他用户信息。

## 10. 测试与分步验收

### 10.1 自动化测试

- 迁移：旧附件回填为 `temporary`，约束和回滚成立；
- Repository：生命周期转换、所有者过滤、并发冲突和幂等删除；
- 服务：保存、移动、目标冲突、数据库失败补偿、符号链接与路径穿越拒绝；
- API：单个和批量操作、404 隔离、会话删除联动；
- 前端：附件卡状态、局部刷新、批量结果、删除确认和空状态；
- 回归：原对话消息、工具过程、附件预览、文件编辑和 owner/collaborator 工作区保持可用。

### 10.2 用户可见验收顺序

1. 新 Agent 首次对话后出现 `media/`、`资料/`、`产物/`；
2. 上传附件后在“临时附件”出现；
3. 对话卡片点击“保存到资料”，文件移动且历史消息仍可下载；
4. 在“Agent 资料”中新建目录并移动资料；
5. 清理临时附件，历史卡片显示“文件已清理”；
6. 删除会话时选择是否清理临时附件，长期资料保持；
7. 两个普通用户使用同一公用 Agent，附件和资料互不可见、不可下载、不可移动；
8. owner/collaborator 原有 Agent 工作区、对话、工具执行和文件编辑无回归。

## 11. 工程原则

- KISS：只实现显式生命周期，不加入自动过期和跨 Agent 资料库；
- YAGNI：产物生命周期留在 R/5，不在 R/3 猜测工具输出规则；
- DRY：复用 WorkspaceResolver、附件 Repository、受保护下载和现有文件工作区；
- SOLID：生命周期状态转换、受控路径解析、文件事务补偿和 HTTP 展示分层实现。
