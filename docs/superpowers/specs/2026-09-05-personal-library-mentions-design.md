# 个人资料库 @ 引用设计

## 目标

在聊天输入框输入 `@` 时，只展示当前登录用户个人资料库中的文件。用户选中文件后，本轮请求携带稳定的文档 ID；后端重新校验文档归属和当前 Agent 授权，并在模型执行前注入只读文档内容。

## 安全边界

- 候选 API 只按认证主体的用户 ID 查询，不接受客户端传入用户 ID。
- 引用解析必须同时验证文档属于当前用户、当前 Agent 仍有资料库授权。
- 无效、被删除、跨用户或授权已撤销的文档统一返回不可用，不回显其存在性。
- 个人资料库引用不转换为工作区路径，不允许模型通过通用文件工具绕过边界。
- 手工输入形似 `@文件名` 的普通文本不获得文档访问权限；只有候选列表生成的文档 ID 才是可信引用。

## 前端交互

- 输入 `@` 后，在输入框上方显示个人资料库候选面板。
- 支持按文件名过滤，方向键选择、Enter 确认、Escape 关闭。
- 选中项渲染为不可拆分的引用标签，标签显示文件名并保存文档 ID。
- 发送消息时，文本仍保留可读的文件名，同时在请求元数据中发送 `personal_library_document_ids`。
- 发送后清空引用状态；删除引用标签时同步移除对应 ID。

## 后端数据流

1. Console 接收本轮 `personal_library_document_ids`。
2. 认证主体覆盖所有客户端用户字段。
3. 个人资料库服务逐个按当前用户和文档 ID 读取，并逐次复核 Agent 授权。
4. 在用户消息之后追加结构化只读上下文，包含文件名、文档 ID 和正文；不暴露磁盘路径。
5. 模型直接依据引用内容回答，不再需要扫描共享工作区定位文件。

## 限制与错误处理

- 首版仅支持个人资料库内可文本读取的 `md/txt/json/yaml/yml/csv` 文件。
- 单次最多引用 5 个文件；每个文件最多读取 65,536 字节。
- 非文本文件仍显示在资料库页面，但不进入聊天 @ 候选列表。
- 引用失效时拒绝本次发送并提示“资料库文件不可用或授权已撤销”，不静默降级为工作区搜索。

## 验收标准

- 当前用户能通过 `@` 看到并选中 `AI写作需求文档.md`。
- 请求中包含文档 ID，回答前不出现工作区 `Glob/Read` 定位过程。
- 同一共享 Agent 的另一用户看不到、也不能伪造引用该文档 ID。
- 撤销 Agent 授权后，候选列表为空，旧引用发送失败。
