## 逻辑审计发现

### 已修复的边界

- 仅前端筛选不足：后端对来源、ID、归属、授权和生命周期重新校验。
- 客户端伪造正文：清除外部传入的已解析引用，正文只由服务端读取。
- 已删除附件重放：旧上传附件 URL 解析此前没有检查 lifecycle，现已拒绝 deleted。
- 跨 Agent 最近会话污染：在归属切换期间拒绝写入旧列表会话。
- 非法空引用类型：`{}`、空字符串、null、false 不再静默按未引用处理。

### 高优先级未完成：通用工具层强隔离

来源：`src/qwenpaw/agents/tools/file_io.py` 的 `_resolve_file_path` 接受绝对路径，Read 默认策略为全局 allow；`src/qwenpaw/governance/policy.py` 的 ToolCallSpec 没有认证用户字段，SMART 默认可放行无风险命中的读取；`resource_governor.py` 在沙箱不可用时允许已通过策略的 Shell 非沙箱执行。

无真实文件读取的复现：构造默认 GovernancePolicy，对 Read 指向 `E:/example/user_workspaces/other-user/default/private.md` 的调用做策略求值，得到 `allow / SMART mode: no findings, no rule hit.`。这证明默认工具策略不是用户目录强隔离；不是在运行服务里读取了其他用户真实文件，也不等于已完成整个工具链的漏洞利用验证。

因此不能保证“所有工具都绝不会读取其他用户资料”。本次接口边界修复不能替代运行工具的权限隔离。建议下一项专门设计并实施：从可信身份生成允许读取/写入的资源集合；在 Read/Glob/Grep/Write/Edit/SendFile 等底层统一执行；Shell、Python、MCP、浏览器等间接文件访问须使用按用户隔离的执行环境，无法隔离时不能退化为无约束放行。单纯对 Shell 字符串做路径过滤不充分。

该加固会影响原有工具执行能力及共享 Agent 使用方式，需作为明确的下一阶段处理，不能把它悄悄混入本次 UI 修复后宣称全平台安全。当前不建议对不受信任的多用户开放无隔离 Shell。

审计方式：授权仓库的定向代码检索、数据流人工核验和回归测试。Semgrep/Bandit 命令在当前环境不可用，未安装工具或进行全仓自动 SAST；未审计的模块不在本次安全结论范围。

## 用户验收步骤

1. 打开聊天，输入 `@`，检查来源标注，选择个人资料库中的文档。
2. 确认该资料库已授权当前 Agent，新建对话直接提到完整文件名。上游恢复后，应围绕对应文档正文回答。
3. 打开任意一条较新的历史对话，切到文件或其他菜单再返回聊天，确认仍是该会话。
4. 使用另一普通用户登录同一个 Agent，候选目录不应出现前一用户资料；共享托管档案可见不等于私人资料共享。
5. 不把步骤 4 的接口验证当成通用 Shell/文件工具隔离验收；该项仍待上述专项加固。
